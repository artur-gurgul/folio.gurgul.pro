\sheettitle{Sanitizers \& runtime checkers — make the bug crash \emph{here}}{debugging · folio}

\oneliner{Memory and threading bugs corrupt silently and crash \emph{later, elsewhere}.
Sanitizers are \textbf{compiler instrumentation + a runtime} that check every access as it
happens and report the \textbf{first bad access} with the stacks that explain it. Runtime
checkers — Main Thread Checker (MTC), Thread Performance Checker (TPC), exclusivity — need no
special build. ASan and TSan cost 2–20$\times$ and their runtimes are not meant for production:
Debug schemes, test plans, CI. Hardware memory tagging is the one built to ship.}

\section{How they work}
\begin{itemize}
  \item \textbf{ASan} replaces \ct{malloc}/\ct{free}, checks both buffers of \ct{memcpy}-style
        calls; \ct{halt\_on\_error=1}: the first report ends the run. Misses leaks,
        uninitialised reads, integer overflow. \ct{-O1} trims its memory (TSan too).
  \item \textbf{TSan} instruments accesses \emph{and} sync calls; \ct{halt\_on\_error=0}: it keeps
        running, one report per race. Swift 6 mode rejects races at compile time, but
        \ct{@unchecked Sendable} and \ct{nonisolated(unsafe)} switch that check off — TSan still
        sees them, and C / ObjC.
  \item \textbf{MTC / TPC} swap system methods for thread-checking variants — no recompile;
        \ct{libMainThreadChecker.dylib} can be injected into an existing macOS binary. TPC:
        \ct{dispatch\_semaphore\_wait} / \ct{dispatch\_group\_wait} cannot donate priority $\to$
        inversion; silence known ones with \ct{PERFC\_SUPPRESSION\_FILE}.
  \item \textbf{Zombies}: freed objects stay as zombies (\ct{NSDeallocateZombies=NO}): ``message
        sent to deallocated instance'' + trap. Field signs: \ct{objc\_msgSend} / \ct{objc\_retain} / \ct{objc\_release} on
        top, or an unrecognised selector (memory reused).
  \item \textbf{HW tags}: Enhanced Security $\to$ \emph{Enable Hardware Memory Tagging}
        (\ct{…checked-allocations} entitlement); \emph{soft mode} writes a simulated crash
        report instead of killing — off before users get the build.
  \item \textbf{Exclusivity}: static where provable, dynamic (\ct{swift\_beginAccess}) for class
        properties, statics, globals, escaping closures; \ct{-enforce-exclusivity=unchecked}
        drops the Release checks. \textbf{Dynamic isolation} (SE-0423): \ct{@objc} thunks,
        \ct{@preconcurrency} conformances, closures passed to unaudited APIs;
        \ct{-disable-dynamic-actor-isolation} opts out.
\end{itemize}

\section{Turning them on}
\ct{clang -fsanitize=address} (or \ct{thread}, \ct{undefined}) · \ct{swiftc -sanitize=address}
(or \ct{thread}; no UBSan) · \ct{xcodebuild test -enableAddressSanitizer YES} (\ct{…Thread…},
\ct{…UndefinedBehavior…}). Scheme $\to$ Run $\to$ \textbf{Diagnostics}; tests: test-plan
configurations, one per sanitizer.
\emph{Runtime API Checking} warns by default; \emph{On (as Failure)} fails the test. UBSan
continues after a report; \ct{-fno-sanitize-recover} exits, \ct{-fsanitize-trap} traps
(SIGILL / SIGTRAP, no runtime). Container-overflow noise:
\ct{ASAN\_OPTIONS=detect\_container\_overflow=0} in the Run scheme and each ASan test plan —
build settings cannot switch it off.

\section{Reading a report {\normalfont\scriptsize(ASan, abridged)}}
\begin{lstlisting}[language=ReportSheet]
==4242==ERROR: AddressSanitizer: heap-use-after-free
READ of size 8 at 0x60200000eff0 thread T0
  #0 parse_header  buf.c:42        // 1 WHERE: bad access
0x60200000eff0 is located 0 bytes inside of 16-byte region
freed by thread T0 here:
  #1 conn_close    conn.c:88       // 2 WHO freed it
previously allocated by thread T0 here:
  #1 conn_open     conn.c:31       // 3 WHO made it
SUMMARY: AddressSanitizer: heap-use-after-free buf.c:42
\end{lstlisting}
Bug type first, then three stacks: access, free, allocation — the fix is usually in \#2 or \#3,
not \#1. More shadow bytes: \ct{f1}/\ct{f2}/\ct{f3} stack left / mid / right redzone · \ct{f5}
stack after return · \ct{f8} after scope · \ct{f9} global redzone · \ct{fc} container overflow.

\textbf{TSan} \ct{WARNING: ThreadSanitizer: data race}: \emph{Write \dots\ by thread T3} +
\emph{Previous read \dots\ by main thread} — two stacks, two threads, one address, no edge: fix the
\emph{ownership} (actor, serial queue, \ct{Mutex}), not the timing. Other kinds: Swift access race ·
thread leak · lock-order-inversion (potential deadlock) · invalid or unlocked mutex ·
signal-unsafe call inside of a signal.

\section{Exclusivity trap at run time}
\begin{lstlisting}[language=SwiftSheet]
final class Counter { var n = 0 }
func bump(_ x: inout Int, by c: Counter) { x += c.n }
let c = Counter()
bump(&c.n, by: c)   // modify of c.n open, then a read of c.n
// Simultaneous accesses to 0x..., but modification requires
//   exclusive access. Previous access (a modification) started
//   at ... Current access (a read) started at: swift_beginAccess
\end{lstlisting}

\section{Traps}
\begin{itemize}
  \trap{ASan + TSan in one run — impossible: two test-plan configurations, two CI runs.}
  \trap{Clean TSan run $\neq$ race-free: unexecuted interleavings and overwritten slots go unseen.}
  \trap{Crash on \ct{0x400000000000bad0}: synthesized \ct{nonatomic} ObjC setters briefly store
        this sentinel — two threads mutated the property.}
\end{itemize}

\section{Remember}
\textbf{ASan = where memory, TSan = when threads, UBSan = C rules, MTC / TPC = the main thread,
tags = the one that ships.} Crash here, not later.
