\sheettitle{Performance in production — field metrics, not lab numbers}{debugging · folio}

\oneliner{The lab tells you \emph{whether a build can} be fast; only the \textbf{field} tells you
whether users' devices \emph{are}. The OS measures launch, hangs, hitches, memory, disk, CPU,
battery and \textbf{why the app died}, aggregates it per day, and hands it to you (MetricKit) or to
Apple (Organizer) / Google (Play vitals). Read \textbf{percentiles per app version and device},
never an average, and gate each release on them.}

\hd{MetricKit — the iOS 27 API}
\begin{itemize}
  \item \ct{MetricManager} — an \emph{instance}, not a singleton: keep \textbf{one}. With two, loops
        over one sequence each get a non-deterministic \emph{subset}.
  \item \ct{metricReports} $\to$ a daily \ct{MetricReport}: \ct{intervalEntries} (incl. the full day) +
        \ct{stateEntries}, values are \ct{MetricResult} cases with a \ct{metricGroup}.
        \ct{diagnosticReports} $\to$ one \ct{DiagnosticReport} per event. Both never throw; \ct{Codable}.
  \item \textbf{Deprecated in 27.2}: \ct{MXMetricManager} + subscriber \ct{didReceive(\_:)} (iOS 13
        metrics, 14 diagnostics) and every other \ct{MX…} type.
  \item \textbf{Device only}; \emph{Debug › MetricKit › Simulate MetricKit Payloads} = sample data, not yours.
  \item \textbf{StateReporting} (27): domains passed to \ct{init(enabledStateReportingDomains:)}; one
        state per domain at a time (A/B arm, tab); only \emph{stable} metadata counts; too many states
        $\to$ \ct{hasExceededStateLimit}.
\end{itemize}

\noindent{\footnotesize Per state: hang, hitch, terminations, signposts, run time; not CPU, memory, launch.}

\hd{Diagnostics — one event, one call-stack tree}
\begin{itemize}
  \item \ct{.crash} (exception type, code, signal, ObjC reason) · \ct{.hang} (\ct{hangDuration}) ·
        \ct{.cpuException} · \ct{.diskWriteException} (\ct{totalBytesWritten}) · \ct{.appLaunch} (slow
        launch) · \textbf{\ct{.memoryException}} (27, iOS only: killed over the memory limit).
  \item Frames = \ct{binaryUUID} + offset + \ct{sampleCount}: symbolicate with the dSYM.
        \ct{environment}: version, OS, device, states.
  \item Hangs come only from devices with hang detection on or in a sampling group.
\end{itemize}

\hd{Example — collect (iOS 27)}
\begin{lstlisting}[language=SwiftSheet]
let mk = MetricManager(enabledStateReportingDomains: ["com.acme.ab"])
Task { for await r in mk.metricReports {          // ~daily
         try await api.upload(JSONEncoder().encode(r)) } }
Task { for await d in mk.diagnosticReports {      // per event
         try await api.upload(JSONEncoder().encode(d)) } }
let log = MetricManager.logHandle(category: "Checkout")
mxSignpost(.begin, log: log, name: "Pay")   // + CPU, memory, writes
defer { mxSignpost(.end, log: log, name: "Pay") }
try await mk.trackLaunchTask(id: "feed") { try await feed.load() }
\end{lstlisting}

\hd{Definitions}
\begin{itemize}
  \item \textbf{Launch} = tap $\to$ first frame \emph{after} the launch screen. \textbf{Resume} = process
        still alive: reported apart, much faster. Cold–warm is a spectrum.
  \item \textbf{Hang} = the main run loop busy between two waits. \textbf{Hang rate} = seconds of hang
        per \textbf{hour}, counting $>$\,250\,ms only. A \textbf{hitch} is a late frame — another metric.
\end{itemize}

10 launches (s): 0.40 0.40 0.45 0.45 0.50 0.50 0.55 0.60 0.90 6.00 — one outlier doubles the mean
(0.53 $\to$ 1.08) and leaves p50 where it was.
\begin{itemize}
  \item MetricKit sends \textbf{histograms}: merge buckets across devices, \emph{then} read the
        percentile — never average per-device averages or percentiles.
  \item \textbf{Rates need a denominator}: hang s per hour, crashes per daily user or session, exits
        per 1\,000 launches. Raw counts grow with adoption.
\end{itemize}

\hd{Organizer and the rollout}
\begin{itemize}
  \item Thin data $\to$ a \textbf{margin of error} or ``Insufficient usage data''; goals show only when
        you are worse; regression notice $\le$\,1 per 24\,h.
  \item Phased release = a \textbf{random sample} of auto-update users (manual updates any time):
        gate each step on p90 launch, hang rate, exits.
  \item Sample frequent diagnostics, keep every rare one, and \textbf{store the rate}.
\end{itemize}

\hd{Traps}
\begin{itemize}
  \trap{``Average launch is 1\,s'' — say p50/p90 per device and version.}
  \trap{\ct{OSSignposter} on the MetricKit handle: no CPU / memory / writes.}
  \trap{Memory kills read as ``no crashes'' — read the termination counters.}
\end{itemize}

\hd{Remember}
\textbf{Lab proves it can be fast; field proves it is.} Percentiles · per version · per device ·
with a denominator.
