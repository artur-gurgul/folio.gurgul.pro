\sheettitle{Crash reporting in practice — from signal to fixed}{debugging · folio}

\oneliner{A crash reporter is a pipeline: an \textbf{in-process handler} writes the
report at the moment of death, the SDK \textbf{uploads it on the next launch}, the
server \textbf{symbolicates} it with the artefacts \emph{you} uploaded for that exact
build, \textbf{fingerprints} it into an issue, \textbf{alerts} on new, regressed or
fast-growing issues, and a human \textbf{triages} by users affected. Every stage has a
way to silently lose the crash.}

\section{The two numbers — and three yardsticks}
\begin{itemize}
  \item \textbf{Crash-free users} = 1 $-$ crashed users\,/\,all users;
        \textbf{crash-free sessions} = 1 $-$ crashed sessions\,/\,all sessions.
        Worked: 1\,000 users, 5\,000 sessions; 10 users crash 20 times $\to$
        users \textbf{99.0\,\%}, sessions \textbf{99.6\,\%}. Users = breadth, sessions
        = frequency; always \emph{per version}, with a minimum sample.
\end{itemize}
{\footnotesize\setlength{\tabcolsep}{3pt}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{12mm}>{\raggedright\arraybackslash}p{13mm}>{\raggedright\arraybackslash}p{25mm}>{\raggedright\arraybackslash}p{24mm}@{}}
\toprule
& \textbf{a user is} & \textbf{a session is} & \textbf{what counts}\\ \midrule
Crashlytics & one \emph{install} & cold start, or foreground after $\ge$\,30\,\textbf{min} away & fatal only — not ANRs, not non-fatals\\
Sentry & a distinct user & launch / foreground; back within 30\,\textbf{s} = same one & ends healthy · errored · crashed · unhandled · abnormal (no clean end: battery died)\\
Play vitals & user × device × \textbf{day} & — (per daily user) & user-perceived (activity shown, foreground service); ANR = input timeouts only\\
\bottomrule
\end{tabular}}
\begin{itemize}
  \item Same day, 3 sessions, 1 crash: vitals \textbf{100\,\%}, Crashlytics \textbf{33\,\%}.
        Vitals sees only Play installs on certified devices of users who share data;
        Sentry sessions are never sampled or filtered (crash events $\neq$ crashed sessions).
  \item Sentry \textbf{adoption} = a release's share of all sessions (or users) in the last
        24\,h — read crash-free next to it: at 1\,\% adoption it is a small sample.
\end{itemize}

\section{Grouping — the fingerprint}
\begin{itemize}
  \item Sentry: \textbf{fingerprint} $\to$ \textbf{stack trace} (\textbf{in-app frames} only:
        module, normalized filename, context line) $\to$ exception type + value $\to$ message.
  \item \textbf{Splits}: minified JS without source maps, a new wrapper frame, ids or URLs in
        the message. \textbf{Merges}: every network error through one helper.
  \item Crashlytics: fatals by stack, \emph{variants} = same failure point; logged
        \ct{NSError}s by \textbf{domain + code} — never put ids there.
  \item Fix: fingerprint rules (\ct{\{\{ default \}\}} + route), stack-trace rules (wrappers
        not in-app), merge / unmerge. Sentry's AI grouping only merges \emph{new} issues.
\end{itemize}

\section{Context that makes a crash fixable}
\begin{itemize}
  \item \textbf{Breadcrumbs}: screens, requests (method, route, status — no bodies), taps,
        lifecycle, memory warnings; Crashlytics takes them from Google Analytics.
  \item \textbf{Custom keys}: cart size, flag arm, sync state. Crashlytics: \textbf{64}
        pairs (more are not saved), 1\,kB each; logs \textbf{64\,kB}, oldest deleted.
  \item \textbf{Non-fatals} (decode failure, 5xx): Crashlytics keeps the \textbf{8} latest per
        session. Recording unwinds the stack + writes to disk \emph{synchronously}; on
        another queue the stack is lost. \textbf{User id}: pseudonymous.
  \item \textbf{Consent}: Info.plist \ct{FirebaseCrashlyticsCollectionEnabled} = \ct{NO}, then
        \ct{setCrashlyticsCollectionEnabled(true)} after opt-in (persists across launches);
        reports stored on the device meanwhile are sent once it is enabled.
\end{itemize}

\section{Example — enrich, then report}
\begin{lstlisting}[language=SwiftSheet]
let c = Crashlytics.crashlytics()
c.setUserID(account.pseudonymousID)          // never email
c.setCustomKeysAndValues(["cart_items": cart.count,
                          "exp_checkout": flags.checkoutArm])
c.log("checkout: pay tapped")                // 64 kB ring
do { try await pay() } catch {
  c.record(error: error)                     // non-fatal
  // Sentry instead: split one call site by route
  SentrySDK.capture(error: error) { scope in
    scope.setFingerprint(["{{ default }}", "/v1/pay"]) } }
\end{lstlisting}

\begin{itemize}
  \item \textbf{Sentry}: \emph{new} = first seen $<$\,7 days. Plain \emph{Resolve}: any later
        event regresses it; \emph{in next release} (prod 1.8.0, fix merged $\to$ only 1.9.0+
        reopens). Archive = alerts paused until it escalates. Crash-rate alert: crash-free
        users or sessions below a set \%.
  \item \textbf{Route}: page on a new fatal or velocity alert in the newest version; ticket
        regressed, trending, non-fatals. Slack, Jira, PagerDuty are built in.
\end{itemize}

\section{Deaths no handler sees}
\begin{itemize}
  \item \textbf{Watchdog / memory kill} (iOS): no signal. Sentry infers one at next launch
        if the last run: didn't crash · was in foreground · wasn't the first launch · had no
        debugger · same app + OS version · wasn't quit by user or OS.
  \item \textbf{iOS hang}: a thread pings main (Sentry \textbf{2\,s}; since 9.0.0 split into fully
        / non-fully blocking); killed during it $\to$ \emph{fatal} hang, sent next launch —
        Sentry's \emph{app hang rate} counts only these.
        MetricKit \ct{HangDiagnostic} (iOS 27; \ct{MXHangDiagnostic} deprecated 27.2).
  \item \textbf{ANR}: input unhandled \textbf{5\,s}. RN: a locked JS thread is \emph{not} one —
        \ct{ScrollView} still scrolls on main.
\end{itemize}

\section{Traps}
\begin{itemize}
  \trap{Debugger attached — it catches the crash first; detach, relaunch to upload.}
  \trap{99.9\,\% overall hiding 100\,\% for one locale/device — slice first.}
  \trap{Logging \emph{after} a recorded error rotates the useful lines out of 64\,kB.}
  \trap{PII in keys, logs, breadcrumbs (emails, tokens, request bodies).}
  \trap{Session replay: Sentry masks all text, images, input by default — unmask only after
        custom masks; \ct{onErrorSampleRate} keeps a 30\,s buffer.}
\end{itemize}
