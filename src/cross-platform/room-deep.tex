\sheettitle{Room in depth — codegen, invalidation, migrations, KMP}{cross-platform · folio}

\oneliner{Room is a \textbf{compile-time} layer over SQLite: KSP reads \texttt{@Entity}/\texttt{@Dao}/\texttt{@Database},
\textbf{checks every SQL string against the schema} and generates the implementation. Observable
queries work by \textbf{SQLite triggers} that mark a \emph{table} dirty; after each transaction the
\textbf{InvalidationTracker} re-runs every query that reads that table. The schema version is a
contract: every change needs a \textbf{migration} or data is lost.}

\section{Codegen \& schema}
\begin{itemize}\raggedright
  \item \texttt{ksp(room-compiler)} generates \texttt{AppDatabase\_Impl}, \texttt{NoteDao\_Impl}; a
        typo'd column is a \textbf{build error}. Kotlin codegen is the default on KSP (2.7+);
        kapt/Java still work in Room 2, \textbf{not in Room 3}.
  \item \texttt{@Entity(indices = [Index("folderId")], foreignKeys = [ForeignKey(Folder::class,
        ["id"], ["folderId"], onDelete = CASCADE)])} — Room warns if an FK column is not
        indexed (every parent delete would scan). \texttt{@Upsert} (2.5+): insert-or-update.
  \item \texttt{@Embedded} flattens a class into columns (\texttt{prefix}); entities may not hold
        \emph{references} to other entities — relations are queried, not lazy-loaded.
  \item \texttt{@TypeConverter} pairs (\texttt{Instant} $\leftrightarrow$ \texttt{Long}) registered
        with \texttt{@TypeConverters} on the DB, DAO or field.
\end{itemize}

\section{Example — many-to-many}
\begin{lstlisting}[language=KotlinSheet]
@Entity data class Playlist(@PrimaryKey val id: Long, val name: String)
@Entity data class Song(@PrimaryKey val id: Long, val title: String)
@Entity(primaryKeys = ["playlistId", "songId"], indices = [Index("songId")])
data class PlaylistSong(val playlistId: Long, val songId: Long)
data class PlaylistWithSongs(
  @Embedded val playlist: Playlist,
  @Relation(parentColumn = "id", entityColumn = "id",
    associateBy = Junction(PlaylistSong::class,
      parentColumn = "playlistId", entityColumn = "songId"))
  val songs: List<Song>)
@Dao interface PlaylistDao {
  @Transaction @Query("SELECT * FROM Playlist WHERE id = :id")
  fun observe(id: Long): Flow<PlaylistWithSongs?>   // 2 queries
  @Upsert suspend fun upsert(song: Song) }
\end{lstlisting}
\raggedright \texttt{@Relation} = a \textbf{second query} per parent batch — without
\texttt{@Transaction} a write between the two gives a torn read.

\section{Threading \& transactions}
\begin{itemize}\raggedright
  \item A blocking DAO call on the main thread throws \texttt{IllegalStateException} (unless
        \texttt{allowMainThreadQueries()}). \texttt{suspend} DAOs hop to Room's executors /
        query context themselves — no \texttt{withContext(IO)} needed.
  \item Multi-DAO write: \texttt{db.withTransaction \{ … \}} (one writer at a time; readers go on
        under \textbf{WAL}, the default journal mode except on low-RAM devices).
\end{itemize}

\section{FTS, Paging}
\raggedright \texttt{@Fts4(contentEntity = Note::class) @Entity class NoteFts(val title: String)}
+ \texttt{WHERE NoteFts MATCH :q} (join on \texttt{rowid}); Room 3 adds \texttt{@Fts5}. A DAO
returning \texttt{PagingSource<Int, Note>} (\texttt{room-paging}) is invalidated by the same
tracker; \texttt{RemoteMediator} writes pages into the table.

\columnbreak

\section{Migrations — the version is a contract}
\begin{itemize}\raggedright
  \item Room stores the schema's \textbf{identity hash}; a DB at another version with no path
        $\to$ \texttt{IllegalStateException} at open.
  \item Manual: \texttt{val M1\_2 = Migration(1, 2) \{ db \arr{} db.execSQL("ALTER TABLE Song ADD COLUMN
        len INTEGER NOT NULL DEFAULT 0") \}}. Paths chain 1$\to$2$\to$3 or jump 1$\to$3.
  \item \texttt{autoMigrations = [AutoMigration(2, 3, spec = S::class)]} diffs two
        \textbf{exported schema JSONs}; rename vs drop+add needs a spec (\texttt{@RenameColumn},
        \texttt{@RenameTable}, \texttt{@DeleteColumn}, \texttt{@DeleteTable}). So
        \texttt{exportSchema = true} + \texttt{room \{ schemaDirectory(…) \}}, \textbf{JSONs in git}.
  \item Test: \texttt{MigrationTestHelper.createDatabase(1)}, insert rows,
        \texttt{runMigrationsAndValidate(2, M1\_2)} = result must equal the v2 schema.
  \item SQLite \texttt{ALTER TABLE} can't change a type/constraint: new table $\to$ copy $\to$
        drop $\to$ rename.
\end{itemize}

\section{KMP (2.7+) \& Room 3}
\begin{itemize}\raggedright
  \item \textbf{2.7.0} (Apr 2025): KMP — Android, iOS, JVM. Builder
        \texttt{.setDriver(BundledSQLiteDriver())} (SQLite compiled from source, same version
        everywhere) \texttt{.setQueryCoroutineContext(Dispatchers.IO)};
        \texttt{@ConstructedBy} + \texttt{expect object … : RoomDatabaseConstructor<AppDb>}.
        Common DAOs: \texttt{suspend}/\texttt{Flow} only; \texttt{useWriterConnection\{\}}.
  \item \textbf{Room 3.0} (stable 1 Jul 2026, \texttt{androidx.room3}): KSP + Kotlin only,
        \texttt{SQLiteDriver} only (no \texttt{SupportSQLite}/\texttt{Cursor}), coroutines-first,
        \texttt{InvalidationTracker.createFlow()}, web targets.
\end{itemize}

\section{Traps}
\begin{itemize}\raggedright
  \trap{\texttt{fallbackToDestructiveMigration()} in release = a silent \textbf{wipe} on any
        missed path; at most \texttt{…OnDowngrade()}.}
  \trap{``Flow emits the changed row'' — it re-runs the query, emits \emph{everything}.}
  \trap{New \texttt{version}, schema JSON not committed — no AutoMigration later.}
\end{itemize}

\textbf{Remember:} \emph{KSP checks SQL · triggers mark tables · commit $\to$ re-query · every
version needs a tested path.}
