\sheettitle{Navigation Compose — back stack, routes, scoping, Nav 3}{cross-platform · folio}

\oneliner{A \texttt{NavController} owns a \textbf{back stack of \texttt{NavBackStackEntry}} — each entry
is its own \textbf{Lifecycle}, \textbf{ViewModelStore} and \textbf{SavedState} owner — and
\texttt{NavHost} shows the top one. Routes are \texttt{@Serializable} classes (2.8+); every
\texttt{navigate()} is a push plus \textbf{NavOptions} that pop, dedupe, save and restore.
\textbf{Navigation 3} drops the controller: \emph{you} own the back stack as a state list.}

\section{The model}
\begin{itemize}\raggedright
  \item \texttt{rememberNavController()} + \texttt{NavHost(nav, startDestination = Home) \{…\}}
        builds a \texttt{NavGraph}; \texttt{currentBackStackEntryAsState()} drives the bottom
        bar. Screens get \textbf{lambdas}, not the \texttt{NavController} (testable, previewable).
  \item \textbf{Type-safe routes} (2.8.0, Sep 2024): \texttt{@Serializable object}/\texttt{data
        class}, fields = arguments (Bundle-encoded: pass \textbf{ids}; custom types need a
        \texttt{typeMap}). Read: \texttt{entry.toRoute<Profile>()}, in the VM
        \texttt{savedStateHandle.toRoute<Profile>()}. 2.9: \texttt{KClass} overloads, value
        classes; \textbf{2.10} (Aug 2026): KMP targets, predictive-pop transitions.
  \item \texttt{navigation<Checkout>(startDestination = Cart) \{…\}} = nested graph: a flow
        with its own start, poppable as a unit (\texttt{popUpTo<Checkout> \{ inclusive = true \}}).
\end{itemize}

\section{Example}
\begin{lstlisting}[language=KotlinSheet]
@Serializable object Home
@Serializable data class Profile(val id: String)
@Serializable object Checkout; @Serializable object Cart
NavHost(nav, startDestination = Home) {
  composable<Home> { HomeScreen(onUser = { nav.navigate(Profile(it)) }) }
  composable<Profile>(deepLinks = listOf(navDeepLink<Profile>(
      basePath = "https://example.com/u"))) { ProfileScreen() }
  navigation<Checkout>(startDestination = Cart) {
    composable<Cart> { entry ->
      val flow = remember(entry) { nav.getBackStackEntry<Checkout>() }
      val vm: CheckoutVM = hiltViewModel(flow)  // shared by the flow
      CartScreen(vm, onDone = { nav.navigate(Home) {
        popUpTo<Checkout> { inclusive = true } } }) } } }
\end{lstlisting}

\section{Back-stack operations}
\begin{itemize}\raggedright
  \item \texttt{popUpTo(X)} pops all above X; \texttt{inclusive = true} pops X too (after
        login). \texttt{launchSingleTop}: no second copy on top.
  \item \texttt{saveState}/\texttt{restoreState} = \textbf{multiple back stacks} (2.4+): popped
        entries keep state + VMs, keyed by the tab.
  \item \texttt{popBackStack()} returns \texttt{false} if nothing popped (empty host = blank
        screen); \texttt{navigateUp()} goes to the parent inside your own task.
\end{itemize}

\section{Traps}
\begin{itemize}\raggedright
  \trap{\texttt{navigate()} in the composable body runs on every recomposition — call it from
        an event or a \texttt{LaunchedEffect}.}
  \trap{Double tap = two pushes: wrap in \texttt{dropUnlessResumed \{ … \}}.}
  \trap{A whole object in a route: Bundle size, stale copy — pass the id.}
\end{itemize}

\textbf{Remember:} \emph{entry = lifecycle + VM store + saved state · pop, single-top, save,
restore · Nav 3: the stack is your list.}

\columnbreak

\section{ViewModel scope \& results}
\begin{itemize}\raggedright
  \item Default \texttt{hiltViewModel()} = the \textbf{entry}: survives rotation, cleared when
        popped. Graph-scoped (Example) lives while any of the graph is on the stack.
  \item \textbf{Result back}: \texttt{previousBackStackEntry\sq savedStateHandle\sq
        set("k", id)}; the caller collects its own \texttt{savedStateHandle.getStateFlow("k",
        null)}. Or a shared graph VM — never a callback into a popped screen.
\end{itemize}

\section{Deep links \& App Links}
\begin{itemize}\raggedright
  \item \texttt{<intent-filter>} \texttt{VIEW} + \texttt{DEFAULT} + \texttt{BROWSABLE} +
        \texttt{<data>}; \texttt{navDeepLink} matches. The controller builds a
        \textbf{synthetic back stack} (start of each parent graph) so Back works; with
        \texttt{FLAG\_ACTIVITY\_NEW\_TASK} the task is cleared and rebuilt.
  \item \textbf{App Links}: \texttt{autoVerify="true"} + \texttt{/.well-known/assetlinks.json}
        (package + SHA-256 cert). Android 12+: unverified links open the \textbf{browser}.
        \texttt{adb shell pm get-app-links <pkg>}.
\end{itemize}

\section{Predictive back}
\raggedright 13: opt-in \texttt{enableOnBackInvokedCallback="true"}; 15: system
back-to-home / cross-activity animations for opted-in apps; \textbf{16 + targetSdk 36}: on by
default — \texttt{onBackPressed()} / \texttt{KEYCODE\_BACK} no longer delivered. Use
\texttt{OnBackPressedCallback}, \texttt{BackHandler}, \texttt{PredictiveBackHandler} (a
\texttt{Flow<BackEventCompat>} of progress); \texttt{NavHost} animates the pop (2.8+).

\section{Navigation 3 — you own the stack}
\raggedright \textbf{1.0.0 stable 19 Nov 2025} (1.2.0 Sep 2026), runtime KMP.
\texttt{rememberNavBackStack(Home)} — keys \texttt{@Serializable : NavKey}, survives process
death; push \texttt{backStack.add(Profile(id))}, pop \texttt{removeLastOrNull()}.
\texttt{NavDisplay(backStack, onBack, entryDecorators, entryProvider \{ entry<Home> \{…\} \})};
per-entry VMs need \texttt{rememberViewModelStoreNavEntryDecorator()}
(\texttt{lifecycle-viewmodel-navigation3}). \texttt{SceneStrategy}: several entries at once
(list-detail, dialog). Tabs = lists you keep; $\approx$ SwiftUI \texttt{NavigationStack(path:)}.
