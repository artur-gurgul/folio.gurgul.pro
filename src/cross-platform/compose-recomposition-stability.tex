\sheettitle{Compose recomposition \& stability — in depth}{cross-platform · folio}

\oneliner{Compose re-runs a composable only if it \textbf{read} snapshot \texttt{State} that
was \textbf{written}; the \textbf{phase} of the read decides how much work follows
(composition $\to$ layout $\to$ draw), and a re-run parent \textbf{skips} a child whose
parameters are \textbf{stable and equal} (strong skipping: unstable ones compared by
\eqeqeq). Performance work = \textbf{read later, read lower, keep inputs stable}.}

\section{Composition \& the snapshot system}
\begin{itemize}\raggedright
  \item The compiler adds \texttt{\$composer} + \texttt{\$changed} bitmask params; results live
        in the \textbf{slot table}. Identity = \textbf{call site} + call order;
        \texttt{key(id)\{\}} gives it explicitly (loops, reordering).
  \item \texttt{mutableStateOf} is a \textbf{snapshot} object (MVCC). Each phase runs under a
        \textbf{read observer} recording which scope read which state; an \textbf{applied}
        write invalidates exactly those scopes; many writes per frame = one recomposition.
  \item \textbf{Recompose scope} = a restartable (non-inline, \texttt{Unit}-returning)
        composable. \texttt{Column}/\texttt{Row}/\texttt{Box} are \texttt{inline}: their
        content re-runs with the caller. A content lambda is its own scope
        (``donut-hole skipping'').
  \item \textbf{Backwards write} (write after reading in the same composition) $\to$
        endless recomposition.
\end{itemize}

\section{Stability \& skipping}
\begin{itemize}\raggedright
  \item \textbf{Stable} = \texttt{equals} forever consistent, public changes notify
        composition, all public props stable: primitives, \texttt{String}, function types,
        \texttt{val}-only classes of those. \textbf{Unstable}: any \texttt{var},
        \texttt{List/Set/Map}, classes from a module \textbf{without} the Compose compiler.
  \item \texttt{@Immutable} = never changes after construction; \texttt{@Stable} = may change
        but only through \texttt{State}. \textbf{Promises, not checks} — lie and the UI goes stale.
  \item \textbf{Strong skipping} (default since \textbf{Kotlin 2.0.20}): every restartable
        composable is skippable; \textbf{unstable} params compared by \eqeqeq{} (instance),
        stable by \texttt{equals}; \textbf{every lambda is auto-\texttt{remember}ed}, keyed
        on its captures. Opt out: \texttt{@NonSkippableComposable}, \texttt{@DontMemoize}.
  \item Today's bug: a \textbf{new instance each pass} (\texttt{list.filter\{\}} in the body)
        $\to$ \neqeq{} $\to$ re-run. Fix: \texttt{remember}, \texttt{ImmutableList}
        (kotlinx), \texttt{@Immutable}, or a \texttt{stabilityConfigurationFile}.
\end{itemize}

\section{Example}
\begin{lstlisting}[language=KotlinSheet]
@Immutable data class Item(val id: Long, val kind: Kind,
                           val tags: ImmutableList<String>)
@Composable fun Feed(items: ImmutableList<Item>) {
  val list = rememberLazyListState()
  val showTop by remember {         // recompose only on the flip
    derivedStateOf { list.firstVisibleItemIndex > 0 } }
  Header(Modifier.offset {          // read in LAYOUT, not composition
    IntOffset(0, -list.firstVisibleItemScrollOffset / 2) })
  LazyColumn(state = list) {
    items(items, key = { it.id }, contentType = { it.kind }) {
      ItemRow(it) }                 // key: state follows the item
  }
  if (showTop) ScrollTopButton()
}
\end{lstlisting}

\textbf{vs SwiftUI:} both track \emph{reads} (\texttt{@Observable} in \texttt{body} $\approx$
snapshot reads); SwiftUI diffs view \emph{values} by structural identity + \texttt{.id()},
Compose re-runs \emph{functions} and skips by parameter equality.

\columnbreak

\section{remember family — when which}
\begin{itemize}\raggedright
  \item \texttt{remember(k1, k2) \{\}}: recompute when a key changes (like React's \texttt{useMemo} with deps).
        \texttt{rememberSaveable}: + rotation and process death (Bundle or \texttt{Saver}).
  \item \texttt{derivedStateOf} (inside \texttt{remember}): only when the \textbf{input changes
        more often than the output} (scroll index $\to$ Boolean); else \texttt{remember(x)}.
  \item \textbf{Lazy lists}: \texttt{key} (default = index) keeps item state across inserts
        and moves; \texttt{contentType} reuses compositions between same-type items.
\end{itemize}

\section{Side effects — beyond the basics}
\begin{itemize}\raggedright
  \item \texttt{LaunchedEffect(k)}: new key $\Rightarrow$ \textbf{cancel + relaunch}; to call
        the \emph{latest} lambda without restarting, \texttt{rememberUpdatedState}.
  \item \texttt{DisposableEffect(k)} must end in \texttt{onDispose\{\}};
        \texttt{SideEffect\{\}} runs after every \emph{successful} composition.
  \item \texttt{produceState}: source $\to$ \texttt{State}; \texttt{snapshotFlow\{\}}:
        \texttt{State} $\to$ cold \texttt{Flow} of distinct values (analytics, debounce).
\end{itemize}
\begin{lstlisting}[language=KotlinSheet]
@Composable fun Splash(onTimeout: () -> Unit) {
  val latest by rememberUpdatedState(onTimeout)
  LaunchedEffect(Unit) { delay(3_000); latest() } // no restart
}
\end{lstlisting}

\section{Measure, don't guess}
\begin{itemize}\raggedright
  \item \textbf{Compiler reports} (\texttt{composeCompiler \{ reportsDestination \}}, release
        build): \texttt{-composables.txt} = \texttt{restartable skippable} + per-param
        \texttt{stable}/\texttt{unstable}; \texttt{-classes.txt} = inferred stability.
  \item \textbf{Layout Inspector}: recomposition + skip counts per node. Judge jank on
        release only.
\end{itemize}

\section{Traps}
\begin{itemize}\raggedright
  \trap{Scroll offset read in composition $\to$ recompose every frame.}
  \trap{Strong skipping + a fresh \texttt{List} per pass $\to$ still re-runs.}
  \trap{\texttt{LaunchedEffect(Unit)} + captured callback $\to$ stale.}
\end{itemize}

\textbf{Remember:} \emph{read later (draw > layout > composition), read lower (small
scopes), same instance or stable type.}
