\sheettitle{Android background work — which API, and what the OS allows}{cross-platform · folio}

\oneliner{Android runs your code in the background only on its terms: a \textbf{coroutine} dies with
its owner, \textbf{WorkManager} guarantees deferrable work (persisted, survives reboot, runs when
quota and constraints allow), a \textbf{foreground service} is visible work the user started, and
\textbf{AlarmManager} is for a wall-clock moment. Every release since 6.0 (Doze) has narrowed the
rest: standby-bucket quotas, background-start bans, typed and time-limited services.}

\section{WorkManager internals}
\begin{itemize}\raggedright
  \item \texttt{enqueue} writes a \texttt{WorkSpec} row to WorkManager's own \textbf{Room} DB, then
        schedules it with \texttt{JobScheduler} (and runs it in-process at once if constraints
        already hold). Reboot, update, force-stop: rows re-registered (boot receiver, next launch).
  \item One run of a worker $\approx$ one job: the system stops it after \textbf{10 min}
        (\texttt{CoroutineWorker} is cancelled, work is retried). Longer: \texttt{setForeground()}
        $\to$ \texttt{SystemForegroundService} — declare it in the manifest with your FGS type.
  \item Numbers: backoff default \textbf{EXPONENTIAL 30\,s}, min 10\,s, max 5\,h; periodic
        $\geq$ \textbf{15 min}, flex $\geq$ 5 min; \texttt{Data} $\leq$ 10\,KB — pass URIs/ids.
  \item \texttt{enqueueUniqueWork(name, KEEP|REPLACE|APPEND|APPEND\_OR\_REPLACE, r)} (periodic:
        \texttt{KEEP/UPDATE}). \texttt{beginWith(listOf(a, b)).then(c)}: outputs merged by an
        \texttt{InputMerger}; a failed parent fails the chain.
  \item \textbf{Expedited}: \texttt{setExpedited(RUN\_AS\_NON\_EXPEDITED\_WORK\_REQUEST |
        DROP\_WORK\_REQUEST)}; quota by standby bucket, none while in foreground; below Android
        12 it runs as an FGS via \texttt{getForegroundInfo()} — missing it = crash.
\end{itemize}

\section{Example — a resilient upload}
\begin{lstlisting}[language=KotlinSheet]
@HiltWorker class UploadWorker @AssistedInject constructor(
  @Assisted ctx: Context, @Assisted p: WorkerParameters, val api: Api
) : CoroutineWorker(ctx, p) {
  override suspend fun doWork(): Result = try {
    setForeground(info())                  // may outlive 10 min
    api.upload(inputData.getString("uri")!!); Result.success()
  } catch (e: IOException) {
    if (runAttemptCount < 5) Result.retry() else Result.failure() }
  override suspend fun getForegroundInfo() = info() // expedited < 12
  private fun info() = ForegroundInfo(42, notification(),
      ServiceInfo.FOREGROUND_SERVICE_TYPE_DATA_SYNC) }
WorkManager.getInstance(ctx).enqueueUniqueWork("upload",
  ExistingWorkPolicy.KEEP, OneTimeWorkRequestBuilder<UploadWorker>()
    .setConstraints(Constraints.Builder()
      .setRequiredNetworkType(NetworkType.UNMETERED).build())
    .setInputData(workDataOf("uri" to uri)).build())
\end{lstlisting}

\section{Traps}
\begin{itemize}\raggedright
  \trap{``WorkManager for a 30-min download the user tapped'' — FGS or UIDT job.}
  \trap{Tested on a plugged-in phone — force Doze and a \texttt{rare} bucket.}
  \trap{\texttt{Thread}/coroutine in a \texttt{BroadcastReceiver} or \texttt{Application} — the
        process can be killed the moment no component is active.}
\end{itemize}

\textbf{Remember:} \emph{dies with screen $\to$ coroutine · clock $\to$ alarm · visible now $\to$
typed FGS · must finish $\to$ WorkManager.}

\section{Foreground services — the rules by version}
\begin{itemize}\raggedright
  \item \textbf{12+}: no FGS start from the background $\to$
        \texttt{ForegroundServiceStartNotAllowedException}. Exemptions: high-priority FCM,
        exact alarm, notification/widget tap, some \texttt{BOOT\_COMPLETED} starts,
        \texttt{SYSTEM\_ALERT\_WINDOW} (15+: only with a visible overlay).
  \item \textbf{14+}: \texttt{android:foregroundServiceType} + \texttt{FOREGROUND\_SERVICE\_<TYPE>}
        permission, else \texttt{MissingForegroundServiceTypeException}; declared in Play Console.
        Camera/mic/location types can't start in background even when exempt.
        \texttt{shortService}: $\sim$\textbf{3 min}.
  \item \textbf{15+}: \texttt{dataSync} and \texttt{mediaProcessing} get \textbf{6 h per 24 h}
        (each), then \texttt{Service.onTimeout(int, int)} — not stopped = crash; foreground resets
        it. \texttt{BOOT\_COMPLETED} may not start \texttt{dataSync}, \texttt{mediaPlayback},
        \texttt{mediaProjection}, \texttt{phoneCall}.
\end{itemize}

\section{Doze \& App Standby Buckets}
\raggedright \textbf{Doze} (unplugged, still, screen off): no network, wakelocks ignored,
jobs/syncs/alarms wait for \textbf{maintenance windows}; \texttt{…AllowWhileIdle} alarms $\leq$
once per \textbf{9 min} per app; high-priority FCM gets brief network. \textbf{Buckets} (usage,
ML-predicted) cap work:

{\scriptsize\noindent\begin{tabularx}{\linewidth}{@{}lLLl@{}}
\toprule
\textbf{Bucket} & \textbf{Regular jobs} & \textbf{Expedited} & \textbf{Alarms} \\
\midrule
Active & 20 min / 60 min & 30 min / 24 h & no limit \\
Working set & 10 min / 4 h & 15 min / 24 h & 10 / h \\
Frequent & 10 min / 12 h & 10 min / 24 h & 2 / h \\
Rare (no network) & 10 min / 24 h & 10 min / 24 h & 1 / h \\
Restricted (12+) & 1 run / day, 10 min & 5 min / 24 h & 1 / day \\
\bottomrule
\end{tabularx}}
\textbf{16}: jobs started while visible or running beside an FGS now count against the quota.
Test: \texttt{am set-standby-bucket <pkg> rare} · \texttt{dumpsys deviceidle force-idle}.

\section{Exact alarms \& broadcasts}
\begin{itemize}\raggedright
  \item \textbf{12}: exact needs \texttt{SCHEDULE\_EXACT\_ALARM}; \textbf{13}: or
        \texttt{USE\_EXACT\_ALARM} (auto-granted, not revocable, policy-limited); \textbf{14}: the
        former is \textbf{denied by default} on new installs — \texttt{canScheduleExactAlarms()}.
        Inexact \texttt{set()}: within 1 h.
  \item Manifest receivers get no implicit broadcasts (8.0+) bar a short list
        (\texttt{BOOT\_COMPLETED}, …). \texttt{onReceive} runs on main, $<$\textbf{10\,s};
        \texttt{goAsync()} buys time, not a lifetime — hand off to WorkManager.
\end{itemize}
