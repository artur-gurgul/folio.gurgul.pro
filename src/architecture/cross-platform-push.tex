\sheettitle{Push on iOS + Android from one app — FCM, APNs, React Native}{architecture · folio}

\oneliner{Your server addresses \textbf{installs}, not users. Each install gets a \textbf{token} (on iOS the
FCM SDK maps the APNs token to an \textbf{FCM token}) and uploads it keyed by \emph{user + device}; the
backend \textbf{fans out} to every live token via \textbf{FCM HTTP v1} (or APNs directly) and deletes the
ones reported dead. What runs on arrival depends on \textbf{message type}, \textbf{app state} and platform.}

\hd{Token lifecycle}
\begin{itemize}
  \item \textbf{Register}: Android — the FCM SDK gets a token. iOS — \ct{registerForRemoteNotifications}
        $\to$ APNs token $\to$ the FCM SDK (swizzled AppDelegate, or set
        \ct{Messaging.messaging().apnsToken} when \ct{FirebaseAppDelegateProxyEnabled = NO})
        $\to$ FCM token. APNs token $\neq$ FCM token: never send one to the other's API.
  \item \textbf{Refresh}: reinstall, restore to a new phone, cleared app data, and at FCM's discretion
        $\to$ \ct{onTokenRefresh}. Upload on every launch with a timestamp.
  \item \textbf{Many per user}: one row per install (phone + tablet + old phone), each with platform,
        APNs environment, app version, locale. \textbf{Stale}: FCM calls a registration stale after a
        month offline and expires Android tokens after 270 days inactive — prune on your timestamps.
  \item \textbf{Delete}: logout $\to$ \ct{deleteToken()} + delete/unlink the row, or the next person
        on that phone gets the last user's pushes. FCM is moving to Firebase Installation IDs (FIDs).
\end{itemize}

\hd{Priorities}
Android \textbf{high} may wake a device in Doze; if high-priority messages don't produce visible
notifications FCM may downgrade them to normal. APNs \textbf{10} = now (alerts), \textbf{5} = power-friendly —
FCM rejects priority 10 for data-only messages to Apple devices. Android 13+: runtime
\ct{POST\_NOTIFICATIONS}; Android 8+: every notification needs a \textbf{channel}.

\hd{Rich \& encrypted payloads}
iOS: \ct{apns.fcm\_options.image} + \ct{mutable-content} $\to$ an NSE calls
\ct{Messaging.serviceExtension()} \ct{.populateNotificationContent(\_:withContentHandler:)}. \textbf{E2EE}:
send ciphertext in \ct{data} + a generic alert; the NSE decrypts with a key shared via an App Group /
Keychain access group and rewrites title/body. Android: send \textbf{data} only, decrypt in your service,
post the notification yourself.

\hd{React Native specifics}
\begin{itemize}
  \item \ct{@react-native-firebase/messaging}: register the background handler early, outside
        components; an iOS background launch can be \textbf{headless} — check \ct{isHeadless}, render
        nothing. \ct{onMessage} shows nothing: use \textbf{Notifee}. RNFB's \ct{requestPermission} is
        deprecated $\to$ react-native-permissions / expo-notifications.
  \item Expo: \ct{expo-notifications} + Expo's push service, or raw FCM/APNs tokens.
\end{itemize}

\hd{Server fan-out}
Event $\to$ queue $\to$ workers: look up the user's live tokens, render per locale, send \textbf{one
message per token} (Admin SDK \ct{sendEach}/\ct{sendEachForMulticast}, $\leq$ 500 per call;
\ct{sendAll}/\ct{sendMulticast} are deprecated), \textbf{topics} for broadcasts. Retry 429/5xx with
backoff; delete on \ct{UNREGISTERED} (404), and on \ct{INVALID\_ARGUMENT} (400) only if the payload is
valid (APNs: 410). Idempotency key per event: a retried job must not double-notify.

\hd{Traps}
\begin{itemize}
  \trap{Android \emph{notification} message in background: your handler never runs — send \emph{data}.}
  \trap{No \ct{deleteToken} on logout — the next user gets the old one's pushes.}
  \trap{Data-only to iOS as a sync trigger — throttled, dropped after force-quit.}
  \trap{Xcode build (sandbox APNs) vs TestFlight (production): different tokens.}
\end{itemize}

\hd{Remember}
\textbf{``Token per install, rows per user, one send per token, delete on 404 — and know which
messages your code never sees.''}
