\sheettitle{JWT attacks \& token hardening — RFC 8725, DPoP, RFC 9700}{security · folio}

\oneliner{Every classic JWT break is the verifier \textbf{trusting the token to describe how to verify itself}:
the header's \ct{alg}, \ct{kid}, \ct{jku}, \ct{jwk} are \emph{attacker input}. Fix: the server decides algorithm,
key and token type (RFC 8725). A signed bearer token is still stealable — \textbf{DPoP} (RFC 9449) binds it to a
key the client holds, and the \textbf{OAuth Security BCP} (RFC 9700, Jan 2025) requires public clients' refresh
tokens to be \textbf{sender-constrained or rotated}.}

\hd{Validation that cannot be steered (RFC 8725)}
\begin{itemize}
  \item \textbf{Algorithm from config, not from the token} (§3.1): the key object carries its one algorithm;
        asymmetric keys can't be used as HMAC secrets.
  \item \textbf{Keys from your trust anchor}: JWKS from the issuer's configured URL, cached; \ct{kid} only
        \emph{selects}. Ignore \ct{jku}, \ct{x5u}, \ct{jwk}, \ct{x5c} unless pinned to an allow-list.
  \item \textbf{Explicit typing} (§3.11): \ct{typ: at+jwt} (RFC 9068) for access tokens, \ct{dpop+jwt} for proofs;
        mutually exclusive rules per token kind (§3.12) stop cross-JWT confusion.
  \item \textbf{Claims}: \ct{iss} exact, \ct{aud} = me, \ct{exp}/\ct{nbf} with small leeway, \ct{sub} format;
        \ct{crit} header you don't understand $\Rightarrow$ reject.
  \item \textbf{Received claims are input} (§3.10): \ct{kid}, \ct{sub}, \ct{email} into SQL, paths, LDAP, logs
        $=$ injection.
\end{itemize}

\hd{JWS vs JWE}
\textbf{JWS} (RFC 7515, 3 parts): integrity + origin, payload \emph{readable}. \textbf{JWE} (RFC 7516, 5 parts:
header . encrypted key . IV . ciphertext . tag): confidentiality; \ct{alg} wraps a CEK (\ct{RSA-OAEP},
\ct{ECDH-ES}, \ct{dir}), \ct{enc} seals (\ct{A256GCM}). Avoid \ct{RSA1\_5} (Bleichenbacher oracle); validate
ECDH-ES points (invalid-curve attack). Need both? \textbf{sign, then encrypt} (nested JWT, \ct{cty:"JWT"}).
A JWE made with the server's \emph{public} key proves nothing about who made it.

\hd{Example — a verifier the token cannot steer (\ct{jose}, Node)}
\begin{lstlisting}
const JWKS = createRemoteJWKSet(
  new URL('https://auth.example.com/.well-known/jwks.json'))
const { payload } = await jwtVerify(token, JWKS, {
  algorithms: ['ES256'],        // allow-list: none / HS256 fail
  issuer: 'https://auth.example.com',
  audience: 'https://api.example.com',
  typ: 'at+jwt',                // explicit typing, RFC 9068
  clockTolerance: 30,           // seconds of skew
  maxTokenAge: '15m',           // iat bound, even if exp is far
})
\end{lstlisting}

\hd{Test your own API — each must be refused}
\ct{alg} none/None · RS$\to$HS with the public key · \ct{kid} path/SQL · \ct{jku} to your host · embedded
\ct{jwk} · signature stripped · expired / future \ct{nbf} · ID token or other \ct{aud} · refresh token reused after logout.

\hd{RFC 9700 — the rules}
{\footnotesize
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{22mm}>{\raggedright\arraybackslash}p{50mm}@{}}
\toprule
PKCE & public clients \textbf{MUST}; AS MUST reject a \ct{code\_verifier} with no challenge (downgrade) \\
implicit / ROPC & implicit \textbf{SHOULD NOT}; password grant \textbf{MUST NOT} \\
redirect URI & \textbf{exact string match} (except localhost port) \\
refresh tokens, public client & \textbf{MUST} be \textbf{sender-constrained} (DPoP / mTLS) \textbf{or rotated} \\
access tokens & SHOULD be sender-constrained; least privilege, audience-restricted \\
\bottomrule
\end{tabular}}\par
\textbf{Rotation} detects theft \emph{after} both parties use the RT (reuse $\to$ revoke family);
\textbf{sender-constraining} makes a stolen RT \emph{unusable} without the private key.

\hd{Tokens on the phone}
\textbf{iOS}: Keychain, \ct{ThisDeviceOnly}; DPoP key in the \textbf{Secure Enclave} (\ct{SecureEnclave.P256.Signing})
— signs, never exported, so a backup/jailbreak dump does not carry it. \textbf{Android}: Android
Keystore. \textbf{RN}: \ct{react-native-keychain} / \ct{expo-secure-store} —
\textbf{never} \ct{AsyncStorage} (plain file). Access token in memory; log out $=$ revoke RT + wipe + drop key.

\hd{Traps}
\begin{itemize}
  \trap{``We verify the signature'' — with which algorithm and key? If the token chose either, it's forgeable.}
  \trap{\ct{decode()} vs \ct{verify()}: reading claims without verifying is an auth bypass.}
  \trap{HS256 shared across services: every service can mint tokens for all the others.}
  \trap{JWE is not authentication — anyone with your public key can encrypt to you.}
  \trap{DPoP without \ct{jti}/\ct{iat} checks: a proof can be replayed within its window; use nonces.}
  \trap{Blocking \ct{alg:none} by string compare: \ct{"None"} slips through\unverified — allow-list instead.}
\end{itemize}

\hd{Remember}
\textbf{``The server picks alg, key and type; the token only picks which of \emph{my} keys (kid). Bind what you can't keep secret.''}
