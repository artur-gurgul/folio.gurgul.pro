\sheettitle{Code smells → refactorings}{design · folio}

\oneliner{\textbf{Refactoring} (Fowler): \emph{``a change made to the internal structure of software
to make it easier to understand and cheaper to modify \textbf{without changing its observable
behaviour}''}. A \textbf{smell} is a surface symptom that \emph{suggests} a deeper problem — name the
smell, name the refactoring, and keep behaviour pinned: \textbf{tests first, tiny steps,
commit each green step}.}

\pat{The discipline}{\textbf{No tests $\to$ write characterization tests first} (Feathers: legacy = code without tests): pin \emph{today's} behaviour, bugs included — assert a wrong value, read the actual from the failure, paste it in; snapshot/golden master for big outputs. Then: \textbf{one tiny behaviour-preserving step} $\to$ run tests $\to$ \textbf{commit}; red $\to$ \textbf{revert}, don't debug. \textbf{Two hats} (Beck): refactoring \emph{or} adding behaviour, never both in one step/PR. \textbf{Preparatory refactoring}: \emph{``make the change easy (warning: this may be hard), then make the easy change''} (Beck). Prefer IDE refactors (Xcode Rename, Extract to Method) — mechanical = safe. Public interface: \textbf{parallel change} (expand $\to$ migrate callers $\to$ contract), with \texttt{@available(*, deprecated, renamed:)}.}

\pat{Big rewrites — strangler fig}{Put a facade/router in front; send one feature at a time to the new code; the legacy shrinks until nothing routes to it. iOS: new SwiftUI screens in \texttt{UIHostingController} inside the UIKit app; a protocol in front of the old service with a feature flag choosing the implementation (\textbf{branch by abstraction}). Every step ships and can be rolled back. The warning against big-bang: Spolsky, \emph{``Things You Should Never Do''} (Netscape's rewrite).}

\begin{lstlisting}[language=SwiftSheet]
// BEFORE: primitive obsession + long list + type code
func book(from: String, to: String, date: Date,
  adults: Int, kids: Int, cabin: Int, email: String)
// AFTER: value object, parameter object, enum
struct Email { let raw: String
  init?(_ s: String) { guard s.contains("@") else { return nil }
    raw = s } }
enum Cabin { case economy, business, first }
struct Trip { var from, to: Airport; var date: Date
  var adults = 1, kids = 0; var cabin = Cabin.economy }
func book(_ trip: Trip, contact: Email)
\end{lstlisting}

\pat[sheetOrange]{Remember}{\textbf{Name the smell, name the refactoring · pin behaviour first · one step, green, commit · strangle, don't rewrite · refactor the hotspots.}}

\columnbreak

\pat{When NOT to refactor}{Code nobody needs to change (ugly but stable: leave it — refactor where you \emph{work}; boy-scout rule applies to the area you touch) · no tests and no cheap way to get them · right before a release · a published API without a deprecation path · taste alone. A refactoring needs a \emph{payoff}: the next feature, a bug class, onboarding.}

\pat{Measure, don't guess}{\textbf{Cyclomatic complexity} (McCabe, 1976) = $E - N + 2P$ on the control-flow graph $\approx$ 1 + decision points (\texttt{if}, \texttt{guard}, loops, \texttt{case}, \texttt{\hbox{\&}\hbox{\&}}, \texttt{\hbox{|}\hbox{|}}, \texttt{?:}, \texttt{catch}); = the minimum number of test paths. McCabe's limit 10; SwiftLint \texttt{cyclomatic\_complexity} warns at 10, errors at 20. \textbf{Cognitive complexity} (SonarSource) also penalises nesting. \textbf{Hotspots} (Tornhill, \emph{Your Code as a Crime Scene}): change frequency from \texttt{git log} × complexity — refactor the top-right, not the whole codebase. Also: SwiftLint \texttt{type\_body\_length}, \texttt{function\_parameter\_count}; coverage at the change point.}

\section{Traps}
\begin{itemize}
  \trap{\textbf{Shotgun surgery} (one change, many classes) $\ne$ \textbf{divergent change} (one class, many reasons) — opposites.}
  \trap{Refactoring without tests is just \emph{changing code}; ``refactor'' a feature in = two hats.}
  \trap{In Swift a switch over an \texttt{enum} is not the smell — a switch over a \emph{type code} (\texttt{Int}, \texttt{String}) repeated everywhere is.}
  \trap{``Moved the VC's code into a Manager'' relocated the smell (god object), not fixed it.}
\end{itemize}
