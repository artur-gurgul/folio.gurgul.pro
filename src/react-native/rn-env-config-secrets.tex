\sheettitle{Environments, config \& secrets in React Native}{react-native · folio}

\oneliner{An \textbf{environment} (dev / staging / prod: API host, ids, keys) is chosen \textbf{at build
time} — Android \ct{productFlavors}, iOS \textbf{configurations + schemes}, or Expo's
\ct{app.config} + EAS \textbf{environments}. Every value that reaches JS or a native resource is
\textbf{inside the binary}; only values read \emph{by the build itself} (signing, uploads) stay secret.}

\hd{Three words that get mixed up}
\textbf{environment} = which backend + ids (dev/staging/prod) · \textbf{build type} = how it is built
(debug: Metro, dev menu; release: bundled, minified, signed) · \textbf{variant} = flavor × build
type (\ct{stagingRelease}). Each environment gets its \textbf{own bundle id / applicationId}: installs
side by side, separate push tokens, keychains, analytics and store/TestFlight tracks.

\hd{Android — productFlavors}
\begin{lstlisting}[language=GradleSheet]
android {
  buildFeatures { buildConfig true }    // AGP 8: off by default
  flavorDimensions "env"
  productFlavors {
    staging { dimension "env"; applicationIdSuffix ".staging"
      resValue "string", "app_name", "Example S"
      buildConfigField "String", "API_HOST",
                       '"https://api.staging.example.com"' }
    prod    { dimension "env" }
  }
}
react { debuggableVariants = ["stagingDebug", "prodDebug"] }
// npx react-native run-android --mode stagingDebug
\end{lstlisting}
\begin{itemize}
  \item \ct{debuggableVariants} skip JS bundling (default \ct{debug}, \ct{debugOptimized});
        with flavors you \textbf{must} list them, or those debug builds bundle JS too.
  \item Per-flavor files live in \ct{src/<flavor>/}: \ct{google-services.json}, icons, \ct{res/}.
        \ct{\dd{}variant} was replaced by \ct{\dd{}mode} in the RN CLI\unverified.
\end{itemize}

\hd{iOS — configurations, schemes, xcconfig}
\begin{itemize}
  \item Project $\to$ Info: duplicate Release as \ct{Staging}; each configuration gets an
        \ct{.xcconfig} (\ct{PRODUCT\_BUNDLE\_IDENTIFIER}, \ct{API\_HOST}, app icon name). A
        \textbf{scheme} per environment picks the configuration for Run / Archive.
  \item Info.plist \ct{<string>\$(API\_HOST)</string>} copies a build setting into the app —
        public, like everything in Info.plist.
  \item Podfile maps custom names: \ct{project 'App', 'Dev' \fat{} :debug} — an unmapped
        configuration is built as \ct{:release} (CocoaPods default).
  \item xcconfig treats \ct{//} as a comment: \ct{https://x} truncates to \ct{https:} — write
        \ct{https:/\$()/x}\unverified.
  \item Per-env entitlements too: \ct{aps-environment}, associated domains, App Group ids.
\end{itemize}

\hd{Expo — one codebase, many variants}
\begin{lstlisting}[language=TSSheet]
// app.config.ts - evaluated at build/prebuild, NOT at runtime
import { ExpoConfig, ConfigContext } from 'expo/config';
const V = process.env.APP_VARIANT ?? 'production';
const id = V === 'production' ? 'com.example.app'
                              : `com.example.app.${V}`;
export default ({ config }: ConfigContext): ExpoConfig => ({
  ...config, name: V === 'production' ? 'Example' : `Example ${V}`,
  ios: { ...config.ios, bundleIdentifier: id },
  android: { ...config.android, package: id },
});
// eas.json build.preview: { "environment": "preview",
//   "env": { "APP_VARIANT": "preview" }, "channel": "preview" }
\end{lstlisting}
\begin{itemize}
  \item \ct{EXPO\_PUBLIC\_*} is \textbf{inlined at bundle time}, and only for static dot access
        \ct{process.env.EXPO\_PUBLIC\_API\_URL} — bracket access or destructuring stays
        \ct{undefined}. A change needs a new bundle (restart Metro, clear its cache).
  \item \textbf{EAS environment variables}: plain text (visible everywhere) · sensitive (masked
        in logs) · \textbf{secret} (never readable outside EAS servers). A build picks them via
        \ct{"environment"} in \ct{eas.json}; \ct{eas env:pull \dd{}environment
        development} writes \ct{.env.local}; \ct{eas update \dd{}environment
        production} — or the update is bundled with your \emph{local} values.
  \item \textbf{react-native-config}: \ct{.env} $\to$ \ct{Config.API\_URL} (JS),
        \ct{BuildConfig} (Android), \ct{\$(VAR)} in Info.plist; \ct{ENVFILE=.env.staging}. Its
        README: it does \emph{not} obfuscate or encrypt — no sensitive keys in \ct{.env}.
\end{itemize}

\hd{Public or secret?}
{\footnotesize
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{36mm}>{\raggedright\arraybackslash}p{37mm}@{}}
\toprule
\textbf{fine in the app} & \textbf{never in the app} \\ \midrule
API base URL, Sentry DSN, Stripe \ct{pk\_}, Firebase config, Maps key \emph{restricted} to your
ids, flag defaults & Stripe \ct{sk\_}, LLM / payment / DB keys, signing keys, keystore + ASC
credentials, \ct{SENTRY\_AUTH\_TOKEN} \\
\bottomrule
\end{tabular}}\par
Values that must change without a build (limits, kill switches) come from the server: remote
config / flags, per environment.

\hd{Traps}
\begin{itemize}
  \trap{``It's an EAS \emph{secret}'' — public once exposed to JS or \ct{extra}.}
  \trap{\ct{const \{ EXPO\_PUBLIC\_URL \} = process.env} $\to$ \ct{undefined}.}
  \trap{OTA update without \ct{\dd{}environment}: prod app talks to staging.}
  \trap{One bundle id for staging + prod: overwrites, crossed push tokens.}
\end{itemize}

\hd{Remember}
\textbf{Chosen at build · baked into the binary · only the build keeps a secret.}
