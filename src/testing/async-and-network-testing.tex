\section{Expectations, precisely}
\begin{itemize}
  \item \ct{wait(for:timeout:)} is \textbf{unavailable in \ct{async} functions} since Xcode 14.3
        (it can deadlock): \ct{await fulfillment(of:timeout:)}. Left out, the timeout is
        \ct{.infinity} — only \ct{executionTimeAllowance} then ends a hang.
  \item A wait returns the moment all are fulfilled: the timeout is a \emph{ceiling}.
        \ct{XCTWaiter.Result}: \ct{completed} · \ct{timedOut} · \ct{incorrectOrder} ·
        \ct{invertedFulfillment} · \ct{interrupted}.
  \item Over-fulfilling fails only with \ct{assertForOverFulfill}: \ct{true} from the
        \ct{XCTestCase} convenience methods, \ct{false} from \ct{XCTestExpectation(description:)}.
  \item Predicate expectations \textbf{poll} — slow; prefer callback, KVO or notification ones
        (inject a private \ct{NotificationCenter()}, hand it to the expectation).
  \item Swift Testing has no wait: a confirmation neither blocks nor suspends. \ct{XCTestExpectation}
        is unsupported in \ct{@Test} — even 6.4's interop (\ct{XCTAssert} now counts there)
        excludes it. Bridge a callback:\newline
        \ct{try await withCheckedThrowingContinuation \{ c in}\newline
        \ct{\ \ api.fetch(42) \{ c.resume(with: \$0) \} \}}\newline
        Resume \textbf{exactly once}: a second resume is a \ct{fatalError}; none leaves the test
        suspended for ever and logs ``leaked its continuation''.
\end{itemize}

\section{Traps}
\begin{itemize}
  \trap{\ct{static var handler} under Swift Testing: all suites run in parallel in one process,
        and \ct{.serialized} does not order unrelated suites — two suites overwrite one stub.
        Key handlers per test (own host or header → table) or nest every network suite in one
        \ct{.serialized} parent. Swift 6 mode: \ct{nonisolated(unsafe)} or a lock.}
  \trap{\ct{URLProtocol.registerClass} is global (consulted in reverse order) — set the
        session's \ct{protocolClasses}. \ct{.ephemeral} still keeps caches, cookies in RAM.}
\end{itemize}

\section{The stub}
\begin{lstlisting}[language=SwiftSheet]
final class MockURLProtocol: URLProtocol {
  nonisolated(unsafe) static var handler:
    ((URLRequest) throws -> (HTTPURLResponse, Data))?
  override class func canInit(with r: URLRequest) -> Bool { true }
  override class func canonicalRequest(for r: URLRequest)
    -> URLRequest { r }
  override func startLoading() {
    do { let (resp, data) = try Self.handler!(request)
      client?.urlProtocol(self, didReceive: resp,
                          cacheStoragePolicy: .notAllowed)
      client?.urlProtocol(self, didLoad: data)
      client?.urlProtocolDidFinishLoading(self)
    } catch { client?.urlProtocol(self, didFailWithError: error) } }
  override func stopLoading() {} }
let config = URLSessionConfiguration.ephemeral
config.protocolClasses = [MockURLProtocol.self]
let sut = APIClient(session: URLSession(configuration: config))
MockURLProtocol.handler = { req in (HTTPURLResponse(url: req.url!,
  statusCode: 500, httpVersion: nil, headerFields: nil)!, Data()) }
await #expect(throws: APIError.status(500)) {
  try await sut.user(id: 42) }
\end{lstlisting}

\section{Time, streams, Combine}
\begin{itemize}
  \item \textbf{Clock}: depend on \ct{any Clock<Duration>} (iOS 16); \ct{sleep(for:)} works on the
        existential since Swift 5.9. Prod \ct{ContinuousClock()}; tests (swift-clocks)
        \ct{TestClock}: \ct{await clock.advance(by: .seconds(5))}, \ct{await clock.run()} until
        nothing sleeps; \ct{ImmediateClock} never suspends; \ct{UnimplementedClock} fails if used.
        Dates: inject \ct{() -> Date}. Timers / GCD: a scheduler protocol whose mock fires at once.
  \item \textbf{Combine}: Apple's \ct{ImmediateScheduler} ignores dates but has its own time
        types, so it cannot replace \ct{DispatchQueue} without generics; combine-schedulers'
        \ct{AnySchedulerOf<DispatchQueue>} + \ct{DispatchQueue.test} + \ct{advance(by:)} can.
        Keep the \ct{AnyCancellable} (deinit cancels), or \ct{for await} over
        \ct{publisher.values} (iOS 15, \ct{Failure == Never}).
  \item \textbf{AsyncStream}: drive the SUT through \ct{AsyncStream.makeStream(of:)} (5.9) — the
        test holds the continuation. Consume \emph{bounded}: \ct{s.prefix(3)} or \ct{finish()};
        an unfinished stream never ends the \ct{for await}.
\end{itemize}

\section{Ordering \& cancellation}
\begin{itemize}
  \item \ct{Task \{ await vm.load() \}} then assert: the next line usually runs before the task
        body. Await \ct{task.value}, call \ct{await vm.load()} directly, or use \ct{Task.immediate}
        (6.2: synchronous up to its first suspension). \ct{withMainSerialExecutor}
        (swift-concurrency-extras) serialises a test's tasks — tests only, flips a global.
  \item \ct{CancellationError} is promised by \ct{Task.checkCancellation()} and \ct{Task.sleep}, not
        by every API (URLSession: \ct{URLError}). Assert the outcome \emph{and} the side effect
        that must not happen. Swift Testing: a \ct{CancellationError} in a cancelled test =
        cancelled, not failed; \ct{Test.cancel()} (6.3).
  \item Cleanup (6.4): \ct{defer \{ await … \}} runs to completion;
        \ct{withTaskCancellationShield} hides cancellation from it (no back-deployment).
\end{itemize}

\section{Remember}
\textbf{Await the event, never sleep. Stub bytes, not objects — the real status check and decoder
run. Four failures: wire · status · decode · cancel. Time is a dependency: inject it, advance it.}
