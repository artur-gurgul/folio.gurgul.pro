\sheettitle{Test doubles — Dummy · Stub · Spy · Mock · Fake}{testing · folio}

\oneliner{A \textbf{test double} (Gerard Meszaros, \emph{xUnit Test Patterns}, 2007; Fowler:
``think stunt double'') replaces a \textbf{DOC} (depended-on component) so the \textbf{SUT} can be tested
alone. The five differ in what they do with the SUT's \textbf{indirect inputs} (what the DOC
returns or throws) and \textbf{indirect outputs} (the calls the SUT makes): a \textbf{Stub} feeds
inputs, a \textbf{Spy} records outputs for the test to check, a \textbf{Mock} checks outputs
itself, a \textbf{Fake} is a lighter working implementation, a \textbf{Dummy} is never called.}

\section{Meszaros' roles}

\toprule
& \textbf{purpose} & \textbf{indirect input} & \textbf{indirect output} & \textbf{test supplies} & \textbf{e.g.}\\
\midrule
\textbf{Dummy} & fill a parameter or attribute & never called & never called & nothing & \ct{nil}, ``ignored''\\
\textbf{Stub} & verify indirect \emph{inputs} & \textbf{injects} & ignores & inputs & canned reply, error\\
\textbf{Spy} & verify indirect \emph{outputs} & optional & \textbf{captures} for later & inputs (opt.) & call log\\
\textbf{Mock} & verify indirect \emph{outputs} & optional & \textbf{verifies} vs expectations & outputs + inputs (opt.) & expected calls\\

\bottomrule

Fowler: only mocks \emph{insist} on behaviour verification; the others can, and usually do,
verify state.

\section{Variations}
\begin{itemize}
  \item \textbf{Stub}: \emph{Responder} (valid inputs, happy path) · \emph{Saboteur} (errors,
        exceptions) · \emph{Temporary Test Stub} (the DOC is not written yet) · \emph{Entity
        Chain Snipping} (one object replaces a network of them).
  \item \textbf{Spy}: exposes its log through a \emph{Retrieval Interface}. \textbf{Mock}: an
        unexpected call or wrong argument fails the test \emph{immediately}, so the test may need
        no assertion; \emph{strict} also fails on out-of-order calls, \emph{lenient} (``nice'')
        tolerates them.
  \item \textbf{Fake}: Fake Database (not a database at all) · In-Memory Database (a real one, in
        RAM) · Fake Web Service · Fake Service Layer.
  \item \textbf{Dummy} should throw if called; a \emph{Null Object} \emph{is} called and does
        nothing.
  \item Built by hand, \emph{dynamically generated} at run time (jMock) or \emph{statically
        generated} as source compiled with the tests. \emph{Hard-coded} (fixed when written) or
        \emph{configurable} (programmed by the test). \emph{Self Shunt}: the test class itself is
        the double.
\end{itemize}

\section{One protocol, five doubles (Swift Testing)}
\begin{lstlisting}[language=SwiftSheet]
protocol Mailer { func send(to: String) -> Bool }

struct DummyMailer: Mailer {          // never to be called
  func send(to: String) -> Bool {
    Issue.record("dummy called"); return false } }
struct StubMailer: Mailer {           // control point
  var result: Bool
  func send(to: String) -> Bool { result } }
final class SpyMailer: Mailer {       // observation point
  private(set) var sent: [String] = []
  func send(to: String) -> Bool { sent.append(to); return true } }
final class MockMailer: Mailer {      // strict: order counts
  private var expected: [String]
  init(expect: [String]) { expected = expect }
  func send(to: String) -> Bool {
    guard expected.first == to else {   // fails AT the call
      Issue.record("unexpected send(to: \(to))"); return false }
    expected.removeFirst(); return true }
  func verify() { #expect(expected.isEmpty) } }  // none missing
final class FakeMailer: Mailer {      // works, no SMTP
  private(set) var outbox: [String] = []
  func send(to: String) -> Bool {
    guard to.contains("@") else { return false }
    outbox.append(to); return true } }
\end{lstlisting}
\begin{lstlisting}[language=SwiftSheet]
@Test func failedMailShowsError() {     // STATE
  let sut = Signup(mailer: StubMailer(result: false))
  sut.register("ada@x.io")
  #expect(sut.state == .emailFailed) }
@Test func sendsWelcomeOnce() {         // BEHAVIOUR
  let spy = SpyMailer()
  Signup(mailer: spy).register("ada@x.io")
  #expect(spy.sent == ["ada@x.io"]) }
\end{lstlisting}

\section{Classical vs mockist (Fowler)}

\begin{tabular}{@{}>{\raggedright\arraybackslash}p{11mm}>{\raggedright\arraybackslash}p{32mm}>{\raggedright\arraybackslash}p{33mm}@{}}
\toprule
& \textbf{classical (``Detroit'')} & \textbf{mockist (``London'')}\\
\midrule
doubles & real objects; a double where awkward (the mail service) & a mock for every object with interesting behaviour\\
verifies & state, mostly & behaviour — the calls\\

Fowler stays classical. Behaviour verification fits where state cannot show it — a cache hit vs
miss. Google (\emph{SE at Google} ch.\,13): real implementation first, then a fake; interaction-test
only \emph{state-changing} calls (\ct{sendEmail}, \ct{saveRecord}); overuse gives
\emph{change-detector tests}.

\section{Rules — \emph{Mock Roles, not Objects} (2004)}
``Mock Objects is misnamed'': it is a way to discover \emph{roles} (interfaces).
\begin{itemize}
  \item \textbf{Only mock types you own} — wrap runtime / library types in thin wrappers.
  \item \textbf{Specify as little as possible} — over-specified tests are brittle; a stub is an
        expectation that need not occur. Say explicitly what must \emph{not} happen.
  \item No mocks for \emph{boundary objects} (data, values, calculations): assert returns. No
        behaviour in mocks; mock immediate neighbours only; too many mocks = object too large.
  \item An immediate failure (mock) beats a post-hoc one (spy): the trace is at the bad call.
\end{itemize}

\section{Swift: doubles are generated, not conjured}
OCMock: mock frameworks ``depend heavily on access to the language runtime, and Swift only offers
extremely limited access'' — it mocks only \ct{NSObject} subclasses, from Objective-C tests. So
Swift tools emit source for the compiler (a codegen step, or an SE-0389 peer macro) — Meszaros'
\emph{statically generated} doubles.

\textbf{Names lie.} Mockito's \ct{mock()} ``will remember all interactions'' and is verified
\emph{after} — a Meszaros spy; Mockito's and Cuckoo's \emph{spy} runs real code (a partial mock).
\emph{Strict} in OCMock: an unexpected call fails; in Meszaros every mock does that, and
\emph{strict} adds order.

\section{On Apple platforms}
\begin{itemize}
  \item Fakes: SwiftData \ct{isStoredInMemoryOnly: true} (iOS 17); Core Data store URL
        \ct{/dev/null} = SQLite in memory (WWDC18) — keep one on-disk test. A fake needs
        \emph{contract tests} against the real thing.
  \item A \ct{Sendable} class is \ct{final} with only immutable sendable properties: put a
        spy's log in a \ct{Mutex} (Swift 6.0, iOS 18) or make it \ct{@MainActor}.
  \item Swift Testing's \ct{confirmation(expectedCount:)} counts callbacks: \ct{0} = must never
        happen; ranges from Swift 6.1.
\end{itemize}

\section{Traps}
\begin{itemize}
  \trap{Before Swift 6.4, \ct{XCTFail} in a \ct{@Test} (or \ct{\#expect} in an
        \ct{XCTestCase}) was silently ignored; 6.4's \emph{limited} interop still only
        \emph{warns} on the first, \emph{complete} fails.}
  \trap{\ct{fatalError} in a dummy crashes the test process, not one test; exit tests (6.2)
        don't run on iOS.}
  \trap{Stub returns exactly what you assert: you tested the stub.}
\end{itemize}
\textbf{Dummy \emph{fills} · Stub \emph{feeds} · Spy \emph{notes} · Mock \emph{judges} · Fake
\emph{works}.}
