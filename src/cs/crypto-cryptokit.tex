\sheettitle{Cryptography with CryptoKit — AEAD, ECDH, signatures, HPKE, ML-KEM}{cs · folio}

\oneliner{\textbf{Symmetric} AEAD (AES-GCM, ChaCha20-Poly1305) encrypts \emph{and} authenticates
bulk data under one key and a \textbf{nonce never repeated under that key}; \textbf{asymmetric}
keys \emph{agree} on that key (ECDH → HKDF, or a KEM inside HPKE) and \emph{sign} (ECDSA, Ed25519,
ML-DSA). CryptoKit ships vetted primitives with safe defaults — the job is choosing them, managing
keys and nonces, and \textbf{never inventing} a primitive, mode or protocol.}

\section{How it works}
\begin{itemize}
  \item \textbf{AEAD} = confidentiality + integrity + authenticity; \ct{open} throws on any flipped
        bit or wrong AAD. \textbf{AES-GCM}: 128/192/256-bit key. \textbf{ChaCha20-Poly1305}: 256-bit
        key, $\sim$3$\times$ faster than AES on chips without AES hardware. Both: 12-byte nonce,
        16-byte tag.
  \item \textbf{Nonce reuse} under one key: $C_1 \oplus C_2 = P_1 \oplus P_2$, and GCM gives away
        its \textbf{hash key} → trivial forgeries under that key (Poly1305: the one-time key
        repeats). A repeated nonce on \emph{decrypt} is harmless.
  \item \textbf{ECDH} output is not uniformly random: HKDF \textbf{extract} (salt; none = zeros),
        then \textbf{expand} with \ct{info} — one purpose per key, $\le$255 × hash length.
        Ephemeral pairs, discarded → forward secrecy.
  \item \textbf{ECDSA} $s = (h + x r)/k$: the same $k$ twice gives $k = (h_1 - h_2)/(s_1 - s_2)$,
        then the private key $x = (s k - h)/r$. RFC 6979 $k$ and EdDSA are deterministic —
        \textbf{CryptoKit randomizes both}: new bytes every call for the same key + message.
  \item \textbf{HPKE} (RFC 9180) = KEM → KDF → AEAD to a public key; nonce = base nonce XOR
        sequence number, so \textbf{open in the order sealed}: no loss or reordering, no replay
        protection, no forward secrecy if the recipient key leaks.
\end{itemize}

\section{Example — the CryptoKit calls}
\begin{lstlisting}[language=SwiftSheet]
let mine = Curve25519.KeyAgreement.PrivateKey()        // ephemeral
let key = try mine.sharedSecretFromKeyAgreement(with: theirPub)
  .hkdfDerivedSymmetricKey(using: SHA256.self, salt: salt,
     sharedInfo: Data("chat v1".utf8), outputByteCount: 32)
let box = try AES.GCM.seal(msg, using: key, authenticating: hdr)
let wire = box.combined!        // random 12 B nonce | ct | tag
let plain = try AES.GCM.open(.init(combined: wire), using: key,
                             authenticating: hdr)
let signer = P256.Signing.PrivateKey()  // SecureEnclave.P256: same
let sig = try signer.signature(for: msg)  // SHA-256, randomized
let ok = signer.publicKey.isValidSignature(sig, for: msg)
let jws = sig.rawRepresentation         // r|s 64 B; X.509: DER
// HPKE, hybrid post-quantum (iOS 26)
let suite = HPKE.Ciphersuite.XWingMLKEM768X25519_SHA256_AES_GCM_256
let sk = try XWingMLKEM768X25519.PrivateKey()
var tx = try HPKE.Sender(recipientKey: sk.publicKey,
                         ciphersuite: suite, info: info)
let c1 = try tx.seal(m1)       // send tx.encapsulatedKey once
var rx = try HPKE.Recipient(privateKey: sk, ciphersuite: suite,
                 info: info, encapsulatedKey: tx.encapsulatedKey)
let p1 = try rx.open(c1)       // open in the order sealed
\end{lstlisting}

\ct{SymmetricKey} bytes → a generic-password Keychain item.

\section{Secure Enclave}
Key types: \ct{P256} (signing, agreement), since iOS 26 also \ct{MLKEM768/1024} and
\ct{MLDSA65/87} — nothing symmetric, no one-time keys. Born inside, never leaves:
\ct{dataRepresentation} is an \emph{encrypted block} only the same SE can restore (store it in the
Keychain). Default access control \ct{AfterFirstUnlockThisDeviceOnly}, no flags.

\section{Post-quantum — why, and the cost}
Ciphertext recorded today can fall to a future quantum computer, so \textbf{key agreement moves
first}: FIPS 203 (ML-KEM), 204 (ML-DSA), August 2024. A \textbf{KEM} \ct{encapsulate}s to a public
key → (secret, ciphertext); only the private key \ct{decapsulate}s, in CryptoKit straight to a
\ct{SymmetricKey}. \textbf{Hybrid} = classical + PQ, safe while \emph{either} holds:
\textbf{X-Wing} = ML-KEM-768 + X25519 (aims at 128-bit, 768 for margin); signatures: ML-DSA
$\Vert$ ECDSA, verify both.

\section{Traps}
\begin{itemize}
  \trap{\textbf{ECB} (equal blocks → equal ciphertext); \textbf{CBC} without a MAC → padding
        oracles. Use AEAD.}
  \trap{\textbf{Fixed or reset nonce} (a counter restarting after reinstall; two devices, one key).
        \ct{seal(inPlace:)} has no random default.}
  \trap{\textbf{Hard-coded keys} — \ct{strings} finds them. \textbf{Password as a key} → slow KDF
        first: \ct{CCKeyDerivationPBKDF} (OWASP $\ge$600\,000 × HMAC-SHA256) or Argon2id.}
  \trap{\textbf{Tag compared after conversion} to \ct{Data} / \ct{[UInt8]} / hex \ct{String} with
        \ct{==} — early exit leaks timing. swift-crypto's MAC \ct{==} and
        \ct{isValidAuthenticationCode} are constant-time.}
  \trap{\textbf{Signature bytes as an ID} or test oracle — they differ every call; verify instead.
        ES256 JWS = the 64-byte raw form, not DER.}
  \trap{\textbf{One key, two jobs} → separate HKDF \ct{info}. \textbf{Unauthenticated ECDH} =
        agreeing with the attacker.}
  \trap{Key bytes from GameplayKit (``not cryptographically robust'') or a seeded test RNG.}
\end{itemize}

\section{Remember}
\textbf{Agree (ECDH or KEM) → derive (HKDF) → seal (AEAD, unique nonce) → sign what must be proven;
hybrid PQ for secrets that must outlive a quantum computer.} Never roll your own.
