\sheettitle{Code signing internals — what \ct{codesign} writes into a Mach-O}{security-build · folio}

\oneliner{A signature is a \textbf{SuperBlob} appended to \ct{\_\_LINKEDIT} and located by
\ct{LC\_CODE\_SIGNATURE}. Its heart is the \textbf{CodeDirectory}: a SHA-256 hash of every
\textbf{4~KiB page} of the file (code slots) plus hashes of \textbf{Info.plist, requirements,
resources and entitlements} (special slots). The hash of the CodeDirectory — the \textbf{cdhash} —
is what a \textbf{CMS} signature from your certificate signs, so one signature covers every byte;
the kernel re-hashes each page as it is \textbf{paged in}.}

\hd{Signing}
\begin{itemize}
  \item \ct{codesign} hashes the file in \textbf{4096-byte pages} up to \ct{codeLimit}, writes
        the CD, requirements and entitlements, then the CMS over the cdhash. Universal binary:
        \textbf{one signature per arch}, different cdhashes (\ct{\dd arch arm64}).
  \item \textbf{Hash agility}: macOS $\leq$ 10.11 needed a SHA-1 CD too (\ct{0x1000} alternate
        slot); since 10.12 a single SHA-256 CD. \ct{CodeDirectory v=20500 … hashes=14+7} =
        14 code pages + 7 special slots.
  \item \textbf{Entitlements} are signed in twice: XML plist (slot 5/$-5$) and DER
        (7/$-7$, the format the OS parses; required on iOS 15+\unverified). Old signatures without
        DER must be re-signed; App Store builds already are.
  \item \textbf{Bundles}: Info.plist and resources are outside the Mach-O, so they are
        \emph{sealed} by hash — edit one PNG and the seal breaks
        (``a sealed resource is missing or invalid'').
  \item \textbf{Nested code signs inside-out}: dylibs/frameworks $\to$ XPC services, app
        extensions, helpers $\to$ the app \textbf{last}, because the outer seal records each
        inner cdhash. Sign the app first and any inner re-sign invalidates it. Xcode does the
        order; by hand never sign with \ct{\dd deep} (it pushes one set of entitlements/options
        onto everything) — \ct{\dd deep} is for \emph{verify} only.
  \item Code must sit where code belongs (\ct{Frameworks/}, \ct{MacOS/}, \ct{PlugIns/}); a Mach-O
        in \ct{Resources/} is sealed as data, not signed as code.
\end{itemize}

\hd{Requirements — the code's identity (macOS)}
A \textbf{requirement} is a boolean expression over a signature; the \textbf{designated
requirement (DR)} says ``if you see me again, this is how you know it's me''. TCC grants,
keychain ACLs and XPC peers (\ct{setCodeSigningRequirement}) store the DR, not a hash —
that's how v1.3 inherits v1.2's microphone permission.
\begin{lstlisting}[language=ShSheet]
designated => identifier "com.example.app" and anchor apple generic
   and certificate leaf[subject.OU] = "ABCDE12345"   # team
anchor apple and identifier "com.apple.TextEdit"     # Apple's own
cdhash H"ff19a91b..."          # this exact build only - brittle
\end{lstlisting}

\hd{Example — reading and making a signature}
\begin{lstlisting}[language=ShSheet]
codesign -dvvv App.app       # CDHash, Authority chain, TeamIdentifier
codesign -d -vvvvvv App.app  # + every slot hash (page size 4096)
codesign -d --entitlements :- App.app   # raw XML ("bplist00" = broken)
codesign -d -r- App.app                 # designated => ...
codesign --verify --deep --strict -vvv App.app   # notarization-grade check
codesign -v -R \
  '=anchor apple generic and identifier "com.example.app"' App.app
codesign -s - -f tool            # ad hoc re-sign (after lipo/patch)
codesign -s "Developer ID Application: Alice (ABCDE12345)" \
  -o runtime --timestamp --entitlements app.entitlements -f App.app
\end{lstlisting}

\hd{How it is enforced}
\begin{itemize}
  \item \textbf{At exec / mmap}: the kernel loads the blob, checks each CD hash against the CMS'
        cdhash list; \textbf{AMFI} (AppleMobileFileIntegrity) decides if the signer may run
        this: platform binaries by cdhash in the \textbf{trust cache}, third-party code by
        certificate + provisioning profile (entitlements $\subseteq$ profile) via \ct{amfid}.
  \item \textbf{At page-in}: every page faulted in from a signed file is hashed and compared to
        its code slot. Mismatch + \ct{CS\_KILL} $\to$ \textbf{SIGKILL} (crash ``CODESIGNING''\unverified).
        Lazy: a tampered page that never runs is never noticed.
  \item \textbf{Process flags} (\ct{cs\_blobs.h}): \ct{CS\_VALID} 0x1 · \ct{CS\_ADHOC} 0x2 ·
        \ct{CS\_GET\_TASK\_ALLOW} 0x4 · \ct{CS\_HARD} 0x100 (refuse invalid pages) ·
        \ct{CS\_KILL} 0x200 · \ct{CS\_REQUIRE\_LV} 0x2000 (library validation) ·
        \ct{CS\_RUNTIME} 0x10000 (hardened runtime) · \ct{CS\_LINKER\_SIGNED} 0x20000.
  \item \textbf{Apple silicon}: macOS won't run \emph{unsigned} arm64 code at all — ad hoc is
        enough to run, not to distribute (Gatekeeper wants Developer ID + notarization). Intel
        could run unsigned. Patch a byte in a binary $\to$ killed at launch.
  \item \textbf{Team ID} (in the CD and the leaf's OU) drives library validation and
        keychain/app-group scoping.
\end{itemize}

\hd{Traps}
\begin{itemize}
  \trap{``The signature encrypts the app'' — no: it \emph{hashes and signs}; FairPlay
        (\ct{cryptid}) is the encryption.}
  \trap{\ct{codesign \dd deep} to \emph{sign} — wrong entitlements on nested code; sign inside-out.}
  \trap{Editing Info.plist / a resource after signing breaks the seal.}
  \trap{A fresh ad hoc build changes cdhash $\to$ TCC/keychain ask again: the DR is the cdhash.}
  \trap{\ct{lipo}/\ct{install\_name\_tool}/\ct{strip} after signing breaks it — re-sign last.}
\end{itemize}

\hd{Remember}
\textbf{``Pages $\to$ CodeDirectory $\to$ cdhash $\to$ CMS $\to$ Team cert $\to$ Apple root — and the kernel re-checks each page as it faults in.''}
