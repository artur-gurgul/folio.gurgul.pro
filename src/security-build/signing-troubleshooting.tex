\sheettitle{Signing failures — symptom $\to$ check $\to$ fix}{security-build · folio}

\oneliner{Every signing error is a \textbf{mismatch between four things} that must agree —
the \textbf{identity} (certificate \emph{+ private key} in a reachable keychain), the
\textbf{profile} (App ID, certificates, entitlements, devices, expiry), the \textbf{signed
entitlements} and the \textbf{bundle} (every nested binary signed, nothing changed after). First
ask \emph{when} it fails — build, CI only, install, upload, launch — then \textbf{decode both
sides and diff them} instead of toggling Xcode settings.}

\hd{Example — decode both sides and diff}
\begin{lstlisting}[language=ShSheet]
unzip -q App.ipa && APP=Payload/App.app
security cms -D -i $APP/embedded.mobileprovision > prof.plist
/usr/libexec/PlistBuddy -c 'Print :Entitlements' prof.plist    # allowed
/usr/libexec/PlistBuddy -c 'Print :ProvisionedDevices' prof.plist
codesign -d --entitlements :- $APP                  # actually signed
codesign -dvvv $APP 2>&1 | grep -E 'Authority|TeamIdentifier'
security find-identity -v -p codesigning            # SHA-1 of your certs
xcodebuild -showBuildSettings | grep -E 'CODE_SIGN|PROVISIONING|TEAM'
codesign --verify --deep --strict -vvv $APP         # nested damage
\end{lstlisting}

\hd{Where things live}
\begin{itemize}
  \item Profiles: \textbf{Xcode 16+} \ct{\textasciitilde/Library/Developer/Xcode/UserData/Provisioning
        Profiles}; Xcode $\leq$ 15 \ct{\textasciitilde/Library/MobileDevice/Provisioning Profiles} —
        tools and CI scripts hard-coding the old path need updating.
  \item In the product: \ct{embedded.mobileprovision} (iOS), \ct{embedded.provisionprofile}
        (macOS). Keys: \ct{TeamIdentifier}, \ct{Entitlements}, \ct{DeveloperCertificates},
        \ct{ProvisionedDevices}, \ct{ExpirationDate}.
\end{itemize}

\hd{Automatic vs manual signing}
\begin{itemize}
  \item \textbf{Automatic} (\ct{CODE\_SIGN\_STYLE = Automatic}): Xcode creates certs, App IDs,
        ``Xcode Managed'' profiles, registers the connected device. On CI:
        \ct{xcodebuild -allowProvisioningUpdates} + an App Store Connect API key
        (\ct{-authenticationKey\{Path,ID,IssuerID\}}).
  \item \textbf{Manual}: \ct{CODE\_SIGN\_IDENTITY} + \ct{PROVISIONING\_PROFILE\_SPECIFIER} per
        target; deterministic — usual on CI with match.
  \item \textbf{Every target signs separately}: each app extension / watch app has its own
        App ID and profile; the host's profile does not cover them.
\end{itemize}

\hd{On the device}
\begin{itemize}
  \item iOS 16+: development-signed apps need \textbf{Developer Mode} (Settings › Privacy \&
        Security); TestFlight / App Store builds don't.
  \item Enterprise builds: the user must trust the developer (Settings › General › VPN \&
        Device Management) and the first launch verifies online\unverified.
  \item No debugger on a distribution build: no \ct{get-task-allow}.
\end{itemize}

\hd{Traps}
\begin{itemize}
  \trap{``Revoke and recreate the certificate'' — kills every other machine's key and CI;
        export the \ct{.p12} instead.}
  \trap{Capability works in Debug, fails in Release: only the \emph{development} profile was
        regenerated.}
  \trap{Toggling ``Automatically manage signing'' hides the real mismatch — diff first.}
  \trap{Anything that edits the bundle after signing (a script phase, \ct{strip},
        \ct{install\_name\_tool}) invalidates it — sign last.}
\end{itemize}

\hd{Remember}
\textbf{``When does it fail? Decode the profile, dump the entitlements, list the identities —
diff, regenerate, sign inside-out.''}
