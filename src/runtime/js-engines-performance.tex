\sheettitle{JS engines — JIT tiers, shapes, inline caches, GC}{runtime · folio}

\oneliner{An engine turns source into \textbf{bytecode}, \textbf{interprets} it while recording
\textbf{feedback} (maps, types, call targets) and compiles hot functions in \textbf{tiers} that
\textbf{speculate} on that feedback — a failed guard \textbf{deoptimises} to the bottom tier.
Objects share \textbf{hidden classes}, so an \textbf{inline cache} turns \ct{o.x} into one compare
and one load. Memory is a \textbf{tracing, generational GC}: what is reachable lives.}

\section{From source to machine code (V8)}
\begin{itemize}
  \item \textbf{Lazy parsing}: inner functions are only \emph{pre-parsed} and compiled on first
        call; \ct{(function()\{…\})} is assumed called and compiled eagerly. Chrome 136:
        \ct{//\# allFunctionsCalledOnLoad} atop a file compiles it all eagerly, off the main
        thread — 17 of 20 pages faster, $-$630\,ms foreground on average; ``use sparingly''.
  \item \textbf{Ignition}: register machine + accumulator; bytecode 25–50\,\% the size of the
        old baseline machine code (2016). Each function's \textbf{feedback vector} records the
        maps, types and call targets every site has seen — the input to every higher tier.
  \item \textbf{Sparkplug} (2021): one linear pass bytecode $\to$ machine code, no IR,
        interpreter-shaped frames, no optimisation; Speedometer +5–10\,\%.
  \item \textbf{Maglev} (2023): SSA + CFG, compiles $\sim$10$\times$ slower than Sparkplug and
        $\sim$10$\times$ faster than TurboFan; on in Node from 22 (V8 12.4).
  \item \textbf{TurboFan}: inlines (callee $\le$\,460 bytes of bytecode, 920 cumulative),
        removes checks, unboxes numbers. Its backend is \textbf{Turboshaft}, a CFG IR that halved
        compile time against Sea of Nodes (2025); the frontend is being replaced by Maglev —
        \ct{--turbolev} (Maglev + Turboshaft as the 4th tier) exists, off by default.
  \item \textbf{OSR} (on-stack replacement): a long loop tiers up mid-run (flags: OSR 500,
        Maglev OSR 100); a tier-up waits $\ge$\,500 invocations after the last IC change.
\end{itemize}

\section{Speculation and deoptimisation}
\begin{itemize}
  \item Optimised code guards each assumption (map check, ``is Smi'', bounds). \textbf{Eager}
        deopt: a guard fails, exit now. \textbf{Lazy}: an assumption the code depends on was
        broken elsewhere — the code is marked and exits when it next runs. The frame is
        rebuilt as an interpreter frame and execution continues there.
  \item \textbf{JSC}: an OSR exit returns to Baseline / LLInt; after $100 \cdot 2^R$ exits ($R$ =
        reoptimisations so far) the code is \textbf{jettisoned} and recompiled with the new
        profile. \textbf{Watchpoints} drop a check entirely: the runtime invalidates the code
        when the watched fact changes. Compile cost: DFG 4$\times$ Baseline, FTL 6$\times$ DFG.
  \item See it: \ct{node --trace-opt --trace-deopt}; \ct{--allow-natives-syntax} adds
        \ct{\%OptimizeFunctionOnNextCall}, \ct{\%GetOptimizationStatus}.
  \item \ct{--jitless} (V8 7.4) allocates no executable memory: Ignition only, regexps
        interpreted — for iOS, TVs, consoles. Cost (2019): Speedometer 2 $\sim$40\,\% slower, Web
        Tooling $\sim$80\,\%.
\end{itemize}

\section{Hidden classes}
\begin{itemize}
  \item Properties live \textbf{in-object} (fastest), in a \textbf{fast} out-of-object array
        (slot from the descriptor array), or in a \textbf{dictionary} — a per-object hash
        table, used once many properties are added and deleted.
  \item \textbf{Slack tracking}: a constructor's objects start with the expected properties
        + 8 spare in-object slots; after 7 constructions the size is fixed and spare slack cut.
  \item \textbf{Field representation} is in the map: a field of small ints is \emph{Smi}, one
        holding other numbers \emph{Double}. A double stored into a Smi field
        \textbf{deprecates} the map; objects migrate lazily on next access. React (2019):
        \ct{Object.preventExtensions} + a later Smi $\to$ Double change orphaned shapes (V8 7.4
        fixed it); init timestamps with \ct{NaN}, not \ct{0}.
\end{itemize}

\section{Smis and pointer compression}
\begin{itemize}
  \item Tagged slot: low bit \ct{0} = \textbf{Smi} (integer in the slot), \ct{1} = pointer.
        Other numbers are boxed \emph{HeapNumbers}; a Double field updates its box in place.
  \item \textbf{Pointer compression} (V8 8.0, Dec 2019; Chrome): slots are 32-bit offsets into a
        4\,GB cage, Smis 31-bit; V8 heap up to 43\,\% smaller.
  \item \textbf{Off in official Node builds}: the configure flag
        \ct{--experimental-enable-pointer-compression} caps the heap at 4\,GB and breaks the
        addon ABI — Node keeps 64-bit slots and 32-bit Smis.
  \item Node $\to$ V8: 22 $\to$ 12.4 · 24 (May 2025) $\to$ 13.6 · 25 (Oct 2025) $\to$ 14.1 ·
        26 (May 2026, LTS due Oct) $\to$ 14.6.
\end{itemize}

\section{Weak references}
\begin{itemize}
  \item \ct{WeakMap} / \ct{WeakSet} (ES2015): keys (objects, non-registered symbols) held
        weakly — the value lives only while its key does; not iterable. Per-object side tables.
  \item \ct{WeakRef} + \ct{FinalizationRegistry} (ES2021): \ct{deref()} may give
        \ct{undefined}; a target read in a job survives to that job's end; cleanup callbacks
        may run late or \textbf{never} — hints, not program logic.
\end{itemize}

\section{Finding leaks}
\begin{itemize}
  \item A leak is \textbf{unwanted reachability}: listeners never removed, live timers,
        unbounded \ct{Map} caches, globals, \textbf{detached DOM} held by JS, closure contexts.
        DevTools tells a \emph{leak} (grows) from \emph{bloat} (too big) and \emph{frequent GC}.
  \item \textbf{Heap snapshot}: shallow size (the object) vs \textbf{retained} size (freed with
        it); the \textbf{Retainers} path and distance from the root say who keeps it.
        Snapshot, repeat the action, snapshot, \textbf{Comparison} view; filter detached nodes.
  \item Node: \ct{--inspect} + DevTools, \ct{--heapsnapshot-signal=SIGUSR2},
        \ct{v8.writeHeapSnapshot()} — synchronous, blocks the event loop, needs $\sim$2$\times$
        the heap; \ct{v8.queryObjects(Ctor)} (22.0) counts live instances for leak tests.
\end{itemize}

\section{Traps}
\begin{itemize}
  \trap{``\ct{try/catch} blocks optimisation'' — true of Crankshaft, retired 2017; TurboFan
        optimises it.}
  \trap{Synthetic benchmarks: Warp lost on Octane and Kraken and won 20\,\% on Google Docs load;
        a cold loop times the interpreter.}
  \trap{\ct{delete}-churn objects end in dictionary mode — dynamic keys belong in a \ct{Map}.}
  \trap{One \ct{-0}, \ct{NaN} or hole in an int array changes its kind for good.}
\end{itemize}

\section{Remember}
\textbf{Same keys, same order, same types — and reachability, not use, keeps memory.}
