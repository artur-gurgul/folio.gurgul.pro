\sheettitle{StoreKit 2 · in-app purchases \& subscriptions}{ios-platform · folio}

\oneliner{A StoreKit 2 purchase ends in a \textbf{signed letter}, not a callback:
each \texttt{Transaction} is a \textbf{JWS} the App Store signs and StoreKit
checks \emph{on the device}, against the certificate chain packed inside it.
Your part is \textbf{verify $\to$ grant $\to$ \texttt{finish()}} — with an ear
open from launch (\texttt{Transaction.updates}) for all that is bought, renewed
or refunded while you are not looking.}

\begin{itemize}
  \item \textbf{2012}: on iOS $\le$ 5.1 an app asked Apple's server ``is this
        receipt valid?'' itself. A DNS redirect plus a user-installed CA put
        an impostor there that said yes, and generic receipts could be
        replayed. Fix: ask from \emph{your} server; iOS 6 closed it.
  \item \textbf{StoreKit 2 asks nobody}: the chain to Apple's root travels
        \emph{inside} each JWS, so the check runs offline, and
        \link{\texttt{deviceVerification}}{https://developer.apple.com/documentation/storekit/transaction/deviceverification}
        = SHA-384(nonce + this device's ID) ties it to one device.
  \item The old PKCS\#7/ASN.1 receipt file is deprecated: \texttt{Transaction}
        and \texttt{AppTransaction} (iOS 16, the app's own purchase) replace it.
\end{itemize}

\section{How it flows}
\begin{itemize}
  \item \textbf{Products live in the store}: \texttt{Product.products(for:)}
        answers an \emph{empty array, not an error}, when IDs or the Paid
        Apps agreement in App Store Connect are wrong.
  \item \textbf{Owning}:
        \link{\texttt{currentEntitlements}}{https://developer.apple.com/documentation/storekit/transaction/currententitlements}
        = latest transaction per non-consumable, live subscription
        (subscribed or in grace) and non-renewing sub; refunded ones vanish.
  \item \textbf{One plan per subscription group}: upgrade bites now,
        downgrade at the next renewal.
  \item \textbf{Refunds}: asked for in-app since iOS 15
        (\texttt{beginRefundRequest}). Apple sends \texttt{CONSUMPTION\_REQUEST}
        and weighs your ``how much was used'' if it comes within
        \link{12 hours}{https://developer.apple.com/documentation/appstoreserverapi/send-consumption-information};
        then \texttt{REFUND} and a \texttt{revocationDate}.
  \item \textbf{Tests}: a \link{\texttt{.storekit} file}{https://developer.apple.com/documentation/xcode/setting-up-storekit-testing-in-xcode}
        (2020) runs offline; the sandbox is real servers on fast time.
        \link{App Review buys in the sandbox}{https://developer.apple.com/library/archive/technotes/tn2413/_index.html}
        with your \emph{production} build: old servers retried on status
        21007, a JWS just says \texttt{environment}.
\end{itemize}

\section{Example: both roads, one handler}
\begin{lstlisting}[language=SwiftSheet]
// App init: one listener for the app's lifetime
let ear = Task.detached {
  for await r in Transaction.updates { await handle(r) } }
func buy(_ p: Product) async throws {
  if case .success(let r) = try await p.purchase() {
    await handle(r) }       // .pending -> arrives on updates
}
func handle(_ r: VerificationResult<Transaction>) async {
  guard case .verified(let t) = r else { return } // reject
  await grant(t)            // durable first ...
  await t.finish()          // ... then "delivered"
}
\end{lstlisting}

\begin{itemize}
  \item \link{Grace}{https://developer.apple.com/help/app-store-connect/manage-subscriptions/enable-billing-grace-period-for-auto-renewable-subscriptions}
        lasts 3, 16 or 28 days (weekly: 3 or 6), the sub still in
        \texttt{currentEntitlements}; in billing retry it drops out.
  \item Grace is money too: recovered in it, the \emph{days of paid service}
        never break — a year of them in one group lifts your share from
        \link{70\% to 85\%}{https://developer.apple.com/help/app-store-connect/manage-subscriptions/offer-auto-renewable-subscriptions/}.
        Back within 60 days the count goes on; later, it restarts.
\end{itemize}

\section{Traps}
\begin{itemize}
  \trap{Trusting \texttt{.unverified} — \emph{the} StoreKit security bug.}
  \trap{No \texttt{finish()} $\to$ double grants; finishing \emph{before}
        recording $\to$ a lost purchase.}
  \trap{No \texttt{updates} listener from launch $\to$ missed renewals, refunds, approvals.}
  \trap{Counting coins in \texttt{currentEntitlements} — consumables never
        appear there. Coins are your own ledger.}
  \trap{Granting on \texttt{.pending}. Trusting sandbox timing.}
  \trap{\texttt{AppStore.sync()} at launch — a sign-in prompt. Entitlements
        sync by themselves; \texttt{sync()} is for the Restore button.}
  \trap{Booking revenue from the JWS \texttt{price} — App Store Connect
        reports are the record.}
\end{itemize}
