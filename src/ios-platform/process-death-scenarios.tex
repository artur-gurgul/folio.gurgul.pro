\sheettitle{Process death — ``the OS killed the app mid-checkout''}{ios-platform · folio}

\oneliner{A backgrounded app is \textbf{suspended}, and a suspended app can be
\textbf{killed without any callback} (iOS jetsam, Android low-memory killer). When
the user comes back it is a \textbf{cold launch}: everything in \textbf{memory is gone},
everything on \textbf{disk / Keychain / restoration data survives} — and the
\textbf{server may already have done the payment}. So persist the screen \emph{and}
the draft before leaving, and make the operation \textbf{idempotent} so resuming can
ask ``did it happen?'' instead of doing it twice.}

\section{Ways an app dies}
{\footnotesize\setlength{\tabcolsep}{3pt}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{20mm}>{\raggedright\arraybackslash}p{29mm}>{\raggedright\arraybackslash}p{26mm}@{}}
\toprule
\textbf{kill} & \textbf{callback?} & \textbf{restore?}\\ \midrule
iOS jetsam (suspended) & none; \ct{applicationWillTerminate} only if running in bg & yes: restoration data kept\\
iOS watchdog / crash & none & crash in restore $\to$ data discarded\\
user swipes app away & none reliable & \textbf{no} — user meant ``quit''\\
Android process death (LMK) & none; \ct{onSaveInstanceState} ran at \ct{onStop} & yes: task + Bundles\\
Android config change & \ct{onDestroy} + recreate & VM survives (not death)\\
reboot / OS / app update & none & disk only\\
\bottomrule
\end{tabular}}
\begin{itemize}
  \item \textbf{iOS}: the system relaunches into the saved scene; you rebuild it
        from \ct{stateRestorationActivity} / \ct{@SceneStorage} (small UI state:
        ids, step, tab) + the draft on disk. Save on \ct{sceneDidEnterBackground},
        not in \ct{willTerminate}.
  \item \textbf{Android}: the task and back stack come back; the \emph{top}
        Activity is recreated from its Bundle and a \textbf{new} process —
        \ct{Application.onCreate} runs again, every singleton and static is fresh.
        \ct{SavedStateHandle} / \ct{rememberSaveable} hold ids; big data goes to
        disk (Bundle $\approx$ 1 MB Binder limit).
  \item \textbf{React Native}: the JS VM is gone; the app boots JS from scratch at
        the initial route. Persist navigation state (React Navigation
        \ct{initialState} + \ct{onStateChange}) and drafts yourself
        (AsyncStorage / MMKV; secrets in Keychain/Keystore). On Android,
        \textbf{react-native-screens} discards the restored fragment state
        (\ct{RNScreensFragmentFactory}) to avoid crashes — so native restore
        will not bring your screens back.
\end{itemize}

\section{Test it — on purpose}
\begin{itemize}
  \item \textbf{iOS}: background the app, then \emph{Stop} in Xcode (or
        \ct{xcrun simctl terminate booted com.example.app}), relaunch.
        Simulator \emph{Debug $\to$ Simulate Memory Warning} tests
        \emph{warnings}, not death. Swipe-away is \emph{not} the test.
  \item \textbf{Android}: \ct{adb shell am kill com.example.app} while in the
        background = real process death; Developer options \emph{Don't keep
        activities} only destroys Activities; \emph{Background process limit:
        none} for soak testing.
  \item Automate one UI test: fill the form, kill, relaunch, assert the draft.
\end{itemize}

\section{Design checklist — a death-proof flow}
\begin{enumerate}
  \item Every screen can be rebuilt from \textbf{route + ids} — no object handed
        over in memory that exists nowhere else.
  \item Drafts persisted on change (debounced), \emph{before} leaving the app.
  \item Side-effecting calls carry an idempotency key; the server has a
        \textbf{status endpoint} for it.
  \item Session state re-hydrates lazily (token from Keychain, user from cache)
        — never ``set by the login screen''.
  \item Restored ids validated; missing $\to$ a sane fallback screen.
  \item Drafts cleared on success, cancel and logout (privacy).
\end{enumerate}

\section{Example — a checkout that survives}
\begin{lstlisting}[language=SwiftSheet]
struct CheckoutDraft: Codable {
  var cartID: String, step: Int
  var payKey: UUID?          // set once, at "Pay"
}
@MainActor final class Checkout {
  var draft: CheckoutDraft { didSet { store.save(draft) } }
  func pay() async throws {  // key saved BEFORE the call
    let key = draft.payKey ?? UUID(); draft.payKey = key
    try await api.pay(draft.cartID, idempotencyKey: key)
  }
  func resume() async throws { // on cold launch
    guard let key = draft.payKey else { return }
    switch try await api.paymentStatus(key) {
    case .paid: route(.receipt); store.clear()
    case .notFound, .failed: route(.pay)  // safe to retry
    case .pending: route(.waiting) }
  } }
\end{lstlisting}

\section{Payments and purchases}
\begin{itemize}
  \item \textbf{Idempotency key}: client makes one UUID per \emph{intent}, persists
        it with the draft, sends it on every retry (\ct{Idempotency-Key} on
        POST/PATCH); the server stores the result per key and replays it. On
        resume: \textbf{query status}, never blindly re-POST.
  \item Server truth wins: order state comes from the server / webhook, not
        from ``the app saw 200''. Redirect flows (3-D Secure, bank app) return
        via a universal link into a possibly \emph{cold} app — the route must
        work from zero.
  \item \textbf{StoreKit 2}: a purchase interrupted by a kill is re-delivered
        through \ct{Transaction.updates} (listen from launch) until you
        \ct{finish()} it — grant content first, then finish.
\end{itemize}

\section{Traps}
\begin{itemize}
  \trap{Relying on \ct{applicationWillTerminate} / \ct{onDestroy} — not called on
        a system kill of a suspended app.}
  \trap{Restoring into a screen whose data is gone — validate ids, fall back.}
  \trap{Relaunched in the background before first unlock: \ct{.complete} files and
        \ct{WhenUnlocked} Keychain items are unreadable.}
  \trap{Persisting RN nav state that crashes on restore — the user is stuck;
        reset it from an error boundary.}
  \trap{Android: a singleton filled by the splash/login screen is \ct{null} when
        the process is restored straight onto screen 3 — classic NPE.}
\end{itemize}

\section{Remember}
\textbf{Memory dies, disk lives, the server remembers.} Save before you send; ask
before you retry.
