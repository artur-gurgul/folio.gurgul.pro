\sheettitle{xcodebuild, simctl \& friends — Xcode from the command line}{cicd · folio}

\oneliner{\ct{xcodebuild} runs one \textbf{action} of a \textbf{scheme} against a \textbf{destination};
\ct{archive} + \ct{-exportArchive} with an \textbf{ExportOptions.plist} make the shippable \ct{.ipa};
test results land in an \ct{.xcresult} read with \ct{xcresulttool}. \ct{xcrun simctl} scripts
simulators, \ct{devicectl} real devices, and \ct{xcode-select} / \ct{DEVELOPER\_DIR} decide
\textbf{which Xcode} answers. Xcode Cloud runs the same \ct{xcodebuild}.}

\hd{Actions}
\ct{build} (default) · \ct{build-for-testing} (+ \ct{.xctestrun}) · \ct{test} ·
\ct{test-without-building} · \ct{archive} · \ct{analyze} · \ct{docbuild} · \ct{clean}; they chain
(\ct{clean build}). \ct{build-for-testing}, \ct{test}, \ct{archive}, \ct{analyze} need \ct{-scheme}.
\textbf{Discover}: \ct{-list -json}, \ct{-showdestinations}, \ct{-showTestPlans},
\ct{-showBuildSettings}. \ct{-showBuildTimingSummary} times each command; \ct{-quiet} = warnings and
errors only.

\hd{Choosing, repeating and timing tests}
{\scriptsize\setlength{\tabcolsep}{2pt}
\begin{tabular}{@{}L{43mm}L{34mm}@{}}
\toprule
\ct{-testPlan P} · \ct{-only-test-configuration C} & plan name without extension \\
\ct{-only-testing T/C/m} · \ct{-skip-testing …} & \ct{@file}: one id a line; \emph{only} wins \\
\ct{-enumerate-tests} · \ct{…-format json} & list, don't run; needs \ct{-destination} \\
\ct{-test-iterations N} & N runs — or the cap for: \\
\ct{-retry-tests-on-failure} & until a pass, ≤3: a flake goes green \\
\ct{-run-tests-until-failure} & until a fail, ≤100: finds flakes \\
\ct{-test-repetition-relaunch-enabled YES} & fresh process per repetition \\
\ct{-test-timeouts-enabled YES} & + per-test time-allowance flags \\
\ct{-collect-test-diagnostics on-failure} & sysdiagnoses, log archives \\
\ct{-enableCodeCoverage YES} · \ct{-testLanguage} & override scheme / test plan \\
\bottomrule
\end{tabular}}\par
\ct{TEST\_RUNNER\_Foo=Bar} $\rightarrow$ \ct{Foo=Bar} in the runner. Xcode 26+: \ct{.xctestrun} keeps
\emph{disabled} plan configurations (\ct{-only-test-configuration}).

\hd{Traps}
\begin{itemize}
  \trap{\ct{xcodebuild … | xcbeautify} without \ct{set -o pipefail}: the pipeline returns the
        formatter's status — a red build reports green.}
  \trap{No \ct{OS=} means \ct{latest}: a new runner image silently moves the iOS version — pin
        \ct{OS=} or \ct{id=}.}
  \trap{Exit codes (sysexits): \textbf{70 = build or test failed}; 64 usage, 66 no input, 74 I/O.}
\end{itemize}

\hd{ExportOptions.plist — what \ct{-exportArchive} reads}
{\scriptsize\setlength{\tabcolsep}{2pt}
\begin{tabular}{@{}L{20mm}L{57mm}@{}}
\toprule
\ct{method} & \ct{app-store-connect} · \ct{release-testing} (ad hoc) · \ct{enterprise} · \ct{debugging}
  (default) · \ct{developer-id} · \ct{mac-application} · \ct{validation}; \ct{app-store}, \ct{ad-hoc},
  \ct{development} are deprecated \\
\ct{destination} & \ct{export} (local file) or \ct{upload} (to App Store Connect) \\
\ct{manageAppVersion}\newline\ct{AndBuildNumber} & Xcode rewrites the build number of everything in the
  archive — turn off when CI owns the number \\
\ct{testFlightInternal}\newline\ct{TestingOnly} & team-only TestFlight; the build can never be submitted \\
\ct{signingStyle} \ct{teamID} & \ct{manual} needs \ct{provisioningProfiles} \{bundle id $\rightarrow$
  profile\}; \ct{uploadSymbols} for symbolicated crashes \\
\bottomrule

\textbf{Signing on a runner}: \ct{-allowProvisioningUpdates} fetches profiles (and creates
certificates for automatic signing) through an account in Xcode's Accounts pane — or an App Store
Connect API key: \ct{-authenticationKeyPath}, \ct{-authenticationKeyID},
\ct{-authenticationKeyIssuerID} (also for uploads, Xcode 15+). \ct{altool} looks for
\ct{AuthKey\_<id>.p8} in \ct{./private\_keys}, \ct{\textasciitilde/.appstoreconnect/private\_keys} and
two more.

\hd{Swift packages, plugins, macros on CI}
\begin{itemize}
  \item Commit \ct{Package.resolved} (in \ct{App.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/});
        \ct{-disableAutomaticPackageResolution} makes CI use exactly it.
  \item Checkouts land in \ct{DerivedData/SourcePackages} unless \ct{-clonedSourcePackagesDirPath P}:
        pin it to cache them.
  \item Private repos: SSH URLs + \ct{known\_hosts}; \ct{-scmProvider system} uses the Mac's git
        config (URL rewrites, proxies, SSH); registries: \ct{-packageAuthorizationProvider netrc}.
  \item Headless, nobody clicks ``Trust \& Enable'': \ct{-skipPackagePluginValidation},
        \ct{-skipMacroValidation} — ``can be a security risk''.
\end{itemize}

\hd{Which Xcode, which components}
\ct{sudo xcode-select -s /Applications/Xcode\_27.app}: every user, persistent;
\ct{DEVELOPER\_DIR=…/Xcode\_27.app}: this process only. \ct{/usr/bin/xcodebuild}, \ct{git}, \ct{swift}
are shims through it; \ct{xcrun \dd find T} resolves a tool. \ct{xcodes install 27.0}; pin the
version in \ct{.xcode-version}. Fresh Mac: \ct{-runFirstLaunch} (components + licence) ·
\ct{-downloadPlatform iOS -exportPath D [-buildVersion 26.4]} once, \ct{-importPlatform D/….dmg} on
each Mac · \ct{-downloadComponent metalToolchain}.

\hd{Xcode Cloud}
From \ct{ci\_scripts/} beside the project it runs only \ct{ci\_post\_clone.sh}, \ct{ci\_pre\_xcodebuild.sh},
\ct{ci\_post\_xcodebuild.sh} (runs \emph{even if xcodebuild failed}). No shebang $\rightarrow$
\ct{zsh file}; no \ct{sudo}; created files are deleted; non-zero exit fails the build. Scripts read
\ct{CI\_*} variables (\ct{CI\_PULL\_REQUEST\_NUMBER} …); secret ones print as \ct{****}. 25 compute
h/month come with the Developer Program; plans add 100, 250, 1,000\,h.
