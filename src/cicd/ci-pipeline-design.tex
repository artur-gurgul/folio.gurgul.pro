\sheettitle{CI pipeline design — fast feedback, safe merges, one artifact}{cicd · folio}

\oneliner{A pipeline is a \textbf{DAG of gates} ordered so the \textbf{cheapest check most likely to fail runs first};
its \textbf{critical path} is the developer's wait. Speed comes from \textbf{content-keyed caches} only CI writes and
\textbf{duration-balanced shards}; \ct{main} stays green because a \textbf{merge queue} tests the merge
\emph{before} it lands; the release \textbf{artifact is built once}, attested, and \textbf{promoted}; the whole
system is judged by the \textbf{DORA} metrics — not by how many jobs it has.}

\hd{Order and speed}
\begin{itemize}
  \item \textbf{Cheap and likely-to-fail first}: lint (seconds) $\rightarrow$ compile $\rightarrow$ unit $\rightarrow$
        snapshot $\rightarrow$ UI/E2E. Commit stage within XP's \textbf{ten-minute build}; slow suites in a
        second stage that ``might take a couple of hours'' (Fowler, rev.\ 2024).
  \item \textbf{Critical path, not CPU}: wall clock = the longest chain. Build \textbf{once}, fan out:
        \ct{build-for-testing -testProductsPath T.xctestproducts} $\rightarrow$ artifact (jobs share no disk)
        $\rightarrow$ \ct{test-without-building} per shard.
  \item \textbf{Skip what cannot change}: path filters (see the trap); Nx \ct{affected} (git diff + project
        graph); Tuist selective testing (hash per test target + its dependencies — target, not test, granularity).
  \item \textbf{Cancel superseded PR runs}, never deploys: GitHub \ct{concurrency} (+ \ct{cancel-in-progress})
        · GitLab \ct{interruptible} · Buildkite \emph{Cancel Intermediate Builds} · Xcode Cloud
        \emph{Auto-cancel Builds} (on by default).
\end{itemize}

\textbf{GitHub restore}: exact key $\rightarrow$ key as prefix $\rightarrow$ each \ct{restore-keys} prefix, newest wins.
Entries are \textbf{immutable} (new lockfile = new key), 10\,GB/repo by default, gone after 7 days unused. Visible: own
branch, default branch, PR base; PR caches sit on \ct{refs/pull/…/merge}. \textbf{GitLab}:
\ct{cache:key:files} ($\leq$ 10 files $\rightarrow$ SHA of contents), \ct{fallback\_keys}, \ct{policy: pull} for readers.
\textbf{Poisoning} = an untrusted job writes what a trusted job restores and runs. One rule everywhere:
\textbf{only trusted CI writes} — GitHub makes \ct{pull\_request\_target}/\ct{workflow\_run} read-only; Bazel:
\ct{\dd{}remote\_upload\_local\_results=false} off CI; Gradle: \ct{isPush = isCiServer}.

\hd{Keeping main green}
\begin{itemize}
  \item \textbf{Not Rocket Science Rule} (Hoare 2014; the \emph{bors} bot): automatically keep a
        repository that never fails its tests — test the \emph{merge}, then advance \ct{main}:
        two PRs green against an old \ct{main} can be red together.
  \item \textbf{GitHub merge queue}: workflows need the \ct{merge\_group} trigger, else checks never report. Branch
        \ct{gh-readonly-queue/main/…} = main + PRs ahead + this PR; 1–100 groups at once, 1–100 PRs per merge.
        Failure or timeout $\rightarrow$ PR out, groups behind rebuilt; jumping rebuilds all in flight.
  \item \textbf{GitLab merge trains} (Premium+): $\leq$ \textbf{20} pipelines in parallel by default; a failure drops
        the MR and restarts all behind it.
  \item \textbf{Required checks} match \textbf{by name}: renaming a job silently un-requires it.
  \item \textbf{Trunk} (DORA): $\leq$ 3 active branches, merged daily, no freezes. Fowler: commit to mainline
        every day; fix a red build first — usually by \textbf{revert}.
\end{itemize}

\hd{Build once, promote}
The first stage ``will do any compilation and provide binaries for later stages'' (Fowler 2013, after
Humble \& Farley); a rebuild per environment ships a binary nobody tested.
\begin{itemize}
  \item \textbf{App Store}: each upload needs a new \textbf{build string} (\ct{CFBundleVersion} ``uniquely
        identifies the build''); a version takes \textbf{one} build, swappable until submitted — the TestFlight
        build \emph{is} the reviewed one. Since \textbf{28 Apr 2026}: Xcode 26+ and a 26 SDK.
  \item \textbf{Google Play}: \ct{versionCode} must grow, never reused, $\leq$ 2\,100\,000\,000. Promote via
        ``Add from library'' or \ct{Edits.tracks: update} with the existing \ct{versionCode}; staged = \ct{inProgress}
        + \ct{userFraction} (not on a first release). You sign with the \textbf{upload key}; Play re-signs with
        the app signing key (required for apps created since Aug 2021).
\end{itemize}

\hd{Traps}
\begin{itemize}
  \trap{Required check + path filter: a skipped \emph{workflow} stays ``Pending'' forever and blocks the PR; a job
        skipped by \ct{if:} reports Success. Fix: one always-run gate job (\ct{if: always()}) that \ct{needs:} the rest.}
  \trap{Secrets mask only verbatim: a base64 or derived copy prints in clear — register it as a secret too.}
\end{itemize}

\hd{Remember}
\textbf{``Cheap first, shard by time, cache by content, queue the merge, build once, attest, measure DORA.''}
