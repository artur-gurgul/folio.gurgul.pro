\sheettitle{Data transfer optimisation — fewer bytes, fewer times}{networking · folio}

\oneliner{The cheapest byte is the one \textbf{never sent}. Work down the ladder: \textbf{don't send}
(cache, 304), \textbf{send less} (fields, pages, deltas), \textbf{encode smaller} (binary, no names),
\textbf{compress} (brotli / zstd / gzip), \textbf{right-size media} (pixels you display, modern formats),
and \textbf{adapt} to the link (HLS). On mobile, fewer \emph{requests} matter as much as fewer bytes:
every one costs RTTs and radio time.}

\hd{Compression}
\begin{itemize}
  \item \textbf{gzip} (DEFLATE + 10-byte header + 8-byte CRC/size trailer, RFC 1952): everywhere.
        \textbf{Brotli} (\ct{br}, RFC 7932): built-in static dictionary of web text — best on text, slow
        at max level (pre-compress static assets). \textbf{zstd} (RFC 8878): fast, trainable dictionaries.
  \item \textbf{Negotiation}: \ct{Accept-Encoding} $\to$ \ct{Content-Encoding} + \ct{Vary:
        Accept-Encoding}. URLSession decodes gzip, deflate, br itself; zstd came to the
        \emph{system networking stack} in iOS 26.3 (WebKit, for Safari) — log your app's
        \ct{Accept-Encoding} before relying on it.
  \item \textbf{Request bodies are never compressed for you}: compress, set \ct{Content-Encoding},
        and make sure the server accepts it. Apple's \ct{Compression} offers zlib, LZFSE, LZ4, LZMA,
        brotli — \ct{COMPRESSION\_ZLIB} is \textbf{raw DEFLATE} (no gzip/zlib header).
  \item Skip already-compressed data (JPEG, HEIC, MP4, zip) and tiny bodies (framing $>$ saving).
\end{itemize}

\hd{Send less, encode smaller}
\begin{itemize}
  \item \textbf{Field selection}: \ct{?fields=id,name}, sparse fieldsets, or GraphQL — list endpoints
        return \emph{summaries}, detail endpoints the rest.
  \item \textbf{Pagination}: cursor-based (\ct{after=<opaque>}, stable under inserts) beats offset;
        page size tuned to one screen + a prefetch margin.
  \item \textbf{Delta sync}: \ct{since=<syncToken>} returns only changes + tombstones; edits as
        \ct{PATCH} with JSON Merge Patch (RFC 7396) or JSON Patch (RFC 6902).
  \item \textbf{Binary}: one record is 54 B as JSON, \textbf{16 B} as protobuf (no names, no text
        digits); gzip narrows the gap on big payloads only.
  \item \textbf{Batching}: many small writes in one request (analytics, receipts) — fewer radio wakes,
        fewer server round trips. HTTP/2 makes requests cheap, not free.
\end{itemize}

\hd{Example — right-sized image + measuring the wire}
\begin{lstlisting}[language=SwiftSheet]
let px = Int(side * traitCollection.displayScale)  // 100 pt @3x = 300 px
var c = URLComponents(string: "https://img.example.com/p/42")!
c.queryItems = [URLQueryItem(name: "w", value: "\(px)")]  // CDN resizes
var req = URLRequest(url: c.url!)
req.setValue("image/avif,image/webp,image/*;q=0.8",
             forHTTPHeaderField: "Accept")   // CDN negotiates + Vary: Accept

// URLSessionTaskDelegate, didFinishCollecting metrics:
let t = metrics.transactionMetrics.last!
let wire = t.countOfResponseBodyBytesReceived       // compressed
let body = t.countOfResponseBodyBytesAfterDecoding  // after br/gzip
log("ratio", Double(body) / Double(max(wire, 1)))
\end{lstlisting}

Pure serialisation, before RTTs and slow start. At 100\,Mbit/s a 50\,KB page is RTT-bound — so

\hd{Prefetch and cache}
Prefetch the \emph{next} page while the radio is up (\ct{UICollectionViewDataSourcePrefetching},
cancel in \ct{cancelPrefetchingForItemsAt}). Hashed URLs + \ct{immutable}; the rest \ct{ETag} $\to$ 304.
Low Data Mode: no prefetch, lower variants.

\hd{Traps}
\begin{itemize}
  \trap{Downloading a 4000-px photo for a 100-pt cell: bytes, decode time and memory all wasted.}
  \trap{``HTTP/2 made batching pointless'' — headers are cheap now; radio wakes and server work are not.}
  \trap{Gzipping a request with \ct{COMPRESSION\_ZLIB} and labelling it \ct{gzip} — it is raw DEFLATE.}
\end{itemize}

\hd{Remember}
\textbf{``Don't send, send less, encode small, compress, size to pixels, adapt.''}
