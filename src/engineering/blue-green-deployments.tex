\sheettitle{Blue/green deployments}{engineering · folio}

\oneliner{Run \textbf{two identical production environments}: \textbf{blue} serves users, the new version is
deployed to idle \textbf{green}, tested there with no user traffic, then \textbf{one switch} (load balancer,
Service selector, DNS, symlink) moves \emph{all} traffic at once. Blue stays up, warm, as the
\textbf{instant rollback} — but only the \emph{stateless} tier is doubled: the database, queues and
side effects are shared, so rollback is instant only if v1 still works with what v2 wrote.}

\hd{How it works}
\begin{itemize}
  \item \textbf{Two full stacks} behind one entry point; the idle one is the \emph{target}. Deploy to green,
        run migrations that are \textbf{backward compatible} (expand only), wait for readiness.
  \item \textbf{Verify before users}: smoke tests through a private route (preview Service, test listener,
        header rule), then \textbf{warm-up}: fill caches, JIT, connection pools; scale green to \emph{blue's}
        size, not the autoscaler's minimum — a cold green at 100\,\% is an outage.
  \item \textbf{Switch} in one step. Existing TCP / HTTP/2 / WebSocket connections are \emph{not} moved:
        they \textbf{drain} on blue (deregistration delay, preStop + \ct{terminationGracePeriodSeconds}, 30\,s
        default in K8s). Endpoints are removed \emph{concurrently} with SIGTERM — sleep in \ct{preStop}.
  \item \textbf{Bake}: watch errors/latency on green; blue idle for the rollback window, then retired or
        reused as the next green. \textbf{Cost}: 2$\times$ the stateless tier for that window.
\end{itemize}

\hd{Implementations}
\begin{itemize}
  \item \textbf{Argo Rollouts} \ct{blueGreen}: \ct{activeService} + \ct{previewService}; controller injects the
        ReplicaSet hash into Service selectors. \ct{autoPromotionEnabled} (default true),
        \ct{prePromotionAnalysis} gates the switch, \ct{postPromotionAnalysis} failure switches back,
        \ct{scaleDownDelaySeconds} (default 30) keeps blue.
  \item \textbf{AWS}: CodeDeploy ECS blue/green — two target groups, prod + optional test listener,
        \ct{ECSAllAtOnce}, \ct{ECSCanary10Percent5Minutes}, \ct{ECSLinear10PercentEvery1Minutes} (NLB:
        all-at-once only); EC2 = replacement ASG; Lambda = alias weights. Since July 2025 \textbf{ECS native}
        \ct{BLUE\_GREEN} strategy: \ct{bakeTimeInMinutes}, lifecycle hooks, alarms.
\end{itemize}

\hd{Mobile — you cannot blue/green a binary}
The installed app is the ``blue'' you can't switch off, and the stores have no rollback. Equivalents:
B/G the \textbf{backend} behind the app; ship \emph{both} code paths and flip a \textbf{remote flag}
(in-app B/G); route by an \ct{App-Version} header; \textbf{min-version} gate as the last resort; RN:
point an EAS Update channel at another branch (JS only).

\hd{Example — Kubernetes: the Service is the switch}
\begin{lstlisting}[language=YAMLSheet]
apiVersion: v1
kind: Service                 # the ONLY thing that flips
metadata: { name: api }
spec:
  selector: { app: api, color: blue }    # -> green
  ports: [{ port: 80, targetPort: 8080 }]
# 1 kubectl apply -f api-green.yaml      # Deployment color: green
# 2 kubectl rollout status deploy/api-green
# 3 smoke: curl -f http://api-preview/healthz  (preview Svc -> green)
# 4 switch:
#   kubectl patch svc api -p '{"spec":{"selector":{"color":"green"}}}'
# 5 rollback = same patch with "blue" (blue pods still running)
# 6 after bake: kubectl scale deploy/api-blue --replicas=0
\end{lstlisting}

\hd{Rollback — instant, with limits}
\begin{itemize}
  \item \textbf{Schema}: a v2 migration that drops/renames breaks v1 on rollback $\Rightarrow$ only
        \emph{expand} before the switch, \emph{contract} after the bake.
  \item \textbf{Data written by v2} (new format, cache entries, queue messages): v1 must read or ignore it.
  \item \textbf{Side effects} are not undone: emails, pushes, charges, webhooks — make them idempotent.
  \item \textbf{Workers} don't follow the LB: both colours consume queues and run cron $\Rightarrow$
        double execution. Gate them by colour/flag; scale blue's to 0.
  \item \textbf{Sessions} in memory are lost: shared store or a signed token.
\end{itemize}

\hd{Traps}
\begin{itemize}
  \trap{``Rollback is instant'' — code yes; schema, data, emails no.}
  \trap{Blue \emph{and} green workers both eating the queue / cron.}
  \trap{Cold green: 100\,\% onto empty caches, min-size autoscaler.}
  \trap{DNS switch called ``instant'' — TTLs and caching resolvers.}
\end{itemize}

\hd{Remember}
\textbf{Two stacks, one switch, one shared database — expand before, contract after.}
