\sheettitle{Debugging Swift Concurrency — pool, actors, executors}{debugging · folio}

\oneliner{Tasks run on the \textbf{cooperative thread pool} (as many threads as CPU cores,
\textbf{never grows}) or on the \textbf{main actor}'s main thread. The runtime's contract is
\textbf{forward progress}: \texttt{await} suspends and frees the thread; a \emph{blocked} thread
is simply lost. Four failures follow — \textbf{main-actor blocking} (hang), \textbf{actor
contention} and \textbf{pool exhaustion} (parallel code turned serial, or deadlock),
\textbf{continuation misuse} (leak or crash). Concurrency instruments show task / actor /
executor \emph{state}; System Trace shows \emph{why} a thread is not running.}

\section{How the runtime behaves}
\begin{itemize}
  \item \textbf{Pool width = CPU cores}, fixed. A GCD concurrent queue adds a thread when one
        blocks; the pool does not.
  \item \textbf{Safe}: \texttt{await}; a lock around a tight, known critical section
        (\texttt{Mutex}, \texttt{os\_unfair\_lock}, \texttt{NSLock}). \textbf{Unsafe}: semaphores,
        condition variables, \texttt{DispatchGroup.wait()}, blocking file / network I/O — they hide
        the dependency from the runtime. All pool threads waiting on pool work = \textbf{deadlock}.
  \item \texttt{LIBDISPATCH\_COOPERATIVE\_POOL\_STRICT=1} (scheme $\to$ Run $\to$ Arguments):
        pool width \textbf{1 per QoS}, so a hidden blocking wait deadlocks \emph{now}, in dev.
  \item \textbf{Main actor} = the main thread. Each hop main $\leftrightarrow$ actor is a context
        switch: hand over arrays, not one item per hop.
  \item \textbf{Where code runs (Swift 6.2)}: new app projects in Xcode 26 default to
        \texttt{MainActor} isolation; \emph{Approachable Concurrency} turns on SE-0461, so a
        \texttt{nonisolated async} func runs on the \emph{caller's} actor; \texttt{@concurrent}
        always switches off it.
  \item \textbf{Priority}: awaiting a task escalates it and its children, never lowered (SE-0462);
        an actor may run a higher-priority job first. A semaphore or continuation hides who will
        resume you — no escalation (6.2: \texttt{withTaskPriorityEscalationHandler}).
        \textbf{Thread Performance Checker} (TPC; on for Run, iOS + macOS) flags such waits:
        \texttt{dispatch\_semaphore\_wait} / \texttt{dispatch\_group\_wait} cannot pass priority on.
        Mute known ones: \texttt{PERFC\_SUPPRESSION\_FILE}.
\end{itemize}

\section{Example — suspend, don't block}
\begin{lstlisting}[language=SwiftSheet]
// BAD: parks a pool thread until the callback fires
func thumb(_ u: URL) async -> UIImage? {
  let sem = DispatchSemaphore(value: 0); var img: UIImage?
  legacyLoad(u) { img = $0; sem.signal() }
  sem.wait(); return img }          // Blocked, thread lost
// GOOD: the task suspends; resume exactly once
func thumb(_ u: URL) async -> UIImage? {
  await withCheckedContinuation { c in
    legacyLoad(u) { c.resume(returning: $0) } } }
// CPU work off the caller's actor (6.2); a named task
@concurrent func decode(_ d: Data) async -> UIImage? {
  UIImage(data: d) }
Task(name: "thumb") { await show(thumb(url)) }
\end{lstlisting}

\section{The runtime's own messages}
\begin{lstlisting}[style=plain]
SWIFT TASK CONTINUATION MISUSE: load() leaked its
  continuation without resuming it.   // task waits forever
SWIFT TASK CONTINUATION MISUSE: load() tried to resume
  its continuation more than once, returning ... // fatalError
BUG IN CLIENT OF LIBDISPATCH: Assertion failed: Block was
  expected to execute on queue [com.apple.main-thread (0x...)]
\end{lstlisting}
Lines 1–2: \texttt{CheckedContinuation} only — \texttt{UnsafeContinuation} (same API) checks nothing.
Line 3 = Swift 6's \textbf{dynamic isolation check} (SE-0423, 6.0): synchronous isolated code
reachable from unchecked callers (\texttt{@objc} thunks, \texttt{@preconcurrency} witnesses,
closures given to unchecked APIs, calls into Swift 6 modules) gets a compiler-inserted executor
check (main actor: \texttt{dispatch\_assert\_queue}) and \textbf{crashes instead of racing}.
Old-SDK apps only log ``data race detected''; opt-out: \texttt{-disable-dynamic-actor-isolation}.
\texttt{0x400000000000bad0} in a crash (ObjC, Xcode 26) = a racing \texttt{nonatomic} property:
synthesized setters store that value briefly.

\section{Traps}
\begin{itemize}
  \trap{``Spawn more tasks'' — the pool never grows.}
  \trap{\texttt{Task.yield()} is no starvation fix: the highest-priority task resumes at once.}
  \trap{\emph{Blocked} $\neq$ hang: an idle main thread is blocked too — ask Hangs, not thread states.}
  \trap{Queue inspector (27) skips tasks enqueued before the trace.}
  \trap{Profiling a \emph{Run}-launched app: TPC's checks can show in stacks — use \emph{Profile}.}
\end{itemize}

\section{Remember}
\textbf{Suspend, never block — the pool never grows.}
