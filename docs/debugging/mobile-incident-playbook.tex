\sheettitle{Mobile production incident — the playbook}{debugging · folio}

\oneliner{\textbf{A build already on users' phones cannot be recalled} — pausing or halting a rollout only
stops it reaching \emph{more} people. So: \textbf{detect} per version, \textbf{stop the spread} (pause / halt),
\textbf{neutralise the bad path server-side} (kill switch, compatibility shim, OTA JS rollback), \textbf{ship a fix}
(hotfix + expedited review, then force-update), \textbf{communicate}, and learn in a \textbf{blameless postmortem}.}

\section{Declare, organise, triage}
\begin{itemize}
  \item \textbf{Declare} if any holds: a second team is needed · customers can see it · unsolved after an hour of
        concentrated analysis. Declaring early and closing on a simple fix beats starting hours in.
  \item \textbf{Stop the bleeding first} — make the system work as well as it can; root cause later.
\end{itemize}

\section{Fix — hotfix, review, adoption}
\begin{itemize}
  \item Smallest diff, cherry-picked to the release branch. App Store: incremental version + incremented build
        string; Play: \ct{versionCode} above every previous one (max 2\,100\,000\,000).
  \item \textbf{Review}: $\ge$\,50\,\% in $<$\,24\,h, 90\,\% in $<$\,48\,h. \textbf{Expedited}: only a submission
        already sent; critical bug + steps to reproduce on the current version in \emph{Notes}; granted as
        availability allows. A rejected bug-fix with no legal/safety issue may ship, fixed next time — once per
        issue. Then phased, or \textbf{Release to All Users} at any time.
  \item \textbf{Force update}: \ct{min\_supported} in config $\to$ blocking screen $\to$ store. Play in-app updates:
        \ct{IMMEDIATE} (full screen; Play installs + restarts) or \ct{FLEXIBLE} (background);
        \ct{inAppUpdatePriority} 0–5 set at rollout via the Play Developer API, never changed.
  \item \textbf{Recovered} = that version's crash-free / funnel back at \emph{baseline}, not ``PR merged''.
\end{itemize}

\section{Kill switch — config, timing, crash loops}
\begin{lstlisting}[language=JSONSheet]
{ "min_supported": { "ios": "4.12.1", "android": 41201 },
  "kill": { "new_checkout": { "ios": ["4.13.0"] } },
  "banner": { "text": "Payments delayed, fixing now" } }
\end{lstlisting}
\begin{itemize}
  \item Firebase Remote Config: default minimum fetch interval \textbf{12\,h}; values apply on \ct{activate}.
        Real-time listener (Apple SDK 10.7.0+): server invalidation $\to$ fetch past the interval, foreground only.
  \item \textbf{expo-updates} guards JS crash loops: an error before the first render on an update's first launch
        marks it failed, waits 5\,s for a newer one, else reloads the last that launched; $>$\,10\,s after first
        render it is not caught. \ct{eas update:rollback} $\to$ a previous update or the embedded one.
\end{itemize}

\section{Learn — blameless postmortem}
\begin{itemize}
  \item \textbf{Triggers}: user-visible degradation past a threshold · any data loss · on-call intervention
        · resolution time past a threshold · a monitoring failure · any stakeholder asks.
  \item \textbf{Record}: timeline (UTC; TTD, TTM, TTR), impact in numbers, actions, root cause(s), follow-ups with
        owner + date. \textbf{Blameless}: causes, not culprits — everyone acted in good faith on what they knew.
\end{itemize}

\section{Traps}
\begin{itemize}
  \trap{Launch crash before config loads: no kill switch reaches it — guard crash loops, cache config.}
  \trap{Removing from sale to stop a phased release: reinstated, the version goes to 100\,\% at once.}
\end{itemize}

\section{Remember}
\textbf{Stop the spread, kill the path, ship the fix, force the stragglers, write it down.}
