\sheettitle{TypeScript generics \& type-level programming}{typescript · folio}

\oneliner{Type parameters are \textbf{solved by inference} at each call and bounded by
\texttt{extends}. \textbf{Conditional}, \textbf{mapped} and \textbf{template-literal} types add a
small pure functional language — if, pattern-bind, map over keys, recurse — that the checker runs
at compile time and erases from the JavaScript, inside fixed depth and union-size limits.}

\section{Type parameters \& inference}
\begin{itemize}
  \item \textbf{Constraint} \ct{<T extends HasId>}: an upper bound, met by shape; in the body
        only the constraint's members exist. \ct{K extends keyof T} ties one parameter to
        another. \textbf{Default} \ct{<T = string>} (2.3): used when inference finds no
        candidate; it must satisfy the constraint; no required parameter after a defaulted one.
  \item \textbf{Inference} gathers candidates from every argument: \ct{combine<T>(a: T[], b: T[])}
        on \ct{([1, 2, 3], ["hello"])} fails with \emph{Type 'string' is not assignable to type
        'number'} — pass \ct{<string | number>} explicitly.
  \item \textbf{Literal candidates} are kept, not widened (\ct{1} $\to$ \ct{number}), when the
        constraint includes a primitive or literal type: \ct{f<T extends number>(x: T, y: T): T[]}
        makes \ct{f(1, 2)} a \ct{(1 | 2)[]}; without the constraint \ct{number[]} (2.1, PR \#10676).
  \item \ct{<const T>} (5.0): infers as if the argument were written \ct{as const}
        (\ct{readonly ["a", "b"]}), but only for literals written in the call — a variable
        stays \ct{string[]}. A mutable constraint gives a mutable tuple: \ct{const T extends
        string[]} infers \ct{["a", "b"]} (5.3, PR \#55229; 5.0–5.2 fell back to \ct{string[]}).
  \item \ct{NoInfer<T>} (5.4, \ct{= intrinsic}): the position is checked but yields no
        candidates — the other arguments decide \ct{T}.
  \item \textbf{Instantiation expression} (4.7): \ct{const ErrorMap = Map<string, Error>} fixes
        the type arguments of a value; \ct{new ErrorMap()} is a \ct{Map<string, Error>}.
  \item Handbook rules: a type parameter should \textbf{appear twice}, or it relates nothing;
        \textbf{push it down} — \ct{<T extends any[]>(arr: T)} returning \ct{arr[0]} is inferred
        as \ct{any}, \ct{<T>(arr: T[])} as \ct{T}; use as few as possible.
\end{itemize}

\section{Operators on types}
\ct{keyof T}: the union of its keys — a \ct{string} index signature gives \ct{string | number}
(\ct{obj[0]} is \ct{obj["0"]}), a \ct{number} one \ct{number}; \ct{keyof any} =
\ct{string | number | symbol} (\ct{PropertyKey}). \ct{typeof v}: a value's type. \ct{T[K]}: indexed
access; \ct{T[number]}: the element type of an array or tuple; a tuple declares \ct{length} as a
literal (\ct{[string, number]["length"]} is \ct{2}). Variadic tuples (4.0): a spread may be generic
and sit anywhere — \ct{concat(a: T, b: U): [...T, ...U]} keeps both tuples' elements. 7.0 sorts
types by content, so a printed union lists its members in one fixed order (6.0:
\ct{--stableTypeOrdering}).

\section{Conditional types \& \texttt{infer} (2.8)}
\begin{itemize}
  \item \ct{T extends U ? X : Y} \textbf{resolves} to \ct{Y} when the most permissive \ct{T} is
        not assignable to \ct{U}, to \ct{X} when it definitely is — otherwise it is
        \textbf{deferred} and stays generic until \ct{T} is known.
  \item \ct{infer R} binds a piece of the match, and is allowed only in the \ct{extends} clause.
        One name in several \textbf{co}variant spots $\to$ a union; in \textbf{contra}variant
        spots (parameters) $\to$ an intersection.
  \item Inferring from an overloaded function uses its \textbf{last} signature only — for
        \ct{ReturnType} too.
  \item \ct{infer S extends string} (4.7) filters in place; 4.8 parses literals:
        \ct{"100" extends `\$\{infer N extends number\}`} gives \ct{100}, but \ct{"1.0"} gives
        \ct{number} (it does not round-trip).
\end{itemize}

\section{Traps}
\begin{itemize}
  \trap{Returning a new object where \ct{T} was promised: \emph{'\{ length: number; \}' is
        assignable to the constraint of type 'Type', but 'Type' could be instantiated with a
        different subtype of constraint …} — the caller may hold a richer \ct{T}.}
  \trap{\ct{Omit}/\ct{Pick} on a union: \ct{keyof (A | B)} has only the shared keys, so
        branch-only members vanish. \ct{Omit} (3.5) does not distribute, by design (\#31501):
        write \ct{T extends any ? Omit<T, K> : never}.}
  \trap{\ct{T extends never ? …} on \ct{never} gives \ct{never} (\#23182): test
        \ct{[T] extends [never]}.}
  \trap{A \ct{return} under a declared \ct{T extends string ? A : B} does not narrow by the
        branch taken — each needs a cast. A fix was in the 5.8 beta (\#56941), reverted
        (\#61136); the retry (\#61359) closed unmerged in Dec 2025.}
\end{itemize}

\columnbreak

\section{Mapped \& template literal types}
\begin{itemize}
  \item \ct{keyof T} may hold \ct{number}/\ct{symbol} keys: remap via \ct{Capitalize<string \& K>}.
  \item \textbf{Template literal types} (4.1) cross-multiply the unions in their holes:
        \ct{`\$\{"one" | "two" | "red" | "blue"\} fish`} has 4 members. A union must stay below
        \textbf{100\,000} members, else TS2590 \emph{Expression produces a union type that is too
        complex to represent}.
  \item \textbf{Matching} \ct{S extends `…\$\{infer X\}…`}: a hole followed by literal text takes
        characters up to that text's \textbf{first} occurrence; a hole followed by another hole
        takes \textbf{one} character; the last takes the rest. 7.0 counts code points: an emoji
        is one character, not two surrogate halves.
  \item \ct{Uppercase}, \ct{Lowercase}, \ct{Capitalize}, \ct{Uncapitalize} are declared
        \ct{intrinsic} in the lib: built into the compiler.
\end{itemize}

\section{Recursion \& limits}
\begin{itemize}
  \item 3.7 resolves type arguments lazily, so an alias may recurse through an array or
        generic: \ct{type Json = string | number | boolean | null | Json[] | \{ [k: string]: Json \}}.
        4.1: conditional types may recurse — ``responsibly and sparingly''.
  \item \textbf{100} nested instantiations, or \textbf{5\,000\,000} in all, end in TS2589
        \emph{Type instantiation is excessively deep and possibly infinite}. Depth was 50 until
        4.5 (PR \#45711); not configurable; 7.0 keeps both (team, Sep 2026).
  \item \textbf{Tail position} (4.5): a branch that \emph{is} another conditional is evaluated in
        a loop, up to \textbf{1000} rounds. \ct{Char | GetChars<Rest>} is not tail; an
        accumulator \ct{Helper<Rest, Char | Acc>} is.
  \item \ct{in}/\ct{out} also speed up deeply recursive types: the checker compares type
        arguments instead of whole structures.
\end{itemize}

\section{The lib (es5.d.ts), condensed}
\begin{lstlisting}[style=ts]
type Partial<T>  = { [P in keyof T]?: T[P] };
type Required<T> = { [P in keyof T]-?: T[P] };
type Readonly<T> = { readonly [P in keyof T]: T[P] };
type Pick<T, K extends keyof T> = { [P in K]: T[P] };
type Record<K extends keyof any, T> = { [P in K]: T };
type Exclude<T, U> = T extends U ? never : T;
type Extract<T, U> = T extends U ? T : never;
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;
type NonNullable<T> = T & {};        // 4.8; was a conditional
type Parameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;
type ReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : any;
type Awaited<T> = T extends null | undefined ? T :
  T extends object & { then(onfulfilled: infer F, ...args: infer _): any }
    ? F extends ((value: infer V, ...args: infer _) => any) ? Awaited<V> : never
    : T;
type Uppercase<S extends string> = intrinsic;  // NoInfer<T> too
\end{lstlisting}

\section{Worked types}
\begin{lstlisting}[style=ts]
type Foo<T> = T extends { a: infer U; b: infer U } ? U : never;
type F1 = Foo<{ a: string; b: number }>;      // string | number
type Bar<T> = T extends { f: (x: infer U) => void;
                          g: (x: infer U) => void } ? U : never;
type B1 = Bar<{ f: (x: { a: 1 }) => void;
                g: (x: { b: 2 }) => void }>;  // { a: 1 } & { b: 2 }
type Handlers<E> = {
  [K in keyof E as `on${Capitalize<string & K>}`]: (e: E[K]) => void };
type H = Handlers<{ login: { id: string }; logout: undefined }>;
// { onLogin: (e: { id: string }) => void; onLogout: (e: undefined) => void }
type Params<S> = S extends `${string}:${infer P}/${infer R}`
  ? P | Params<`/${R}`>
  : S extends `${string}:${infer P}` ? P : never;
type P1 = Params<"/u/:id/post/:pid">;          // "id" | "pid"
function light<C extends string>(all: C[], start: NoInfer<C>) {}
light(["red", "green"], "blue");  // error: Argument of type
// '"blue"' is not assignable to parameter of type '"red" | "green"'.
\end{lstlisting}
