\sheettitle{Hilt \& Dagger in depth — graph, components, scopes, tests}{cross-platform · folio}

\oneliner{Dagger turns \texttt{@Inject}/\texttt{@Provides}/\texttt{@Binds} into a \textbf{dependency graph checked
at compile time} and emits plain factory code — no reflection. Hilt fixes the \textbf{component tree}
to Android lifetimes: a binding lives in one component, is visible to that component's
\textbf{children}, and a \textbf{scope} annotation means ``one instance per component instance''.}

\section{Binding sources}
\begin{itemize}\raggedright
  \item \texttt{@Inject constructor} — your own classes; prefer it. \texttt{@Provides} — code
        for types you don't own (Retrofit, Room builder). \texttt{@Binds} — abstract,
        \textbf{no body}, interface $\to$ impl, cheapest (no module instance).
  \item \texttt{@Module @InstallIn(X::class)} decides the component (and so who can see it and how
        long a scoped instance lives). A scope on a binding must match its component.
  \item \textbf{Qualifiers} for two bindings of one type: \texttt{@Named("auth")} or a custom
        \texttt{@Qualifier annotation class}; built-ins \texttt{@ApplicationContext},
        \texttt{@ActivityContext}.
  \item \textbf{Multibindings}: \texttt{@IntoSet}/\texttt{@ElementsIntoSet} $\to$
        \texttt{Set<T>}; \texttt{@IntoMap} + \texttt{@StringKey}/\texttt{@ClassKey}/custom
        \texttt{@MapKey} $\to$ \texttt{Map<K, V>} or \texttt{Map<K, Provider<V>{}>};
        \texttt{@Multibinds} declares a possibly empty one. Plug-ins, interceptors, initialisers.
  \item \texttt{Provider<T>}: \texttt{get()} each call (new if unscoped). \texttt{Lazy<T>}
        (\texttt{dagger.Lazy}): built on first \texttt{get()}, then cached \emph{per Lazy}. Both
        defer work and break a cycle.
\end{itemize}

\section{Example}
\begin{lstlisting}[language=KotlinSheet]
@Qualifier annotation class Auth
@Module @InstallIn(SingletonComponent::class)
abstract class DataModule {
  @Binds abstract fun repo(impl: NoteRepoImpl): NoteRepo
  @Binds @IntoSet abstract fun log(i: LogInterceptor): Interceptor
  companion object {
    @Provides @Singleton @Auth
    fun ok(set: Set<@JvmSuppressWildcards Interceptor>) =
      OkHttpClient.Builder().apply { set.forEach(::addInterceptor) }.build() } }
@HiltViewModel(assistedFactory = NoteVM.Factory::class)
class NoteVM @AssistedInject constructor(@Assisted val id: Long,
    repo: NoteRepo, heavy: Lazy<Parser>) : ViewModel() {
  @AssistedFactory interface Factory { fun create(id: Long): NoteVM } }
// Compose: hiltViewModel<NoteVM, NoteVM.Factory> { it.create(id) }
\end{lstlisting}

\section{Traps}
\begin{itemize}\raggedright
  \trap{Scoping ``for performance'' — a scope is a lifetime + a lock, not a speed-up.}
  \trap{\texttt{Set<Interceptor>} in Kotlin needs \texttt{@JvmSuppressWildcards}, or MissingBinding.}
  \trap{Plain unit tests need no Hilt — call the \texttt{@Inject} constructor with fakes.}
\end{itemize}

\textbf{Remember:} \emph{Inject constructors, Bind interfaces, Provide the rest · install decides
visibility · scope = one per component.}

\columnbreak

\section{Assisted injection \& entry points}
\begin{itemize}\raggedright
  \item \texttt{@AssistedInject} mixes runtime values (\texttt{@Assisted id}) with graph deps
        via a generated \texttt{@AssistedFactory}; VMs: \texttt{@HiltViewModel(assistedFactory =
        …)} (Dagger \textbf{2.49}). Assisted values are \textbf{not saved} on process death —
        nav args go in \texttt{SavedStateHandle}.
  \item \texttt{@EntryPoint} = a door \emph{into} the graph for what Hilt can't construct
        (\texttt{ContentProvider}, library callbacks): \texttt{interface E \{ fun repo(): Repo \}}
        + \texttt{EntryPointAccessors.fromApplication(ctx, E::class.java).repo()}.
\end{itemize}

\section{Testing}
\begin{itemize}\raggedright
  \item \texttt{@HiltAndroidTest} + \texttt{@get:Rule val hilt = HiltAndroidRule(this)} (first
        rule) + \texttt{hilt.inject()}, \texttt{HiltTestApplication}; a \textbf{fresh}
        SingletonComponent per test.
  \item Per class: \texttt{@UninstallModules(NetModule::class)} + a nested test module. Whole
        source set: \texttt{@TestInstallIn(replaces = [NetModule::class], …)}. One field:
        \texttt{@BindValue @JvmField val api: Api = FakeApi()}.
\end{itemize}

\section{Koin vs Hilt}
\raggedright Koin: \texttt{module \{ single \{ Repo(get()) \}; viewModel \{ VM(get()) \} \}},
resolved at \textbf{runtime}: fast builds, KMP-ready, a missing binding crashes on first use
(\texttt{verify()} test; Koin Annotations add KSP checks). Hilt: compile-time, Android/JVM only.

\section{Errors you will read}
\begin{itemize}\raggedright
  \item \texttt{[Dagger/MissingBinding] X cannot be provided without an @Inject constructor or an
        @Provides-annotated method} — wrong component/qualifier, no \texttt{@Binds}.
  \item \texttt{[Dagger/IncompatiblyScopedBindings]} (\texttt{@Singleton} $\to$
        \texttt{@ActivityScoped}); \texttt{[Dagger/DependencyCycle]} $\to$ \texttt{Provider}/\texttt{Lazy}.
  \item ``Hilt Activity must be attached to an @HiltAndroidApp Application'' — no
        \texttt{android:name}.
\end{itemize}
