\sheettitle{Android build \& performance — Gradle, R8, profiles, startup}{cross-platform · folio}

\oneliner{A release build is \textbf{Gradle} (configure a task graph, then run only out-of-date
tasks) driving \textbf{kotlinc/KSP $\to$ R8 $\to$ dex $\to$ AAB}; Play splits it per device. At
runtime ART \textbf{interprets/JITs} unbundled code such as Compose, so a \textbf{Baseline
Profile} tells it what to compile \textbf{ahead of time} at install. Prove every win with \textbf{Macrobenchmark} + \textbf{Perfetto}.}

\section{Gradle \& AGP}
\begin{itemize}\raggedright
  \item \textbf{Config cache} (\texttt{org.gradle.configuration-cache=true}) stores the task
        graph; \textbf{build cache} (\texttt{org.gradle.caching=true}, local or remote)
        stores task \emph{outputs} keyed by input hashes — CI shares them.
  \item \textbf{Version catalog} \texttt{gradle/libs.versions.toml} $\to$
        \texttt{libs.hilt.android}; \textbf{convention plugins} (included
        \texttt{build-logic} build) share module setup.
  \item \texttt{api} leaks a dependency to consumers $\to$ wider recompiles; prefer
        \texttt{implementation}.
  \item \textbf{KSP} over \textbf{kapt} (Java \emph{stubs}, maintenance mode): up to
        \textbf{2$\times$} faster — but one kapt processor left keeps stubs for the module.
  \item \textbf{AGP 9}: Kotlin built in (no \texttt{kotlin-android} plugin), new DSL only,
        Gradle $\geq$ 9.1.
\end{itemize}

\section{R8 — full mode (default since AGP 8.0)}
\begin{itemize}\raggedright
  \item Tree-shakes from entry points (manifest, keep rules), inlines, merges classes,
        renames; unused resources go too (AGP 9: optimized resource shrinking).
  \item Full mode vs compat: a kept class \textbf{no longer keeps its default constructor};
        \texttt{Signature}/annotations kept \textbf{only for kept items} even with
        \texttt{-keepattributes} — Gson \texttt{TypeToken}, Retrofit generics break.
  \item \texttt{-keep} (name + existence) · \texttt{-keepclassmembers} (members if class
        survives) · \texttt{-keepnames}/\texttt{,allowshrinking} (rename no, remove yes) ·
        \texttt{-if} (conditional). Libraries ship \texttt{consumerProguardFiles}.
\end{itemize}

\section{Example — build config}
\begin{lstlisting}[language=GradleSheet]
# gradle.properties
org.gradle.configuration-cache=true
org.gradle.caching=true
// app/build.gradle.kts
android { buildTypes { release {
  isMinifyEnabled = true; isShrinkResources = true
  proguardFiles(getDefaultProguardFile(
    "proguard-android-optimize.txt"), "proguard-rules.pro") } } }
dependencies {
  ksp(libs.hilt.compiler)                     // not kapt
  implementation(libs.androidx.profileinstaller)
  baselineProfile(project(":baselineprofile")) }
# proguard-rules.pro (Gson in full mode)
-keepclassmembers,allowobfuscation class * {
  @com.google.gson.annotations.SerializedName <fields>; }
\end{lstlisting}

\section{Traps}
\begin{itemize}\raggedright
  \trap{Timing a \emph{debug} build — no R8, no AOT: meaningless numbers.}
  \trap{A stale profile silently loses its gain — benchmark it in CI.}
  \trap{``R8 broke my app'' — it removed what only reflection used; add a keep rule, don't
        disable minify.}
\end{itemize}

\columnbreak

\section{Baseline \& Startup Profiles}
\begin{itemize}\raggedright
  \item Compose/AndroidX are \emph{libraries}, not in the OS image: first runs are
        interpreted/JIT'd. A \textbf{Baseline Profile} lists hot classes/methods; ART
        AOT-compiles them at install — about \textbf{30\%} faster from the first launch.
        Play ships it; \texttt{ProfileInstaller} covers sideloads.
  \item Generate with \texttt{BaselineProfileRule().collect(pkg) \{ … \}} over startup +
        key journeys (\texttt{generateBaselineProfile}); regenerate per release.
  \item \textbf{Startup Profile} (\texttt{includeInStartupProfile = true}): R8 lays startup
        code into the primary dex — about \textbf{15\%} more. \textbf{Cloud Profiles} (API
        28+) come later from real users.
\end{itemize}

\section{Measure — benchmarks \& Perfetto}
\begin{itemize}\raggedright
  \item \textbf{Macrobenchmark}: own module drives the installed, non-debuggable
        \texttt{profileable} app — \texttt{StartupTimingMetric}, \texttt{FrameTimingMetric};
        \texttt{StartupMode.COLD}; \texttt{CompilationMode.None()} vs \texttt{Partial()}
        proves the profile. \textbf{Micro}: \texttt{BenchmarkRule}, one function.
  \item \textbf{Perfetto} system trace $\to$ ui.perfetto.dev; \texttt{trace("load")\{…\}}
        marks code; read \texttt{bindApplication}, \texttt{doFrame}, lock/binder waits.
\end{itemize}

\section{Startup — the numbers}
\begin{itemize}\raggedright
  \item \textbf{Cold}: new process · \textbf{warm}: process alive, Activity re-created ·
        \textbf{hot}: Activity brought to front. Optimise for cold.
  \item \textbf{TTID} = first frame, logged automatically (\texttt{Displayed … +480ms});
        \textbf{TTFD} = when you call \texttt{reportFullyDrawn()} (Compose:
        \texttt{ReportDrawnWhen \{ loaded \}}).
  \item Vitals ``excessive'': cold $\geq$ \textbf{5\,s}, warm $\geq$ \textbf{2\,s}, hot
        $\geq$ \textbf{1.5\,s}. Frames: $>$16\,ms (60 Hz) slow, $>$700\,ms frozen.
  \item Fixes: nothing blocking in \texttt{Application.onCreate}, lazy SDK init, profiles.
\end{itemize}

\textbf{Remember:} \emph{configure cheap, execute cached · R8 keeps what it sees · profile
$\to$ AOT at install · measure release + cold.}
