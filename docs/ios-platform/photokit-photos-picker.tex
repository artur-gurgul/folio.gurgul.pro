\sheettitle{Photos — the picker vs PhotoKit, limited library}{ios-platform · folio}

\oneliner{Two ways in. The \textbf{out-of-process picker} (\ct{PHPickerViewController} 14, SwiftUI \ct{PhotosPicker} 16)
needs \textbf{no permission} — the app gets only the picked items. \textbf{PhotoKit} (\ct{PHPhotoLibrary},
\ct{PHAsset}, \ct{PHImageManager}) is a live database behind \textbf{authorization}: \ct{.readWrite} — which may
come back \textbf{\ct{.limited}}, a user-chosen subset (iOS 14) — or \ct{.addOnly}. Picker unless you \emph{are}
a gallery, backup or editor app.}

\hd{Door 1 — the picker}
\begin{itemize}
  \item Result = \ct{PHPickerResult.itemProvider} (UIKit) or \ct{PhotosPickerItem} (a \ct{Transferable} placeholder).
        UIKit: \ct{didFinishPicking} fires on Add \emph{and} Cancel — \textbf{you dismiss}.
  \item Config: \ct{selectionLimit} (default 1, \textbf{0 = no limit}); \ct{filter} \ct{.images} \ct{.videos}
        \ct{.livePhotos} \ct{.screenshots}, combined by \ct{.any(of:)} \ct{.all(of:)} \ct{.not}; encoding
        \ct{.current} (keep HEIC) vs \ct{.compatible} (transcode).
  \item \textbf{IDs} are \ct{nil} unless built with \ct{init(photoLibrary: .shared())} — required for
        \ct{preselectedAssetIdentifiers} (15); fetching that \ct{PHAsset} still needs authorization.
  \item \textbf{Embedded, iOS 17}: \ct{.photosPickerStyle(.inline)}, \ct{selectionBehavior: .continuous}
        (live, no Add button), \ct{.photosPickerDisabledCapabilities([.search, .stagingArea])}.
\end{itemize}

\hd{Example — picker, no permission}
\begin{lstlisting}[language=SwiftSheet]
PhotosPicker(selection: $items, maxSelectionCount: 5,
    matching: .all(of: [.images, .not(.screenshots)]),
    preferredItemEncoding: .compatible) { Label("Add", systemImage: "photo") }
.task(id: items) {
  for item in items {                      // Image.self: PNG/JPEG only
    guard let d = try? await item.loadTransferable(type: Data.self)
    else { continue }                      // nil = type not offered
    thumbs.append(downsample(d, maxPixels: 600)) } } // never full size
\end{lstlisting}
Video: \ct{FileRepresentation} / \ct{loadFileRepresentation} — temp file \textbf{deleted when the handler returns}.

\hd{Door 2 — PhotoKit}
\begin{itemize}
  \item \ct{PHAsset} = metadata (\ct{mediaType}, \ct{pixelWidth}, \ct{creationDate}, \ct{localIdentifier});
        \ct{PHAssetCollection} = album; \ct{PHAssetResource} = the original files.
  \item \ct{fetchAssets} $\to$ \ct{PHFetchResult}: \textbf{lazy}, thread-safe, a \textbf{snapshot} (count fixed) —
        updates come as \ct{PHChange}, often on a \textbf{background queue}.
  \item \ct{requestImage(for:targetSize:contentMode:options:)}: size in \textbf{pixels}; keep the
        \ct{PHImageRequestID}, \ct{cancelImageRequest} on reuse. \ct{isNetworkAccessAllowed} defaults
        \textbf{false} $\to$ iCloud-only asset: \ct{PHImageResultIsInCloudKey}, no image.
  \item \ct{PHCachingImageManager}: \ct{startCachingImages} for rows about to appear — then request with the
        \textbf{same} size, mode, options, or it misses.
  \item \textbf{Writes} only in \ct{performChanges \{\}} (creation / change requests, \ct{deleteAssets}); runs on
        a serial background queue; editing or deleting shows a \textbf{confirmation per call} — batch.
\end{itemize}

\hd{Which door?}
Avatar, attachment, ``import to edit'' $\to$ \textbf{picker}. Own gallery, backup, bulk edit $\to$
\textbf{\ct{.readWrite}}, designed for \ct{.limited} too. Camera app that only saves $\to$ \textbf{\ct{.addOnly}}.
Original bytes / RAW: \ct{PHAssetResourceManager.writeData(for:toFile:options:)}.

\hd{Keys and the limited library}
{\footnotesize
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{36mm}>{\raggedright\arraybackslash}p{36mm}@{}}
\toprule
\ct{NSPhotoLibraryUsageDescription} & \ct{.readWrite}: read, edit, add \\
\ct{NSPhotoLibraryAddUsageDescription} & \ct{.addOnly} (iOS 11): save only \\
\ct{PHPhotoLibraryPrevent-}\newline\ct{AutomaticLimitedAccessAlert} & YES = no auto ``select more'' prompt (default once per life cycle) \\
picker, \ct{PhotosPicker} & \textbf{nothing} \\
\bottomrule
\end{tabular}}\par
\textbf{\ct{.limited}}: fetches see only the selection; no user albums; assets you \textbf{create} join it;
\ct{presentLimitedLibraryPicker} (15: returns new ids) grows it. \textbf{IDs}: \ct{localIdentifier} is per device —
\ct{PHCloudIdentifier} (15) across devices. \textbf{26.1}: \ct{PHBackgroundResourceUploadExtension} (backup apps).

\hd{Traps}
\begin{itemize}
  \trap{Full library access to set an avatar — the picker needs no prompt and no key.}
  \trap{\ct{authorizationStatus()} without a level: \ct{.limited} reads \ct{.authorized} — ``why 3 photos?''}
  \trap{\ct{Image}'s \ct{Transferable} is PNG + JPEG only — load \ct{Data} or your own type.}
  \trap{\ct{targetSize} in points, or \ct{PHImageManagerMaximumSize} for a thumb: 48 MB per 12 MP.}
  \trap{Cancel after preselection returns the \emph{preselected} ids, not \ct{[]}.}
\end{itemize}

\hd{Remember}
\textbf{``Picker: no permission. PhotoKit: prompt, \emph{limited} = subset. Pixels, twice, back to main.''}
