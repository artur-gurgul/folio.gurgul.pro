\sheettitle{ARKit + RealityKit — tracking, anchors, entities}{ios-platform · folio}

\oneliner{\textbf{ARKit} fuses feature points tracked across camera frames with the \textbf{IMU}
(\textbf{visual-inertial odometry}) into a 6-DoF \textbf{camera pose} in a gravity-aligned world in
\textbf{metres}; each tick is an \ct{ARFrame}, and what it recognises (planes, images, faces, meshes)
becomes \textbf{anchors} it keeps correcting. \textbf{RealityKit} renders on top: an
\textbf{Entity-Component-System} engine (\ct{ARView} in UIKit, \ct{RealityView} in SwiftUI from
iOS 18) drawing USD content locked to those anchors.}

\hd{How ARKit works}
\begin{itemize}
  \item \ct{ARSession} runs \textbf{one} configuration; \ct{run(cfg, options: [.resetTracking,
        .removeExistingAnchors])} starts over, \ct{pause()} frees the camera. The delegate gets
        frames, anchor add/update/remove, tracking-state changes, interruptions.
\end{itemize}
{\footnotesize
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{9mm}>{\raggedright\arraybackslash}p{64mm}@{}}
\toprule
\multicolumn{2}{@{}l}{\ct{AR\ldots Configuration}} \\ \midrule
World & back camera, 6 DoF: planes, images, objects, mesh, depth, people \\
Face & front: \ct{ARFaceAnchor} mesh + \ct{blendShapes} 0–1 (\ct{jawOpen}…); TrueDepth up to iOS 13, any Neural Engine device from iOS 14 \\
Body & \ct{ARBodyAnchor} skeleton · \textbf{Image}: known images only \\
Geo & \ct{ARGeoAnchor} at lat/long; A12+, GPS, outdoors, supported cities \\
\bottomrule
\end{tabular}}
\begin{itemize}
  \item \textbf{Anchors}: \ct{ARPlaneAnchor} (horizontal/vertical, \ct{classification}) ·
        \ct{ARImageAnchor} (reference image + \textbf{physical size}) · \ct{ARObjectAnchor}
        (\ct{.arobject}) · \ct{ARMeshAnchor} (LiDAR, \ct{sceneReconstruction = .mesh}, iOS 13.4).
  \item \textbf{Raycast} (iOS 13; \ct{hitTest} deprecated in 14): screen point $\to$
        \ct{ARRaycastQuery}; target \ct{.estimatedPlane} (instant, rough) ·
        \ct{.existingPlaneGeometry} (inside a detected plane) · \ct{.existingPlaneInfinite}.
        \ct{trackedRaycast} re-fires as understanding improves; \ct{stopTracking()}.
  \item \textbf{Depth}: \ct{frameSemantics} \ct{.personSegmentationWithDepth} (iOS 13, people
        occlude content) · \ct{.sceneDepth} (iOS 14, LiDAR depth + confidence). Check
        \ct{supportsFrameSemantics} first.
  \item \textbf{Persist}: at \ct{worldMappingStatus \hbox{=}\hbox{=} .mapped}, \ct{getCurrentWorldMap} $\to$
        \ct{ARWorldMap} (\ct{NSSecureCoding}) $\to$ later \ct{initialWorldMap}; state is
        \ct{.relocalizing} until the room is recognised. \textbf{Shared}: \ct{isCollaborationEnabled};
        you ship \ct{CollaborationData} (e.g. Multipeer) $\to$ \ct{update(with:)}; best $\leq$ 4 users.
  \item Limited tracking: show a hint, place nothing; or \ct{ARCoachingOverlayView} (iOS 13,
        \ct{goal: .horizontalPlane}…). \ct{lightEstimate}: 1000 lm = neutral.
\end{itemize}

\hd{Example — tap to place (ARView)}
\begin{lstlisting}[language=SwiftSheet]
let cfg = ARWorldTrackingConfiguration()
cfg.planeDetection = [.horizontal]
if ARWorldTrackingConfiguration.supportsSceneReconstruction(.mesh) {
  cfg.sceneReconstruction = .mesh }            // LiDAR only
arView.session.run(cfg)
guard let q = arView.makeRaycastQuery(from: tapPoint,
        allowing: .estimatedPlane, alignment: .horizontal),
      let hit = arView.session.raycast(q).first else { return }
let a = AnchorEntity(raycastResult: hit)
a.addChild(ModelEntity(mesh: .generateBox(size: 0.1),  // 10 cm
                       materials: [SimpleMaterial()]))
arView.scene.addAnchor(a)
var t = matrix_identity_float4x4; t.columns.3.z = -0.5 // 50 cm ahead
session.add(anchor: ARAnchor(transform: frame.camera.transform * t))
\end{lstlisting}

\hd{RealityKit}
\begin{itemize}
  \item \textbf{ECS}: \ct{Entity} = identity + hierarchy; \textbf{components} = data (\ct{Transform},
        \ct{ModelComponent}, \ct{CollisionComponent}, \ct{PhysicsBodyComponent},
        \ct{AnchoringComponent}, yours); \textbf{systems} (iOS 15) = behaviour, run each frame over
        the entities that match a query.
  \item \ct{AnchorEntity(.plane(...))} lets RealityKit do the ARKit anchoring; also
        \ct{(raycastResult:)}, \ct{(world:)}, \ct{(anchor:)}.
  \item \ct{ARView} (UIKit, iOS 13): owns an \ct{ARSession}; \ct{cameraMode .ar/.nonAR}.
        \ct{RealityView} (SwiftUI; visionOS 1, \textbf{iOS 18}): \ct{content.camera = .spatialTracking}
        (passthrough + tracking) or \ct{.virtual}; \ct{SpatialTrackingSession} picks tracking and
        scene understanding (occlusion, shadows).
  \item Assets are \textbf{USD/USDZ}, authored in \textbf{Reality Composer Pro} (ships with Xcode).
        \textbf{SceneKit is deprecated} (WWDC25, soft: no removal date); \ct{ARSCNView} deprecated in
        iOS 26 $\to$ \ct{RealityView}.
\end{itemize}

\hd{Example — a custom component + system (iOS 18)}
\begin{lstlisting}[language=SwiftSheet]
struct Spin: Component { var speed: Float = 1 }
struct SpinSystem: System {
  static let q = EntityQuery(where: .has(Spin.self))
  init(scene: Scene) {}
  func update(context: SceneUpdateContext) {
    for e in context.entities(matching: Self.q,
                              updatingSystemWhen: .rendering) {
      guard let s = e.components[Spin.self] else { continue }
      let dt = Float(context.deltaTime)                 // seconds
      e.transform.rotation = simd_quatf(angle: s.speed * dt,
                                axis: [0, 1, 0]) * e.transform.rotation } } }
// once: Spin.registerComponent(); SpinSystem.registerSystem()
RealityView { content in
  content.camera = .spatialTracking          // passthrough + tracking
  let a = AnchorEntity(.plane(.horizontal, classification: .any,
                              minimumBounds: [0.2, 0.2]))
  let box = ModelEntity(mesh: .generateBox(size: 0.1),
                        materials: [SimpleMaterial()])
  box.components.set(Spin(speed: 2)); a.addChild(box); content.add(a) }
\end{lstlisting}

\hd{Traps}
\begin{itemize}
  \trap{\textbf{Holding \ct{ARFrame}s} (a property, an async closure, slow Vision work on the delegate
        queue) drains the camera's buffer pool: ``delegate is retaining N ARFrames'', then the feed
        freezes. Copy out what you need.}
  \trap{Placing content while \ct{.limited} or before a plane settles $\to$ drift; planes grow and merge.}
  \trap{\textbf{No AR in the Simulator}; gate every feature on \ct{isSupported} / \ct{supports…}
        (LiDAR, face, geo). \ct{arkit} in required capabilities only if AR is the whole app.}
  \trap{No \ct{NSCameraUsageDescription} $\to$ crash; face tracking also needs a privacy policy.
        Wrong reference-image \textbf{physical size} $\to$ content floats or sinks.}
  \trap{\textbf{Thermal}: camera + VIO + mesh + occlusion + rendering. Stop plane detection when done;
        \ct{pause()} off screen.}
\end{itemize}

\hd{Remember}
\textbf{``Camera + IMU $\to$ pose $\to$ anchors; entities = ids, components = data, systems = behaviour.''}
