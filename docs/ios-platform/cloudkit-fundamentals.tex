\sheettitle{CloudKit fundamentals — databases, zones, records, errors}{ios-platform · folio}

\oneliner{Apple's hosted database behind the user's iCloud account. A \textbf{container} holds
three databases — \textbf{public} (everyone, your quota), \textbf{private} (this user, \emph{their}
quota), \textbf{shared} (zones others shared with me). \textbf{Records} live in \textbf{zones}; a save
is checked against the record's \textbf{change tag}, so a conflict is an \emph{error you resolve},
never a silent overwrite. Only \textbf{custom zones} give atomic writes, change tokens and sharing.}

\hd{Records}
\begin{itemize}
  \item \ct{CKRecord} = \ct{recordType} + fields (String, number, Data, Date, CLLocation, arrays,
        \ct{CKAsset}, \ct{Reference}), $\leq$ \textbf{1 MB} without assets. \ct{CKRecord.ID} =
        \ct{recordName} (yours, e.g. UUID $\to$ idempotent retry) + \ct{zoneID}: a record never
        changes zone.
  \item System fields: \ct{recordChangeTag}, \ct{creationDate}, \ct{modificationDate},
        \ct{creatorUserRecordID}, \ct{parent}, \ct{share}. Local cache? keep
        \ct{encodeSystemFields(with:)} or every save conflicts.
  \item \ct{CKRecord.Reference(recordID:action:)}: \textbf{same zone only}; \ct{.deleteSelf}
        cascades. \ct{CKAsset(fileURL:)}: uploaded apart, fetched to a \emph{temporary} file — copy it.
\end{itemize}

\hd{Operations vs async API}
\begin{itemize}
  \item \textbf{Async} (iOS 15): \ct{record(for:)}, \ct{save(\_:)},
        \ct{modifyRecords(saving:deleting:…)}, \ct{records(matching:…)},
        \ct{recordZoneChanges(…)}. Results are \textbf{per item} (\ct{[ID: Result]}): no
        throw $\neq$ all saved.
  \item \textbf{CKOperation} subclasses (\ct{CKModifyRecordsOperation}, \ct{CKQueryOperation}, …):
        per-record callbacks, progress, cancel, dependencies, long-lived. Default QoS is low.
  \item Save policy: \ct{.ifServerRecordUnchanged} (default, tag must match) ·
        \ct{.changedKeys} / \ct{.allKeys} (overwrite, no check). \ct{isAtomic} (default
        \ct{true}): all-or-nothing \emph{per custom zone}.
\end{itemize}

\hd{Example — save, and resolve a conflict}
\begin{lstlisting}[language=SwiftSheet]
let db = CKContainer(identifier: "iCloud.com.example.app")
           .privateCloudDatabase
func rename(_ id: CKRecord.ID, to title: String) async throws {
  var rec = try await db.record(for: id)    // carries change tag
  for _ in [1, 2, 3] {
    rec["title"] = title
    do { _ = try await db.save(rec); return } // tag must match
    catch let e as CKError where e.code == .serverRecordChanged {
      guard let server = e.serverRecord else { throw e }
      rec = server           // merge INTO the server copy (new tag)
    } catch let e as CKError where e.retryAfterSeconds != nil {
      try await Task.sleep(for: .seconds(e.retryAfterSeconds ?? 1))
    }
  }
}
\end{lstlisting}

\hd{Queries, indexes, schema environments}
\begin{itemize}
  \item \ct{CKQuery(recordType:predicate:)} + sort, paged by \ct{queryCursor}. Indexes:
        \textbf{Queryable} (equality; on \ct{recordName} to list all), \textbf{Sortable}
        (ranges, sort), \textbf{Searchable} (tokens).
  \item \textbf{Development}: an unknown type or key is \emph{created} on save. \textbf{Production}:
        it is an error. CloudKit Console $\to$ \emph{Deploy Schema Changes}; production is
        \textbf{add-only}. Xcode runs use Development; \textbf{TestFlight + App Store use Production}.
\end{itemize}

\hd{Subscriptions + silent push}
\begin{itemize}
  \item \ct{CKQuerySubscription} (public + private) · \ct{CKRecordZoneSubscription} (one zone)
        · \ct{CKDatabaseSubscription} (private + shared, every custom zone — how you hear of
        \emph{new} shared zones).
  \item \ct{shouldSendContentAvailable = true} $\to$ silent push (Background Mode \emph{Remote
        notifications}, no prompt). \textbf{Coalesced, droppable}: a hint to fetch, not data.
\end{itemize}

\hd{Account}
\ct{accountStatus()}: \ct{.available} · \ct{.noAccount} · \ct{.restricted} ·
\ct{.couldNotDetermine} · \ct{.temporarilyUnavailable}. On \ct{.CKAccountChanged}, a
new \ct{userRecordID()} $\to$ \textbf{wipe old data}.

\hd{Errors you must handle — \ct{CKError.Code}}
{\footnotesize\setstretch{0.95}\setlength{\tabcolsep}{3pt}
\begin{tabular}{@{}L{27mm}L{48mm}@{}}
\toprule
\ct{serverRecordChanged} & merge into \ct{e.serverRecord}, save again \\
\ct{partialFailure} & per item: \ct{e.partialErrorsByItemID} \\
\ct{batchRequestFailed} & atomic zone: another item failed; fix, resend \\
\ct{requestRateLimited}, \ct{zoneBusy}, \ct{serviceUnavailable} & wait \ct{e.retryAfterSeconds}, then retry — never a hot loop \\
\ct{limitExceeded} & too many items / bytes: split the batch \\
\ct{changeTokenExpired} & refetch the zone from a \ct{nil} token \\
\ct{zoneNotFound} & create the zone, retry \\
\ct{userDeletedZone} & user wiped iCloud data: ask before re-upload \\
\ct{quotaExceeded} & user's iCloud full: tell them, stop retrying \\
\ct{notAuthenticated} & no account: check \ct{accountStatus()} \\
\bottomrule
\end{tabular}}

\hd{Traps}
\begin{itemize}
  \trap{Default zone ``to keep it simple'' — no atomic batch, tokens or share; create a custom zone.}
  \trap{Resaving your own copy after a conflict — old tag, fails forever.}
  \trap{Fine in Development, empty in Production — schema not deployed.}
  \trap{Private-DB \ct{quotaExceeded} is the \emph{user's} storage, not yours.}
\end{itemize}

\hd{Remember}
\textbf{Container $\to$ 3 DBs $\to$ zones $\to$ records.} Custom zone = atomic + tokens
+ share; stale tag = merge.
