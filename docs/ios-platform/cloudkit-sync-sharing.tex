\sheettitle{CloudKit sync \& sharing — CKSyncEngine, mirroring, CKShare}{ios-platform · folio}

\oneliner{Three ways to sync: \textbf{CKSyncEngine} (iOS 17) — \emph{your} store, the engine
schedules push/fetch and you persist its state; \textbf{NSPersistentCloudKitContainer} (iOS 13) —
Core Data \emph{mirrors} itself into a zone, no sync code; \textbf{SwiftData} — the same mirror,
private database only. \textbf{Sharing}: a \ct{CKShare} in the owner's private custom zone
covers one \textbf{record hierarchy} or the \textbf{whole zone}; an accepted share shows up in the
participant's \textbf{shared database}, and their writes land in the \emph{owner's} zone.}

\hd{CKSyncEngine — how it works (iOS 17)}
\begin{itemize}
  \item Create it early at launch with the saved \ct{stateSerialization} — in any account state;
        it stays dormant until someone is signed in. Not for the public DB.
  \item Queue work: \ct{.saveRecord(id)} / \ct{.deleteRecord(id)}; zones via
        \ct{add(pendingDatabaseChanges: [.saveZone(z)])}. Build batches with
        \ct{RecordZoneChangeBatch(pendingChanges:\allowbreak recordProvider:)} — it stops at the limit.
  \item Schedule is \emph{indeterminate} (battery, network): pull-to-refresh $\to$
        \ct{fetchChanges()}, ``back up now'' $\to$ \ct{sendChanges()}; tests: \ct{automaticallySync = false}.
  \item Keep each record's system fields (change tag) beside your row, or every save conflicts.
\end{itemize}

\hd{Example — the delegate}
\begin{lstlisting}[language=SwiftSheet]
final class Sync: CKSyncEngineDelegate {
  var engine: CKSyncEngine!
  init(db: CKDatabase, saved: CKSyncEngine.State.Serialization?) {
    engine = CKSyncEngine(.init(database: db,
               stateSerialization: saved, delegate: self)) }
  func edited(_ id: CKRecord.ID) {        // after the local write
    engine.state.add(pendingRecordZoneChanges: [.saveRecord(id)]) }
  func handleEvent(_ e: CKSyncEngine.Event,
                   syncEngine: CKSyncEngine) async {
    switch e {
    case .stateUpdate(let u): store.persist(u.stateSerialization)
    case .fetchedRecordZoneChanges(let c): store.apply(c)
    case .sentRecordZoneChanges(let s): merge(s.failedRecordSaves)
    case .accountChange(let a): store.handle(a.changeType)
    default: break } }
  func nextRecordZoneChangeBatch(_ ctx: CKSyncEngine.SendChangesContext,
      syncEngine: CKSyncEngine) async -> CKSyncEngine.RecordZoneChangeBatch? {
    let todo = syncEngine.state.pendingRecordZoneChanges
                 .filter { ctx.options.scope.contains($0) }
    return await .init(pendingChanges: todo) { store.record(for: $0) } }
}
\end{lstlisting}

\hd{Traps}
\begin{itemize}
  \trap{Not persisting \ct{.stateUpdate} — every launch refetches everything.}
  \trap{A pending \ct{CKRecord.ID} built without its \ct{zoneID} means the default zone — the engine keeps resending\unverified.}
  \trap{SwiftData + an iCloud entitlement syncs \emph{by default}; a \ct{.unique} model then fails to load.}
  \trap{No \ct{CKSharingSupported} in Info.plist — the share link never opens your app.}
  \trap{A child linked by your own reference field is \emph{not} in a hierarchy share — set \ct{parent}.}
\end{itemize}

\hd{Core Data mirroring — \ct{NSPersistentCloudKitContainer}}
\begin{itemize}
  \item Swap the class; capabilities iCloud/CloudKit + \emph{Remote notifications}. Per store
        description: \ct{cloudKitContainerOptions} (\ct{containerIdentifier}, \ct{databaseScope}
        \ct{.private} · \ct{.public} · \ct{.shared}). Model configurations keep entities local.
  \item Runs off \textbf{persistent history}: set \ct{NSPersistentHistoryTrackingKey} + the
        remote-change key, \ct{automaticallyMergesChangesFromParent = true}, a merge policy.
  \item \textbf{Model rules}: no unique constraints; attributes optional \emph{or} defaulted;
        relationships optional \emph{with an inverse} (records arrive out of order); no
        \textbf{Deny}; no ordered relationships\unverified.
  \item \ct{initializeCloudKitSchema()} (DEBUG only) uploads sample records so Development has
        every field — then \emph{Deploy}. Errors: \ct{eventChangedNotification}.
  \item Sharing (iOS 15): 2nd store with \ct{.shared} scope; \ct{share(\_:to:)},
        \ct{acceptShareInvitations(from:into:)}, \ct{persistUpdatedShare}, \ct{fetchShares}.
\end{itemize}

\hd{SwiftData + CloudKit}
The same mirror. \ct{ModelConfiguration(cloudKitDatabase:)}: \ct{.automatic} (\textbf{default} —
first container in the entitlements) · \ct{.private("iCloud.com.example.app")} · \ct{.none}.
Same model rules. Private DB only: no public DB, no sharing API.

\hd{Sharing — CKShare}
\begin{itemize}
  \item \textbf{Hierarchy}: \ct{CKShare(rootRecord:)}; children by \ct{setParent(\_:)}; save share
        with the root. \textbf{Zone-wide} (iOS 15): \ct{CKShare(recordZoneID:)}. A record is in
        \textbf{one} share, else \ct{alreadyShared}.
  \item $\leq$ 100 participants, each with iCloud. \ct{.readOnly} / \ct{.readWrite}; roles
        \ct{.owner} · \ct{.privateUser} (invited) · \ct{.publicUser} (\ct{publicPermission}
        $>$ \ct{.none}: anyone with the link) · \ct{.administrator} (iOS 26, with
        \ct{allowsAccessRequests}).
  \item UI: \ct{ShareLink} + \ct{CKShareTransferRepresentation} (iOS 16);
        \ct{UICloudSharingController(share:container:)} manages people;
        \ct{CKShare.SystemFieldKey.title} names the invite.
  \item Only the owner deletes the root; a participant deleting the share just leaves.
\end{itemize}

\hd{Remember}
\textbf{Engine: you store, it schedules. Mirror: it does both, you obey its model rules. A share
lives in the owner's zone.}
