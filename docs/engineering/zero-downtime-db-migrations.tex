\sheettitle{Zero-downtime database migrations}{engineering · folio}

\oneliner{Every schema change must be tolerated by \textbf{all code that is still running} — the old pods of a
rolling deploy, the blue stack you may roll back to, and \textbf{app versions installed on phones for months}.
So a breaking change becomes \textbf{expand $\to$ migrate $\to$ contract} across several releases, data moves
in \textbf{small batches}, and every DDL holds its lock for \textbf{milliseconds}.}

\begin{multicols}{2}
\raggedright\setstretch{1.0}

\hd{Why every breaking change takes several releases}
\begin{itemize}
  \item A \textbf{rolling deploy} runs N and N+1 against one DB; a \textbf{blue/green rollback} brings N back;
        \textbf{mobile clients} are version N-k for months. A rename in one step breaks at least one of them.
  \item Rule: schema $v$ must work with code N \emph{and} N+1; code N+1 must work with schema $v$ and $v$+1.
  \item Same for the API: add the field, keep the old one until its clients are gone; for app clients
        measure by version header, then raise the min version.
\end{itemize}

\hd{Expand / contract — rename \ct{name} $\to$ \ct{full\_name}}
\begin{enumerate}
  \item \textbf{Expand}: add the column nullable (or constant default), tables, indexes. Old code ignores them.
  \item \textbf{Dual write} (N+1): write both, still read old. Or a DB trigger — keeps writes from old
        code in sync too.
  \item \textbf{Backfill} old rows in batches (below). Verify: counts, checksums, sample diffs.
  \item \textbf{Switch reads} (N+2); then constraints: \ct{NOT NULL}, FK, unique.
  \item \textbf{Stop writing} the old column; make the ORM ignore it (Rails \ct{ignored\_columns}) or its
        cached column list breaks on drop.
  \item \textbf{Contract}: drop column / trigger — after rollback window + old clients.
\end{enumerate}

\hd{Backfill — batches, not one \ct{UPDATE}}
One \ct{UPDATE} of 50\,M rows = one huge transaction: row locks held for its whole length, WAL burst,
replica lag, dead tuples. Instead: keyset batches (1–10k rows by PK), commit each, sleep, throttle on
replica lag; \textbf{idempotent} (\ct{WHERE full\_name IS NULL}) and \textbf{resumable}; run as a job, not
inside the deploy.

\hd{MySQL}
\ct{ALGORITHM=INSTANT} ADD/DROP COLUMN (default in 8.4, any position; 64 row versions, then a rebuild).
Other changes: \textbf{gh-ost} — triggerless: copies into a ghost table and applies the \textbf{binlog}
stream; throttle / pause, cut-over when \emph{you} choose; \textbf{pt-online-schema-change} — same copy,
but \textbf{triggers} on the live table (extra write load). Both end with an atomic \ct{RENAME}.

\hd{Dual writes vs CDC (moving data to a new store)}
App \textbf{dual write} = two non-atomic writes: one fails or reorders $\Rightarrow$ silent drift; needs
reconciliation. \textbf{CDC} (Debezium-style reading WAL/binlog) or a \textbf{transactional outbox}: one
source of truth, ordered by log position, replayable. Snapshot + stream $\to$ verify $\to$ switch reads $\to$
switch writes.

\hd{Order around deploys · rollback}
\textbf{Expand before} the code that needs it (old code must survive it); \textbf{contract after} the old code
and the rollback window are gone. One migrator with an advisory lock — not every pod at start-up. A
``down'' migration after data is written loses data: roll \textbf{forward}; contract is the only one-way
door, so back up (PITR) before it.

\hd{PostgreSQL — which lock, which trick}
{\footnotesize\setlength{\tabcolsep}{2.5pt}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{27mm}>{\raggedright\arraybackslash}p{46mm}@{}}
\toprule
\textbf{statement} & \textbf{lock · safe form}\\ \midrule
most \ct{ALTER TABLE} & \textbf{ACCESS EXCLUSIVE}: blocks reads \emph{and} writes — must be instant\\
\ct{ADD COLUMN … DEFAULT} & PG 11+: constant default kept in metadata, no rewrite; \emph{volatile}
  (\ct{clock\_timestamp()}) rewrites\\
\ct{ALTER COLUMN TYPE} & rewrite + index rebuild, unless binary coercible (\ct{varchar(n)} $\to$ \ct{text})\\
\ct{CREATE INDEX} & SHARE: blocks writes $\to$ \ct{CONCURRENTLY}\\
\ct{ADD CONSTRAINT … CHECK / FOREIGN KEY} & \ct{NOT VALID} (instant) then \ct{VALIDATE CONSTRAINT} (SHARE UPDATE
  EXCLUSIVE: reads + writes go on). FK locks \emph{both} tables\\
\ct{SET NOT NULL} & full scan — unless a valid \ct{CHECK (c IS NOT NULL)} proves it. PG 18: NOT NULL itself
  can be \ct{NOT VALID}\\
\ct{ADD PRIMARY KEY / UNIQUE} & build the unique index \ct{CONCURRENTLY}, then \ct{ADD CONSTRAINT … USING INDEX}\\
\bottomrule
\end{tabular}}

\hd{Example — PostgreSQL, one step per deploy}
\begin{lstlisting}[language=SQLSheet]
SET lock_timeout = '2s';   -- fail fast + retry, never queue
ALTER TABLE users ADD COLUMN full_name text;    -- metadata only
-- deploy N+1 (writes both); then repeat until 0 rows:
UPDATE users SET full_name = name WHERE id IN (SELECT id
  FROM users WHERE full_name IS NULL ORDER BY id LIMIT 5000);
ALTER TABLE users ADD CONSTRAINT full_name_nn
  CHECK (full_name IS NOT NULL) NOT VALID;       -- instant
ALTER TABLE users VALIDATE CONSTRAINT full_name_nn; -- no write lock
ALTER TABLE users ALTER full_name SET NOT NULL;  -- CHECK proves it
CREATE INDEX CONCURRENTLY users_full_name_idx ON users (full_name);
-- deploy N+2; weeks later, when N, N+1 and app 5.1 are gone:
ALTER TABLE users DROP COLUMN name;             -- contract
\end{lstlisting}

\hd{The lock queue — how a 1 ms ALTER causes an outage}
The \ct{ALTER} waits for ACCESS EXCLUSIVE behind one long \ct{SELECT} or an \emph{idle in transaction}
session; every query that arrives \emph{after} it queues behind the \ct{ALTER}. \ct{lock\_timeout} applies to each
lock attempt: give up after 1–5\,s, retry with backoff. \ct{CONCURRENTLY}: two scans, waits for old
transactions, not inside a transaction block (turn off the tool's wrapping txn), failure leaves an
\textbf{INVALID} index — drop it and retry, or \ct{REINDEX INDEX CONCURRENTLY}.

\hd{Traps}
\begin{itemize}
  \trap{Rename / drop in the same release as the code change: old pods and old apps crash.}
  \trap{New \ct{NOT NULL} column with no default: old code's \ct{INSERT}s fail.}
  \trap{``The ALTER is instant'' — not while it waits in the lock queue.}
\end{itemize}

\hd{Remember}
\textbf{Add, write both, backfill, read new, stop old, drop — each its own deploy.}
