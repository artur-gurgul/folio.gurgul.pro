\sheettitle{Typed contracts across iOS, Android, web \& backend}{engineering · folio}

\oneliner{Teams stop arguing about JSON when \textbf{one machine-readable schema} — OpenAPI,
GraphQL SDL, Protobuf or JSON Schema — is the \textbf{source of truth} in version control:
every client and the server \textbf{generate} their types from it, CI \textbf{rejects breaking
diffs}, and \textbf{contract tests} prove the provider still serves what each consumer uses —
a mismatch fails a build, not a user's app.}

\hd{The four contract languages}
{\footnotesize
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{13mm}>{\raggedright\arraybackslash}p{30mm}>{\raggedright\arraybackslash}p{31mm}@{}}
\toprule
 & \textbf{shape} & \textbf{evolution rule} \\ \midrule
OpenAPI & REST/JSON; 3.1 = JSON Schema 2020-12 inside & add optional fields; \ct{deprecated: true}; breaking $\to$ new path/version \\
GraphQL & one typed graph; clients pick fields per operation & never version: add fields, \ct{@deprecated(reason:)}, remove when unused \\
Protobuf & binary; \textbf{field numbers} are the wire identity & never reuse a number (\ct{reserved 3}); unknown fields are kept \\
JSON Schema & payloads, events, config; validates at runtime & same as OpenAPI; codegen via quicktype etc. \\
\bottomrule
\end{tabular}}

\hd{Safe vs breaking — the table that matters}
{\footnotesize
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{37mm}>{\raggedright\arraybackslash}p{37mm}@{}}
\toprule
\textcolor{sheetGreen!60!black}{\textbf{safe}} & \textcolor{sheetRed}{\textbf{breaking}} \\ \midrule
add endpoint / operation & remove or rename a field / path \\
add \emph{optional} response field & change a type (\ct{int} $\to$ \ct{string}) \\
add optional request field & make a request field required \\
loosen validation & tighten validation, shrink limits \\
add enum case \emph{if clients tolerate unknowns} & add enum case for strict decoders \\
\bottomrule
\end{tabular}}
Mobile twist: old builds live for \textbf{years} — judge ``breaking'' against every one.

\hd{Example — OpenAPI $\to$ Swift, generated at build time}
\begin{lstlisting}[language=YamlSheet]
paths:
  /orders/{id}:
    get:
      operationId: getOrder
      parameters: [{name: id, in: path, required: true,
                    schema: {type: string}}]
      responses:
        '200': {content: {application/json:
                  {schema: {$ref: '#/components/schemas/Order'}}}}
# openapi-generator-config.yaml (beside it, in the target)
generate: [types, client]
accessModifier: internal
\end{lstlisting}
\begin{lstlisting}[language=SwiftSheet]
let client = Client(serverURL: URL(string: "https://api.example.com")!,
                    transport: URLSessionTransport())
switch try await client.getOrder(path: .init(id: "42")) {
case .ok(let ok):   let order = try ok.body.json  // Components.Schemas.Order
case .undocumented(let status, _): throw APIError.unexpected(status)
}
\end{lstlisting}
swift-openapi-generator (Apple): SwiftPM \textbf{build plugin}, OpenAPI 3.0/3.1 (3.2
preliminary), transports for URLSession, AsyncHTTPClient, Vapor, Hummingbird; nothing
generated is committed; every status is an enum case.

\hd{Contract tests — what they prove}
\begin{itemize}
  \item \textbf{Schema checks} prove the \emph{shape} is compatible. \textbf{Consumer-driven
        contracts} (Pact) prove the provider still serves what each consumer \emph{actually
        uses} — the consumer's test writes the contract, the provider's CI replays it.
  \item \textbf{Provider states} (``given order 42 exists'') seed each replay;
        \ct{can-i-deploy} asks the broker if this version fits what is deployed — a gate for
        both sides.
  \item Pact $\neq$ E2E: contracts, not business behaviour. Bi-directional: pact vs OpenAPI.
\end{itemize}

\columnbreak

\hd{Versioning and deprecation}
\begin{itemize}
  \item Prefer \textbf{additive evolution}, no version bump. Breaking: new field/endpoint beside
        the old, or \ct{/v2}, or a dated header version (Stripe style).
  \item Deprecate in the schema, then on the wire: \ct{Deprecation: @1688169599} (RFC 9745,
        2025) + \ct{Sunset:} (RFC 8594) — sunset never earlier than deprecation.
  \item Measure usage \textbf{per app version} (\ct{User-Agent}, an app-version header); remove only
        when traffic is \textasciitilde0 or a \textbf{minimum-version / force-update} gate covers it.
\end{itemize}

\hd{Sharing models with React Native}
\begin{itemize}
  \item JS layer: TS types from the same schema (openapi-typescript, GraphQL Code Generator),
        not hand-written DTOs.
  \item JS $\leftrightarrow$ native: the \textbf{TurboModule TS spec} is itself a typed
        contract — Codegen emits the ObjC++/Java interfaces; a mismatch fails the native
        build. Alternatives: KMP shared models for Android + iOS.
\end{itemize}

\hd{API review process}
RFC with the schema diff $\to$ CODEOWNERS from each client team $\to$ lint + breaking check
block the merge $\to$ mock + SDKs published $\to$ changelog $\to$ deprecation window in app
adoption, not weeks.

\hd{Traps}
\begin{itemize}
  \trap{``Adding an enum value is backward compatible'' — a strict \ct{Codable} enum throws and
        the \emph{whole} response fails. Decode unknowns to \ct{.unknown}.}
  \trap{Server sends \ct{null} where the schema says non-nullable — the decoder fails. Validate
        responses against the schema in backend tests, or the spec drifts.}
  \trap{Renaming a proto field is wire-safe for binary but breaks ProtoJSON and generated
        names; reusing a field number silently corrupts data.}
  \trap{Hand-editing generated code — overwritten next build; extend it instead.}
\end{itemize}

\hd{Remember}
\textbf{One schema, many generators; CI says no before users do; add, don't change; retire by
version telemetry.}
