\sheettitle{Lint \& static analysis — where each check runs}{engineering · folio}

\oneliner{A linter is a \textbf{program that reads your source} and reports patterns;
\textbf{syntax-only} rules (SwiftLint lint, ESLint core, ktlint) are fast and run on every save,
\textbf{type-aware} ones (SwiftLint \ct{analyze}, typescript-eslint typed rules, detekt with type
resolution) need a compile and run in CI. A \textbf{formatter} rewrites layout and ends style
debate. What works is the \textbf{pipeline}: the right check at the cheapest stage, one
\textbf{blocking} gate in CI, a \textbf{baseline} for old code, and a written \textbf{suppression policy}.}

\hd{Swift / iOS}
\begin{itemize}
  \item \textbf{SwiftLint} (\ct{.swiftlint.yml}): \ct{disabled\_rules}, \ct{opt\_in\_rules},
        \ct{only\_rules}, \ct{analyzer\_rules}, \ct{custom\_rules} (a \textbf{regex} +
        \ct{match\_kinds} + \ct{message} + \ct{severity}); \ct{strict} = warnings are errors.
        Runs as an SPM \textbf{build tool plugin} (package \ct{SwiftLintPlugins}) or a run-script phase.
  \item \ct{swiftlint analyze \dd{}compiler-log-path xcodebuild.log}: \textbf{analyzer rules}
        (\ct{unused\_declaration}, \ct{unused\_import}) use the \emph{type-checked} AST, need
        the log of a \textbf{clean} build, and are much slower — CI only.
  \item \textbf{Formatter}: \textbf{swift-format} (swiftlang; \textbf{in the toolchain since Swift 6 /
        Xcode 16}: \ct{swift format -i}, \ct{swift format lint \dd{}strict}, JSON
        \ct{.swift-format}) \emph{vs} \textbf{SwiftFormat} (Nick Lockwood, community, more rules,
        \ct{.swiftformat}, \ct{\dd{}lint} mode). Pick \emph{one}; let SwiftLint skip style rules it
        already fixes.
  \item \textbf{Compiler} (SE-0443, Swift 6.1): \ct{-warnings-as-errors -Wwarning
        DeprecatedDeclaration} = all errors \emph{except} one group; \ct{-Werror <group>} the
        reverse; \textbf{last flag wins}; \ct{-print-diagnostic-groups} shows the group name.
  \item \textbf{Clang static analyzer} (Product $\to$ Analyze, or ``Analyze During Build''):
        path-sensitive checks for \textbf{C / Obj-C} — leaks, null derefs, use-after-free.
        It does not analyse Swift.
\end{itemize}

\hd{Example — the two configs that matter}
\begin{lstlisting}[language=CfgSheet]
# .swiftlint.yml
opt_in_rules: [force_unwrapping, empty_count]
analyzer_rules: [unused_declaration, unused_import]
excluded: [Pods, .build, "**/Generated"]
custom_rules:
  no_print:
    regex: "\\bprint\\("
    match_kinds: [identifier]
    message: "Use Logger, not print()"
    severity: error
\end{lstlisting}
\begin{lstlisting}[language=CfgSheet]
// eslint.config.js (flat config)
import { defineConfig } from 'eslint/config';
import tseslint from 'typescript-eslint';
import reactHooks from 'eslint-plugin-react-hooks';
import prettier from 'eslint-config-prettier';
export default defineConfig([
  tseslint.configs.recommendedTypeChecked,
  reactHooks.configs.flat.recommended,
  { languageOptions: { parserOptions: { projectService: true } },
    linterOptions: { reportUnusedDisableDirectives: 'error' },
    rules: { '@typescript-eslint/no-floating-promises': 'error' } },
  prettier,            // LAST: turns off every style rule
]);
\end{lstlisting}

\hd{Example — the CI lint job (cheapest first, fail fast)}
\begin{lstlisting}[language=CfgSheet]
swift format lint --strict --recursive Sources
swiftlint lint --strict --reporter github-actions-logging
xcodebuild clean build -scheme App ... > xcodebuild.log
swiftlint analyze --strict --compiler-log-path xcodebuild.log
npx prettier --check .  &&  npx tsc --noEmit
npx eslint . --max-warnings 0     # warnings fail too
./gradlew detekt lint             # android/
npx danger ci                     # PR comments, fail()
\end{lstlisting}

\hd{Remember}
\textbf{Format on save · lint the staged files · gate in CI · baseline the past · every
suppression names a rule and a reason.}

\hd{JavaScript / TypeScript / React Native}
\begin{itemize}
  \item \textbf{ESLint} flat config (\ct{eslint.config.js}, default since ESLint 9): an array of
        config objects, later ones override earlier; plugins are imported objects, not strings.
  \item \textbf{typescript-eslint} \ct{recommendedTypeChecked} + \ct{projectService: true} asks
        TypeScript for types: \ct{no-floating-promises} (an un-\ct{await}ed promise),
        \ct{no-misused-promises} (async fn in \ct{onPress} expecting \ct{void}),
        \ct{switch-exhaustiveness-check}. Cost: a TS program build before linting.
  \item \textbf{eslint-plugin-react-hooks}: \ct{rules-of-hooks}, \ct{exhaustive-deps} + the
        \textbf{React Compiler} rules in \ct{recommended}/\ct{recommended-latest} (\ct{purity},
        \ct{refs}, \ct{immutability}, \ct{set-state-in-render}, \ct{set-state-in-effect},
        \ct{static-components}\ldots; flat: \ct{configs.flat.recommended}).
        \ct{eslint-plugin-react-compiler} is superseded by it.
  \item \textbf{Prettier} = formatter only; \ct{eslint-config-prettier} last in the config
        disables ESLint's style rules, so the two never fight. CI: \ct{prettier \dd{}check}.
  \item \textbf{Types are the biggest static analyser}: \ct{tsc \dd{}noEmit} in CI
        (Metro/Babel only strip types) — strict flags: see ts-config-and-practice.
\end{itemize}

\hd{PR bots, hooks, gates}
\begin{itemize}
  \item \textbf{Danger} (JS; also Danger Swift): a \ct{dangerfile} runs in CI with the PR
        (\ct{danger.github.pr}) and posts \ct{message}/\ct{warn}/\ct{fail}: ``no CHANGELOG'',
        ``PR $>$ 500 lines'', ``lockfile changed without \ct{package.json}'', SwiftLint results
        inline. \textbf{Judgement rules} a linter can't express.
  \item \textbf{Hooks}: husky (\ct{.husky/pre-commit}) + \textbf{lint-staged} (per-glob commands
        on staged files) · \textbf{lefthook} (Go binary, one \ct{lefthook.yml}, \ct{parallel},
        \ct{\{staged\_files\}}; no Node needed — good for iOS repos). Hooks are
        \textbf{convenience}: \ct{\dd{}no-verify} skips them, so CI repeats every check.
  \item \textbf{Ratchet}: turning a rule on in a big repo = thousands of hits. Baseline them
        (SwiftLint \ct{write\_baseline}/\ct{baseline}, detekt, Android Lint), block only
        \textbf{new} violations, burn the baseline down.
\end{itemize}

\hd{Suppressions policy}
Narrowest scope + rule id + reason: \ct{// swiftlint:disable:next force\_cast} ·
\ct{// eslint-disable-next-line no-console \dd{} CLI output} · \ct{@Suppress("MagicNumber")}.
Ban blanket \ct{swiftlint:disable all} / bare \ct{eslint-disable}; report \textbf{unused}
directives (\ct{superfluous\_disable\_command}, \ct{reportUnusedDisableDirectives}); count them in CI.

\hd{Traps}
\begin{itemize}
  \trap{Warnings nobody fails on grow forever — a warning is either an \textbf{error} or \textbf{off}.}
  \trap{Pre-commit as the gate: skippable, per-machine versions. \textbf{CI} is the gate.}
  \trap{Running \ct{analyze} / typed ESLint on every keystroke — slow; they need a build.}
  \trap{ESLint \emph{and} Prettier both formatting — endless diffs; one owner per concern.}
  \trap{Fixing lint in a 3,000-file ``cleanup PR'' — ruins \ct{git blame}; baseline + ratchet.}
\end{itemize}
