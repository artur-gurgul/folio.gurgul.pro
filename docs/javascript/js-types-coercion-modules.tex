\section{Types and the four conversions}
\begin{itemize}
  \item Primitives: \ct{undefined null boolean number string}, \ct{symbol} (ES2015),
        \ct{bigint} (ES2020). All else is an \textbf{object}: arrays, functions, wrappers
        (\ct{new Boolean(false)} is truthy). \ct{"a".length} goes through a temporary wrapper.
        Assignment and arguments copy the value; for an object that value is a reference —
        mutating a parameter shows in the caller, reassigning it does not.
  \item \ct{typeof} on an undeclared name $\to$ \ct{"undefined"}; on a \ct{let}/\ct{const} in
        its TDZ $\to$ ReferenceError. Browsers' \ct{document.all} (Annex B) is the one object
        with \ct{typeof} \ct{"undefined"}, falsy and \ct{\eqq{} null}. Better tests:
        \ct{x \eqq{} null} · \ct{Array.isArray} (cross-realm, unlike \ct{instanceof}) ·
        \ct{Object.prototype.toString.call(null)} $\to$ \ct{"[object Null]"} ·
        \ct{Number.isNaN} (\ct{isNaN("abc")} is \ct{true}).
\end{itemize}

\section{Numbers and BigInt}
\begin{itemize}
  \item \ct{number} = IEEE-754 double: integers exact to \ct{MAX\_SAFE\_INTEGER} $= 2^{53}-1$
        $= 9007199254740991$; \ct{2\pw53 + 1 \eqqq{} 2\pw53}. \ct{0.1 + 0.2} $\to$
        \ct{0.30000000000000004}. \ct{Number.EPSILON} $= 2^{-52}$, the gap after 1 — scale it.
  \item \ct{-0 \eqqq{} 0}, but \ct{1/-0} $\to$ \ct{-Infinity}, \ct{Object.is(-0, 0)} false,
        \ct{String(-0)} \ct{"0"}. \ct{Math.round} ties go to $+\infty$: \ct{2.5} $\to$ 3,
        \ct{-2.5} $\to$ \ct{-2}. Bitwise ops use ToInt32 (\ct{\ush}: ToUint32): \ct{2\pw31 | 0} $\to$
        \ct{-2147483648}; \ct{-1 \ush{} 0} $\to$ \ct{4294967295}.
  \item \ct{BigInt} (\ct{10n}, ES2020): \ct{1n + 1}, \ct{+1n}, \ct{Math.max(1n)} throw
        TypeError, but \ct{1n < 1.5} and \ct{1n \eqq{} 1} work. \ct{/} truncates
        (\ct{-7n / 2n} $\to$ \ct{-3n}); \ct{BigInt(1.5)} RangeError. \ct{JSON.stringify(1n)}
        throws; ES2026: \ct{JSON.rawJSON(String(v))} writes it, reviver \ct{\{source\}} reads it.
\end{itemize}

\section{\ct{\qq}, \ct{\oo}, \ct{\qd} and defaults}
\begin{itemize}
  \item \ct{a \oo{} d} takes \ct{d} for \emph{any} falsy \ct{a} (\ct{0}, \ct{""} lost);
        \ct{a \qq{} d} only for \ct{null}/\ct{undefined} (ES2020, like \ct{\qd}); \ct{a \qq{} b \oo{} c}
        without parentheses is a SyntaxError. Parameter and destructuring defaults fire only
        for \ct{undefined}: \ct{f(null)} keeps \ct{null}.
  \item One \ct{\qd} short-circuits the \emph{whole} chain: \ct{a\qd b.c.d}; \ct{(a\qd b).c}
        throws. \ct{a\qd b = 1}, \ct{new a\qd()} are SyntaxErrors.
        \ct{x \ooe{} d}, \ct{\ane}, \ct{\qqe} (ES2021) assign only when needed.
\end{itemize}

\section{ES modules — load, link, evaluate}
\begin{itemize}
  \item \textbf{Load} parses the whole graph; \textbf{Link} binds every import to an export —
        a missing name is a SyntaxError before any module of the graph runs; functions are
        ready, \ct{let}/\ct{const}/\ct{class} not; \textbf{Evaluate} runs dependencies
        first, each module once. Always strict; top-level \ct{this} is \ct{undefined}.
  \item \ct{import * as ns}: null prototype, sorted keys, tag \ct{"Module"}, assigning
        throws. Cached per URL (Node: new \ct{?query}, new instance); browser: deferred, CORS.
  \item \ct{import(expr)} (ES2020) works in scripts and CommonJS too; a promise of the
        namespace. \textbf{ES2025}: \ct{import c from "./c.json" with \{ type: "json" \}}
        (default export only; \ct{import(p, \{ with: \{\spr\} \})}).
  \item \textbf{Cycles}: CJS hands the requirer the \emph{unfinished} \ct{exports} (missing
        keys \ct{undefined}); ESM links fine, but reading a \ct{let}/\ct{const}/\ct{class}
        export before its module ran throws ReferenceError; functions already work.
\end{itemize}

  \item \ct{.mjs} ESM · \ct{.cjs} CJS · \ct{.js} $\to$ nearest \ct{package.json}
        \ct{"type"}, else syntax detection (default since 22.7; slower — set \ct{"type"}).
  \item \textbf{import CJS}: default is \emph{always} \ct{module.exports}; named imports only
        where static analysis finds them. Compiled \ct{\_\_esModule} code: the real default
        sits at \ct{x.default}.
  \item \textbf{\ct{require(esm)}}: the namespace (\ct{.default}; \ct{\_\_esModule: true} added
        when a default exists); \ct{export \{ v as "module.exports" \}} returns \ct{v}. Unflagged
        22.12, stable 25.4; top-level await in its graph $\to$ \ct{ERR\_REQUIRE\_ASYNC\_MODULE}.
  \item ESM: no \ct{require}/\ct{\_\_dirname} — \ct{import.meta.dirname} (stable 24.0),
        \ct{createRequire(import.meta.url)}; extensions mandatory; \ct{assert \{\}} gone (22.0).
        Separate \ct{import}/\ct{require} entry files: \textbf{dual package hazard}.
\end{itemize}
