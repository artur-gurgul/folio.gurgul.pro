\sheettitle{Scope, closures and \texttt{this}}{javascript · folio}

\oneliner{Scope is \textbf{lexical}: fixed by where code is \emph{written}. Every function
keeps \ct{[[Environment]]}, the Environment Record it was created in; a closure is that link
keeping \textbf{bindings} (not values) alive. \ct{this} is \textbf{dynamic}: set by \emph{how
the function is called} and looked up in the nearest record that has one — arrows have none,
so they see the enclosing \ct{this}.}

\section{Environment Records — the scope chain}
\begin{itemize}
  \item A record maps names $\rightarrow$ bindings; \ct{[[OuterEnv]]} links it to the enclosing
        one. Lookup walks that chain; a name found nowhere $\rightarrow$ ReferenceError on read,
        \ct{"undefined"} from \ct{typeof}, a new global property on sloppy assignment.
  \item \textbf{Declarative} (block, \ct{catch}, \ct{let const class}) and its two kinds:
        \textbf{Function} (+ \ct{[[ThisValue]]}, \ct{[[ThisBindingStatus]]} lexical / initialized /
        uninitialized, \ct{[[NewTarget]]}) and \textbf{Module} (imports as live indirect
        bindings; \ct{this} = \ct{undefined}). \textbf{Object} (\ct{with}). \textbf{Global} = an Object
        record over the global object (\ct{var}, \ct{function}) + a Declarative record
        (\ct{let const class}) + \ct{[[GlobalThisValue]]}.
  \item One \textbf{execution context} per script, module or call: code state, Function, Realm,
        ScriptOrModule, LexicalEnvironment, VariableEnvironment, PrivateEnvironment
        (\ct{\#names}, ES2022), Generator. \ct{this} is \emph{not} a field of it (ES5's
        ThisBinding was): ResolveThisBinding walks outward to the first record that has one.
  \item A \textbf{function object} carries \ct{[[Environment]]} (the closure), \ct{[[ThisMode]]}
        (\emph{lexical} = arrow, \emph{strict}, \emph{global} = sloppy), \ct{[[HomeObject]]} (for
        \ct{super}), \ct{[[Realm]]}.
\end{itemize}

\begin{itemize}
  \item \textbf{TDZ} is \emph{temporal}: from scope entry until the declaration
        \emph{executes}. A closure called after \ct{let x = 1} ran may read \ct{x} though written
        above it. \ct{typeof x} in the TDZ throws; \ct{let x = x} throws; all \ct{case}s of a
        \ct{switch} share one block.
  \item \textbf{Redeclaring}: \ct{var} + \ct{var} / \ct{function} is allowed (\ct{var a = 1;
        function a()\{\}} $\rightarrow$ \ct{a} is 1); \ct{let const class import} + anything in the
        same scope is an early SyntaxError — nothing runs. Classic scripts share one global
        lexical scope: \ct{let x} in two \ct{<script>}s throws in the second.
  \item Script top level: \ct{var} / \ct{function} become \textbf{non-configurable}
        \ct{globalThis} properties (\ct{delete} fails); sloppy \ct{x = 1} makes a configurable
        one; \ct{let const class} make none. A module (or CommonJS file) keeps its top level to
        itself.
\end{itemize}

\section{Closures — what is kept}
\begin{itemize}
  \item The \textbf{binding}, shared: a later write is seen by every closure over it. To fix a
        value, pass it as an argument or copy it into a \ct{const} inside the loop body. React's
        stale closure is a render's old bindings.
  \item \ct{for-of} / \ct{for-in} with \ct{let}/\ct{const}: a fresh record each turn.
        \ct{for(let;;)}: copied per iteration (drawing 2). \ct{var}: one binding.
  \item \textbf{Default parameters} get their own scope: closures in the parameter list never
        see the body's \ct{var}s.
  \item Named function expression \ct{function fact()\{\}}: \ct{fact} is an
        \textbf{immutable} binding visible only inside; \ct{fact = 1} is ignored (sloppy) or a
        TypeError (strict).
  \item \textbf{Dynamic code}: direct \ct{eval(s)} sees the local scope (sloppy: its \ct{var}s
        land in the caller); indirect \ct{(0, eval)(s)} and \ct{new Function(s)} see
        \textbf{only the global} scope.
  \item \textbf{V8}: variables an inner function references move into a heap
        \textbf{context}; every closure made in that scope points at that one context, so a big
        array captured by one closure lives as long as \emph{any} of them. Leaks are
        reachability: a listener, timer or cache holding a closure.
\end{itemize}

\section{Traps}
\begin{itemize}
  \trap{``\ct{let}/\ct{const} aren't hoisted'' — they are, uninitialised (TDZ).}
  \trap{``A closure copies the value'' — it keeps the variable (3 3 3).}
  \trap{An arrow as an object method: \ct{\{ n: 1, m: () \fat{} this.n \}} reads the outer
        \ct{this}.}
\end{itemize}

\section{\texttt{this} — the details}
\begin{itemize}
  \item \textbf{Arrows}: no own \ct{this}, \ct{arguments}, \ct{super}, \ct{new.target}; no
        \ct{prototype}; \ct{new} $\rightarrow$ TypeError; call / apply / bind ignore the
        thisArg (bind still pre-fills arguments). An arrow \emph{property} of an object literal
        sees the \ct{this} outside the literal.
  \item \textbf{Lost \ct{this}}: \ct{arr.forEach(o.m)}, \ct{const \{m\} = o},
        \ct{setTimeout(o.m)} hand over a value, not a reference. Fixes: \ct{o.m.bind(o)},
        \ct{() \fat{} o.m()}, an arrow class field \ct{onTap = () \fat{} this.go()} — fixed for life,
        but one closure per instance, not on the prototype.
  \item \textbf{bind} is permanent: call, apply and a second bind cannot change it; \ct{new}
        ignores the bound \ct{this} but keeps the bound arguments.
  \item \textbf{Classes} (always strict): instance field initialisers $\rightarrow$ the
        instance; static fields, static blocks, static methods $\rightarrow$ the class. Derived
        constructor: \ct{this} before \ct{super()} $\rightarrow$ ReferenceError, so is a second
        \ct{super()}.
  \item \ct{super} is fixed by \ct{[[HomeObject]]}, where the method is written: moving a
        method changes its \ct{this}, never its \ct{super}. Getters and setters get the object
        accessed \emph{through}, also via the prototype chain.
  \item \textbf{Hosts pick it for callbacks}: array iteration methods take a \ct{thisArg}
        (else \ct{undefined}); Promise reactions \ct{undefined}; DOM listeners
        \ct{currentTarget}; browser timers \ct{window}, even for a strict function.
\end{itemize}

\section{Strict mode (classes, modules: always)}
\ct{'use strict'} first in a script or function body. \ct{this} never substituted or boxed ·
undeclared assignment $\rightarrow$ ReferenceError ·
writing a read-only, getter-only or non-extensible property, \ct{delete} of a
non-configurable one $\rightarrow$ TypeError · \ct{with}, \ct{delete x}, duplicate parameters,
\ct{010}, \ct{"\textbackslash 045"}, \ct{eval}/\ct{arguments} as names $\rightarrow$ SyntaxError ·
\ct{arguments} no longer aliases parameters (also unaliased whenever parameters are not
simple); \ct{arguments.callee} $\rightarrow$ TypeError · \ct{eval}'s \ct{var}s stay inside it ·
\ct{'use strict'} in a function with default, rest or destructured parameters $\rightarrow$
SyntaxError.

\section{\texttt{using} (ES2027)}
\ct{using r = open()}: \ct{const}-like, block-scoped, TDZ. At block exit calls
\ct{r[Symbol.dispose]()}, last declared first; \ct{null}/\ct{undefined} allowed, any other value
without the method $\rightarrow$ TypeError; errors chain into a \ct{SuppressedError}. Allowed in
blocks, function bodies, static blocks, a module's top level, \ct{for} / \ct{for-of} heads; not at
a classic script's top level, not directly in a \ct{switch}, no destructuring. \ct{await using}
awaits \ct{[Symbol.asyncDispose]()}, falling back to \ct{[Symbol.dispose]()}.
