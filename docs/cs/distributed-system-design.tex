Algorithms: round-robin (weighted), \textbf{least connections}, IP / consistent hash (affinity),
\textbf{two random choices} (nginx \ct{random two least\_conn}: draw 2, take the one with fewer
active connections; the shorter of two queues balances \emph{exponentially} better than one random

\ct{DELETE}, safe methods (RFC 9110); by default nginx does not resend a \ct{POST} / \ct{PATCH}
already sent. State in a server's memory breaks all of it → Redis / DB or a signed token.

\textbf{Delete, don't update} on write: deletes are idempotent; concurrent sets can land out of
order (a stale set). TTL bounds staleness. \textbf{Stampede}: recomputes ≈ request rate × recompute
time (10/s × 3 s = 30). Fixes: one recompute per key (lock / single-flight) + serve stale;
\textbf{leases} (memcache: one token per key per 10 s took peak DB load from 17K/s to 1.3K/s);
probabilistic early refresh (XFetch). Miss rate 10\,\% → 1\,\% = \textbf{10$\times$} less DB load.
Redis ships \ct{maxmemory-policy noeviction} (writes fail when full; a cache wants
\ct{allkeys-lru}) and \ct{appendonly no}.

\section{Replication, quorums, consensus}
\begin{itemize}
  \item \textbf{Leader–follower} (PostgreSQL): streaming replication is \textbf{async} by default —
        lag typically $<$1 s; a primary crash can lose committed transactions. \textbf{Sync}: commit
        waits for the standby's WAL flush, loss only if both crash; \ct{remote\_apply} waits until it
        is visible there; \ct{ANY 2 (s1,s2,s3)} = quorum commit.
  \item Lag breaks \textbf{read-your-writes}: read your own data from the leader, or wait until the
        replica's \ct{pg\_last\_wal\_replay\_lsn()} passes the write's LSN. \textbf{Monotonic reads}:
        pin a user to one replica. Redis replicates async; \ct{WAIT} does not make it CP.
  \item \textbf{Multi-region}: DynamoDB global tables settle conflicts ``last writer wins'' per item.
        A hot key meets a hard ceiling there: each partition serves at most 3,000 reads + 1,000
        writes per second (units of 4 KB / 1 KB).
  \item \textbf{Cross-shard} is the cost of sharding: Redis Cluster runs a multi-key command only
        when every key hashes to one slot — hash tags force it (\ct{\{u1\}.following},
        \ct{\{u1\}.followers}).
  \item \textbf{Leaderless} (Dynamo, Cassandra): N replicas, write W, read R; \textbf{W + R > N} ⇒ the
        sets overlap; Dynamo's usual (N,R,W) = (3,2,2); N=2, W=R=1 guarantees nothing.
        \textbf{Sloppy quorum}: the first N \emph{healthy} nodes + hinted handoff → ``always
        writeable'', conflicts reconciled on read — deleted items can resurface.
  \item \textbf{Raft}: $\leq$1 leader per term; an entry commits once on a \textbf{majority}; 2f+1
        servers survive f failures (5 → 2). Randomized election timeouts (e.g.\ 150–300 ms);
        broadcast (0.5–20 ms) \pdfonly{$\ll$}\htmlonly{≪} election timeout (10–500 ms)
        \pdfonly{$\ll$}\htmlonly{≪} MTBF (months).
  \item \textbf{Fencing}: a lock holder paused by GC past its lease still writes — the storage
        rejects token 33 once it has seen 34.
\end{itemize}

\section{Back-of-envelope}
1 day $\approx$ 10\textsuperscript{5} s → 1M requests/day $\approx$ 12 QPS; in flight = rate $\times$
latency (Little, $L = \lambda W$); storage $\times$ 3 replicas (HDFS default). Downtime:
\textbf{99.9\,\%} = 8.76 h/yr (43.2 min/month) · 99.99\,\% = 52.6 min/yr · 99.999\,\% = 5.26 min/yr;
serial dependencies multiply. Targets are percentiles: Dynamo's example SLA is 300 ms for 99.9\,\%
of requests at a peak of 500 req/s. \textbf{Example}: 10M DAU $\times$ 20 =
2$\times$10\textsuperscript{8}/day → $\sim$2,300 QPS, $\sim$7,000 at an assumed 3$\times$ peak,
$\sim$460 in flight at 0.2 s; 10\,\% post a 500 KB photo/day → 500 GB/day → $\sim$180 TB/yr,
$\times$3 $\approx$ 0.5 PB → object store + CDN.

\section{CAP, PACELC, consistency}
\textbf{CAP}: in a partition an operation refuses (\textbf{C}) or answers from what it has
(\textbf{A}). ``2 of 3'' ``was always misleading'' (Brewer, 2012): partitions are rare, the
choice is per operation, and ``a partition is a time bound on communication''. ATMs pick A:
stand-in mode caps net withdrawal (``k might be \$200''). \textbf{PACELC} (Abadi, 2010): if P, A or
C; \emph{else} \textbf{L}atency or \textbf{C}onsistency — Dynamo, Cassandra PA/EL · ACID PC/EC ·
PNUTS PC/EL.

Sticky = only while a client stays on one server (Jepsen). \textbf{TrueTime}: Spanner's
\ct{TT.now()} is an interval [earliest, latest] from GPS + atomic-clock masters, $\epsilon$
$\sim$1–7 ms (mean 4); \textbf{commit wait} until \ct{TT.after(s)} (\pdfonly{$\geq 2\bar{\epsilon}$}\htmlonly{≥ 2ε̄}, overlapped
with Paxos) buys external consistency. PostgreSQL: Read Committed by default; Serializable is SSI
and fails with \ct{40001} — retry the transaction.

\section{Traps}
\begin{itemize}
  \trap{CAP as ``pick two''; averages instead of p99 — fan-out makes the rare case common.}
  \trap{Reading a replica right after a write — the user's change vanishes.}
  \trap{Updating the cache on write; a lock without a fencing token.}
  \trap{Retrying a non-idempotent call without a key — charged twice.}
\end{itemize}

\section{Remember}
\textbf{Stateless → cache → replicate → shard → queue; a majority for truth.} For each: what goes
stale, what breaks, which number made it necessary.
