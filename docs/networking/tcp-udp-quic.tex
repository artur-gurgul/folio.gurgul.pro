\sheettitle{TCP · UDP · QUIC — handshakes, windows, and why QUIC exists}{networking · folio}

\oneliner{\textbf{TCP} turns lossy IP packets into one \textbf{reliable, ordered byte stream}: a 3-way
handshake agrees on sequence numbers, ACKs + retransmission recover loss, the \textbf{receive window}
protects the receiver (flow control), the \textbf{congestion window} protects the network. \textbf{UDP}
is ports + checksum and nothing else. \textbf{QUIC} rebuilds TCP's guarantees \emph{per stream} on
UDP with TLS 1.3 inside — 1-RTT setup, no cross-stream head-of-line blocking, survives an IP change.}

\hd{TCP}
\begin{itemize}
  \item \textbf{Header} (20–60 B): ports · \textbf{seq} (number of the first payload byte) ·
        \textbf{ack} (next byte expected) · flags \ct{SYN ACK FIN RST PSH URG ECE CWR} · 16-bit
        \textbf{window} · checksum · options (MSS, window scale $\leq$14 $\Rightarrow$ 1\,GiB, SACK,
        timestamps). The 4-tuple (IPs + ports) \emph{is} the connection.
  \item \textbf{Open}: random ISNs (anti-spoofing); SYN and FIN each consume a sequence number;
        MSS 1460 on a 1500-byte MTU (IPv4). \textbf{Close}: each direction separately (half-close)
        $\to$ 4 segments; the first closer holds \textbf{TIME\_WAIT} 2$\times$MSL (RFC MSL 2\,min;
        Linux 60\,s). \ct{RST} aborts at once.
  \item \textbf{Loss}: 3 duplicate ACKs $\to$ fast retransmit; RTO expiry $\to$ retransmit + slow
        start from 1 segment. \textbf{SACK} reports which ranges arrived.
  \item \textbf{Flow control} $\neq$ \textbf{congestion control}: \textbf{rwnd} $=$ receiver's free
        buffer, in every ACK (0 $\to$ sender stops, probes); \textbf{cwnd} $=$ sender's guess of the
        \emph{network}. Reno, CUBIC (RFC 9438, Linux's default) are loss-based; \textbf{BBR}
        (Google) models bottleneck bandwidth + min RTT and paces — better on lossy radio and
        against bufferbloat.
  \item \textbf{Nagle} (RFC 896) holds small segments while data is unacked; \textbf{delayed ACK}
        (RFC 1122: $<$0.5\,s, every 2nd full segment) holds the ACK $\Rightarrow$ write-write-read
        stalls tens to hundreds of ms. Fix: \ct{TCP\_NODELAY} (\ct{noDelay}) or one write.
  \item \textbf{Head-of-line blocking}: in-order delivery — one lost segment stalls every byte
        behind it, i.e.\ every HTTP/2 stream on the connection.
\end{itemize}

\hd{UDP — what you do \emph{not} get}
8-byte header (ports, length, checksum). No handshake, order, retransmission or congestion
control; message boundaries kept; oversize datagrams fragment or drop. Used by DNS, QUIC,
RTP/WebRTC, games, mDNS. NATs forget idle UDP mappings fast $\to$ keepalives.

\hd{Example — Network.framework knobs}
\begin{lstlisting}[language=SwiftSheet]
import Network
let tcp = NWProtocolTCP.Options()
tcp.noDelay = true            // Nagle off: small RPC-style writes
tcp.connectionTimeout = 5     // seconds for the handshake
tcp.enableKeepalive = true; tcp.keepaliveIdle = 30
let conn = NWConnection(host: "api.example.com", port: 443,
               using: NWParameters(tls: .init(), tcp: tcp))
conn.stateUpdateHandler = { state in  // preparing/ready/waiting/failed
  if case .waiting(let err) = state { print("no path yet", err) } }
conn.start(queue: .main)
// QUIC (iOS 15): NWParameters(quic: NWProtocolQUIC.Options(alpn: ["h3"]))
// URLSession: h3 when offered (iOS 15); MPTCP: multipathServiceType
\end{lstlisting}

\hd{QUIC — why it exists (RFC 9000/9001/9002, 2021)}
\begin{itemize}
  \item \textbf{Ossification}: TCP lives in kernels and middleboxes that drop the unfamiliar. QUIC
        runs in user space over UDP and \textbf{encrypts almost all of its header} (even packet
        numbers), so the network cannot come to depend on it.
  \item \textbf{Streams} native, loss per stream. Stream-ID bit 0 $=$ opener (client 0 / server 1),
        bit 1 $=$ bidi 0 / uni 1. \textbf{Packet numbers never reused} (a retransmission is a new
        packet) $\to$ unambiguous RTT samples; ACK ranges $=$ built-in SACK.
  \item \textbf{Migration}: \textbf{connection IDs}, not the 4-tuple; a new IP is checked with
        \ct{PATH\_CHALLENGE}/\ct{PATH\_RESPONSE} and the connection continues.
  \item \textbf{Anti-amplification}: the client pads its first Initial to $\geq$\textbf{1200 B}; an
        unvalidated server sends $\leq$\textbf{3$\times$} what it received.
  \item \textbf{Costs}: more CPU than kernel TCP; UDP blocked or throttled on some networks $\to$
        clients race / fall back to TCP; opaque to middleboxes (by design).
\end{itemize}

\hd{Traps}
\begin{itemize}
  \trap{Flow control $\neq$ congestion control: receiver buffer (rwnd) vs network capacity (cwnd).}
  \trap{Thousands of \ct{TIME\_WAIT}s on a server: the server closes first. Let clients close, keep
        connections alive; don't shrink MSL.}
  \trap{Half-open sockets look alive; TCP keepalive defaults to 2\,h — use app heartbeats.}
  \trap{More bandwidth rarely speeds a small API call: it is RTT- and slow-start-bound.}
\end{itemize}

\hd{Remember}
\textbf{``rwnd: receiver, cwnd: network, TIME\_WAIT: who hangs up first; QUIC $=$ TCP per stream.''}
