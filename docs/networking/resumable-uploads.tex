\sheettitle{Resumable \& chunked uploads — from a phone that keeps losing signal}{networking · folio}

\oneliner{A big upload over a mobile network \emph{will} be interrupted. \textbf{Resumable}: the server
keeps the bytes it has under an \textbf{upload URL} and reports its \textbf{offset}; after a drop the client
asks \emph{``where were we?''} and continues from there. \textbf{Chunked / multipart}: the file is split into
parts that are sent, retried and \textbf{checksummed} independently, then \textbf{assembled} by an explicit
\emph{complete}. On iOS a \textbf{background URLSession} hands the transfer to a system daemon —
\textbf{from a file}, never from \ct{Data}.}

\hd{How it works}
\begin{itemize}
  \item \textbf{Why}: cells drop, NAT rows expire, the app is killed — restarting 500 MB at 90\,\%
        burns time, battery and data.
  \item \textbf{Resumable} = one sequential stream with a \textbf{server-authoritative offset}
        (IETF draft, tus, GCS). \textbf{Multipart} = N parts, any order, \textbf{in parallel},
        assembled at the end (S3). Both need an \textbf{upload id/URL persisted} on the device.
  \item \textbf{Integrity}: a checksum per chunk (tus \ct{Upload-Checksum} $\to$ 460 on mismatch;
        S3 \ct{x-amz-checksum-*}, CRC64NVME default) + a whole-file hash checked at
        \emph{complete}. Hash first $\to$ server can \textbf{dedupe} (already have it: skip).
  \item \textbf{Retries}: exponential backoff + jitter; on every resume re-read the offset. Chunk
        size trades request overhead against bytes re-sent after a failure.
  \item \textbf{Progress}: \ct{didSendBodyData} / \ct{task.progress} count bytes \emph{sent};
        show the server-acknowledged offset. Multipart: a parent \ct{Progress} with one child
        per part, weighted by bytes.
\end{itemize}

\hd{The protocols}
{\footnotesize
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{12mm}>{\raggedright\arraybackslash}p{61mm}@{}}
\toprule
\textbf{IETF draft} & \ct{draft-ietf-httpbis-resumable-upload} (-12, Jul 2026, not yet an RFC).
  Server \emph{may} answer the POST with \textbf{104 Upload Resumption Supported} + \ct{Location};
  offset: \ct{HEAD} $\to$ \ct{Upload-Offset}; append: \ct{PATCH}, \ct{application/partial-upload},
  \ct{Upload-Complete: ?1} on the last; cancel: \ct{DELETE}. Also \ct{Upload-Length},
  \ct{Upload-Limit}, \ct{Upload-Draft-Interop-Version}. \\
\textbf{tus 1.0} & \ct{Tus-Resumable: 1.0.0}. POST $\to$ 201 + \ct{Location}; HEAD $\to$ \ct{Upload-Offset};
  PATCH \ct{application/offset+octet-stream} $\to$ 204 + new offset (409 if offsets differ);
  DELETE; \ct{Upload-Expires}. \\
\textbf{S3} & Create $\to$ UploadPart 1–10{,}000 (5 MiB–5 GiB, last smaller; each returns an
  \ct{ETag}) $\to$ \textbf{Complete} with every PartNumber + ETag. Max object 48.8 TiB. Abort;
  lifecycle \ct{AbortIncompleteMultipartUpload}. Client: one \textbf{presigned URL per part}. \\
\textbf{GCS} & POST \ct{?uploadType=resumable} $\to$ session URI (valid 1 week); PUT chunks, multiples of
  256 KiB, \ct{Content-Range: bytes 0-262143/*}; \textbf{308} + \ct{Range} = incomplete; status =
  empty PUT \ct{bytes */SIZE}. \\
\bottomrule
\end{tabular}}

\hd{Server contract (what to ask the backend for)}
Idempotent create (client upload id / \ct{Idempotency-Key}) · offset is the server's truth ·
size limits up front · auth on \emph{every} chunk (re-signable URLs) · expiry + garbage collection of
abandoned uploads · \emph{complete} verifies the hash, then processing (scan, transcode) runs async
$\to$ 202 + status URL.

\hd{Example — the IETF draft on the wire, then iOS 17}
\begin{lstlisting}[language=HTTPSheet]
POST /uploads          # Upload-Complete: ?1, whole file
  <- 104 Upload Resumption Supported
     Location: /uploads/7f3      # save it!
# ... connection lost ...
HEAD /uploads/7f3
  <- Upload-Offset: 6291456, Upload-Complete: ?0
PATCH /uploads/7f3     # Upload-Offset: 6291456
  Content-Type: application/partial-upload
  Upload-Complete: ?1  # bytes 6291456..end
  <- 200 OK            # the original request's answer
\end{lstlisting}
\begin{lstlisting}[language=SwiftSheet]
// iOS 17+: URLSession resumes by itself if the server
// speaks the draft; you can also pause and resume later
let task = session.uploadTask(with: req, fromFile: file)
task.resume()
task.cancel(byProducingResumeData: { data in
  store.save(data) })          // nil: not resumable
if let data = store.load() {   // file must be unchanged
  session.uploadTask(withResumeData: data).resume() }
\end{lstlisting}

\hd{On iOS}
\begin{itemize}
  \item iOS 17: upload tasks are \textbf{automatically resumable} when the server supports the
        draft (WWDC23 \emph{Build robust and resumable file transfers}; interop version 3).
  \item \textbf{Background session}: Apple: \emph{``Only upload tasks from a file are supported
        (uploads from data instances or a stream fail after the app exits).''} Multipart: write
        each part to its own file — \ct{uploadTask(fromFile:)} sends the whole file.
  \item Keep files in Application Support (not \ct{tmp}/Caches, which the system may purge).
  \item RN: \ct{fetch} has no resume. tus-js-client resumes in the foreground; background needs a
        native module on URLSession / WorkManager.
\end{itemize}

\hd{Traps}
\begin{itemize}
  \trap{Resuming from the \emph{client's} byte counter — bytes in flight were lost. Ask the server.}
  \trap{\ct{uploadTask(with:from: Data)} in a background session — fails once the app exits.}
  \trap{S3 parts under 5 MiB (except the last) are rejected; unfinished uploads are \textbf{billed}
        until aborted — add the lifecycle rule.}
  \trap{Presigned URL expired mid-upload $\to$ re-sign that part, don't restart.}
  \trap{``Chunked'' $\neq$ HTTP/1.1 \ct{Transfer-Encoding: chunked} — that streams one request of
        unknown length and resumes nothing.}
\end{itemize}

\hd{Remember}
\textbf{``Ask where you are, send from there, check every piece, finish explicitly, sweep the
abandoned.''}
