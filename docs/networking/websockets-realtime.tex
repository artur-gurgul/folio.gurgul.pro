\sheettitle{WebSockets \& realtime on iOS}{networking · folio}

\oneliner{A \textbf{WebSocket} (RFC 6455) is an HTTP/1.1 request that \textbf{upgrades} (101) into a
full-duplex stream of small \textbf{frames} on the same TCP connection. It gives foreground realtime;
it does \emph{not} give delivery across reconnects, ordering across connections, or life in the
background — you build \textbf{heartbeats}, \textbf{resubscribe}, \textbf{gap fill} and \textbf{dedup},
and use \textbf{APNs} when the app is not running.}

\hd{Choosing the transport}
{\footnotesize\setlength\tabcolsep{3pt}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{11mm}>{\raggedright\arraybackslash}p{11mm}>{\raggedright\arraybackslash}p{12mm}>{\raggedright\arraybackslash}p{15mm}>{\raggedright\arraybackslash}p{23mm}@{}}
\toprule
& \textbf{direction} & \textbf{latency} & \textbf{battery} & \textbf{infra / catch} \\ \midrule
polling & pull & = interval & worst: radio per poll & plain HTTP, cacheable \\
long poll & pull, held & near real-time & a request per batch & held requests, timeouts \\
SSE & down only & real-time & one stream & auto-resume; proxies buffer \\
WebSocket & \textbf{duplex} & lowest & foreground only & LB: Upgrade + long idle \\
APNs & down & seconds, best-effort & best (system link) & throttled; 4 KB payload \\
\bottomrule
\end{tabular}}\par
Pick the simplest that meets latency: a feed $\to$ SSE or polling; chat, collaboration, games
$\to$ WebSocket; ``tell me while I'm not running'' $\to$ APNs.

\hd{How it works}
\begin{itemize}
  \item Auth happens at the \textbf{handshake}: \ct{URLSessionWebSocketTask} takes a
        \ct{URLRequest}, so set \ct{Authorization} (browsers can't — they use a query token or a
        first message). After 101 there are no headers: an expired token needs an in-band
        re-auth or a reconnect.
  \item \textbf{Heartbeats}: NATs silently drop idle mappings; a half-open socket looks
        \emph{open} until a write fails, minutes later. \ct{sendPing} every $\sim$20–30\,s; no pong
        in time $\to$ dead, reconnect. App-level heartbeats also prove the server \emph{app} lives.
  \item \textbf{Reconnect}: exponential backoff + \textbf{full jitter}, reset after a stable period;
        also on \ct{NWPathMonitor} ``satisfied'' and on foreground. On open: auth $\to$
        \textbf{resubscribe} (the new server knows nothing) $\to$ gap fill $\to$ flush outbox.
  \item \textbf{Ordering}: TCP orders one connection only; across reconnects, servers and
        backplanes you need the server seq. Delivery is at-least-once $\to$ idempotent handlers,
        dedupe by message id.
  \item \textbf{Background}: iOS suspends the app seconds after it leaves; the socket dies with it.
        Close cleanly inside \ct{beginBackgroundTask}; deliver via \textbf{APNs}; reconnect + gap
        fill on foreground. (PushKit VoIP is for calls only.)
\end{itemize}

\hd{Example — URLSessionWebSocketTask (iOS 13)}
\begin{lstlisting}[language=SwiftSheet]
var req = URLRequest(url: URL(string: "wss://api.example.com/ws")!)
req.setValue("Bearer \(token)", forHTTPHeaderField: "Authorization")
let ws = session.webSocketTask(with: req)
ws.resume()
try await ws.send(.string(#"{"op":"sub","ch":"room.7","since":42}"#))
while true {                             // receive() = ONE message
  switch try await ws.receive() {        // throws when it closes
  case .string(let s): handle(s)
  case .data(let d):   handle(d)
  @unknown default:    break
  }
}
// heartbeat timer: ws.sendPing { error in /* nil = pong */ }
// leaving: ws.cancel(with: .goingAway, reason: nil)
\end{lstlisting}

\hd{Server side — fan-out}
Sockets are \textbf{stateful}: each gateway holds its connections in memory. A message published
anywhere must reach sockets on \emph{every} gateway $\to$ a \textbf{pub/sub backplane} (Redis
pub/sub, NATS, Kafka, an MQTT broker): gateways subscribe to the channels their clients want and push
down the sockets. The WebSocket itself pins to one gateway, so stickiness only matters for
multi-request fallbacks (long polling). Budget per-connection memory; bound each client's send
buffer — a slow consumer gets dropped, not buffered forever. A deploy closes thousands of sockets
at once: send close 1001, drain, and rely on client jitter to avoid a reconnect storm.

\hd{MQTT over WebSocket}
MQTT packets carried in binary frames (\ct{Sec-WebSocket-Protocol: mqtt}): browsers can't open raw
TCP, and some networks allow only 443. You get topics + wildcards, QoS 0/1/2 (QoS 1 $=$ duplicates
$\to$ idempotent), retained last value, Last Will — the reconnect/state problems above, already
solved by the broker. A native iOS client can use MQTT over TLS directly.

\hd{Traps}
\begin{itemize}
  \trap{Not re-arming \ct{receive()} (completion API): one message, then silence.}
  \trap{``The socket is open, so the peer is alive'' — half-open TCP. Heartbeat with a timeout.}
  \trap{Reconnect without \textbf{resubscribe} + \ct{since}: connected, and silently missing messages.}
  \trap{Fixed-delay reconnect: every client returns in the same second after a server blip.}
  \trap{Keeping a socket in the background ``with a background mode'': not allowed for this — push.}
  \trap{\ct{Sec-WebSocket-Accept} is not security; auth the handshake, use \ct{wss://} (TLS).}
  \trap{Default \ct{maximumMessageSize} is 1\,MB\unverified{} — a bigger message fails the receive.}
\end{itemize}

\hd{Remember}
\textbf{``Upgrade, heartbeat, backoff with jitter, resubscribe, fill the gap, drop the dup — and
push when you're asleep.''}
