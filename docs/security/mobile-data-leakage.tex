\sheettitle{Where data leaks on a phone — and what to wipe}{security · folio}

\oneliner{Putting the token in the Keychain secures \emph{one} copy. The OS makes more
copies for you: the \textbf{keyboard} learns what is typed, the \textbf{app switcher} photographs
the screen, \textbf{URLCache} writes API responses to \ct{Cache.db}, \textbf{logs}, \textbf{backups},
the \textbf{pasteboard}, \textbf{notifications}, \textbf{Spotlight} and your \textbf{SDKs} keep
theirs. MASVS-STORAGE-2 (``prevents leakage'') and PLATFORM-3 (``UI used securely'') are about
\emph{those} copies — and logout must delete every one.}

\hd{The mechanisms}
\begin{itemize}
  \item \textbf{Keyboard}: autocorrect / predictive text learn from non-secure fields. Secret
        $\to$ \ct{isSecureTextEntry} (no copy; system keyboard only; no learning\unverified).
        Sensitive but visible (IBAN, card) $\to$ \ct{autocorrectionType = .no},
        \ct{spellCheckingType = .no}. Block custom keyboards:
        \ct{shouldAllowExtensionPointIdentifier} $\to$ \ct{false} for \ct{.keyboard}.
        Android: \ct{flagNoPersonalizedLearning}.
  \item \textbf{Snapshot}: Apple — after the background delegate \emph{returns}, UIKit takes the
        image shown in the switcher and at relaunch. Hide it in \ct{sceneDidEnterBackground};
        SwiftUI: overlay unless \ct{scenePhase} is \ct{.active}.
  \item \textbf{Capture}: iOS only \emph{tells} you — \ct{userDidTakeScreenshotNotification}
        (after the fact); \ct{UIScreen.isCaptured} (iOS 11, deprecated in 27) $\to$
        \ct{sceneCaptureState} trait (iOS 17) for recording + mirroring. Android \ct{FLAG\_SECURE} \emph{blocks} screenshots,
        recording and the Recents thumbnail; 14 detects screenshots, 15 recording.
  \item \textbf{URLCache}: \ct{URLSession.shared} caches cacheable responses in memory + on disk.
        Fix at the source (\ct{no-store}), or per session (\ct{.ephemeral}: nothing on disk), or
        per response (\ct{willCacheResponse} $\to$ \ct{nil}).
  \item \textbf{Backups}: Documents + Library (not Caches/tmp) go to iCloud / Finder;
        Keychain items restore to another device unless \ct{…ThisDeviceOnly}.
        \ct{isExcludedFromBackup} is for caches/support files — Apple: edits to user documents
        can reset it. Android: \ct{allowBackup} defaults \ct{true} (Auto Backup, 25~MB/app, Google
        Drive); 12+: \ct{dataExtractionRules} splits \ct{<cloud-backup>} / \ct{<device-transfer>}
        — \ct{allowBackup="false"} may not stop device-to-device transfer.
  \item \textbf{Pasteboard}: \ct{setItems(\_:options:)} + \ct{.localOnly} (no Universal
        Clipboard) + \ct{.expirationDate}. iOS 16+ prompts before a programmatic paste
        (\ct{UIPasteControl} doesn't). Android 13+: \ct{EXTRA\_IS\_SENSITIVE} hides the preview.
\end{itemize}

\hd{Example — the logout wipe (server first, then every copy)}
\begin{lstlisting}[language=SwiftSheet]
func logOut() async {
  try? await api.revokeSession()   // refresh token + push token
  Keychain.deleteAll(service: "auth")          // SecItemDelete
  URLCache.shared.removeAllCachedResponses()   // Cache.db
  HTTPCookieStorage.shared.removeCookies(since: .distantPast)
  await WKWebsiteDataStore.default().removeData(
    ofTypes: WKWebsiteDataStore.allWebsiteDataTypes(),
    modifiedSince: .distantPast)               // WebView store
  UserDefaults.standard.removePersistentDomain(
    forName: Bundle.main.bundleIdentifier!)
  try? FileManager.default.removeItem(at: userDir)  // DB, drafts
  imageCache.clearDisk(); memoryCaches.removeAll()
  try? await CSSearchableIndex.default()
            .deleteAllSearchableItems()        // Spotlight
  UIPasteboard.general.items = []   // only if WE put a secret there
  router.reset()                    // no stale screens in memory
}
\end{lstlisting}

Put per-user data under \textbf{one directory} (+ one App Group folder for extensions) so
``delete the user'' is one call — then test it: log out, grep the container.

\hd{Also leaks}
Android accessibility services read the screen · exported content providers · App Group
containers + widgets · WebView form data · the state-restoration archive (same rule as the snapshot).

\hd{Traps}
\begin{itemize}
  \trap{``The token is in the Keychain, done'' — the \emph{response} that carried it may sit in
        \ct{Cache.db}, a log line, a crash breadcrumb.}
  \trap{Covering the UI in \ct{applicationWillTerminate} — not called on suspend; the snapshot
        follows \ct{sceneDidEnterBackground}.}
  \trap{``We block screenshots on iOS'' — you can't; detect, and hide while captured.}
  \trap{\ct{Library/Caches} is not \emph{backed up} but is still \emph{on the device} —
        a filesystem dump reads it.}
  \trap{Logout that only drops the in-memory token: the refresh token still works server-side.}
  \trap{RN: \ct{AsyncStorage} is a plain unencrypted store — never tokens.}
\end{itemize}

\hd{Remember}
\textbf{``Seen, stored, sent.''} Every secret has copies the user \emph{sees} (screen, keyboard,
clipboard), the OS \emph{stores} (cache, logs, backups) and SDKs \emph{send}. Logout = server
revoke + delete every copy.
