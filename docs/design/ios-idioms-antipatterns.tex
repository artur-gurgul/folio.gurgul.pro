\sheettitle{iOS idioms and anti-patterns}{design · folio}

\oneliner{Cocoa gives you a small set of \textbf{communication idioms} — delegate, data source,
target–action, closure, NotificationCenter, KVO, responder chain — and choosing one is a
question of \textbf{how many listeners}, \textbf{whether the sender needs an answer}, and
\textbf{who owns whom}. Most iOS anti-patterns are one mistake: \textbf{responsibilities and
dependencies that nobody can see}.}

\section{The idioms}
{\footnotesize\setlength\tabcolsep{3pt}
\begin{tabular}{@{}L{15mm}L{7mm}L{55mm}@{}}
\toprule
\textbf{Idiom} & \textbf{Shape} & \textbf{Mechanism · rule} \\
\midrule
Delegate & 1:1 & protocol \texttt{: AnyObject}, \texttt{weak var delegate}; can answer
(\texttt{shouldSelect}), \texttt{did/will/should} names, sender first \\
Data source & 1:1 & delegate that \emph{supplies data} (\texttt{numberOfRows}); UIKit holds
both \texttt{weak} \\
Target–action & 1:N & \texttt{addTarget(\_:action:for:)} + \texttt{@objc} selector; the control
does \textbf{not} retain the target; \texttt{UIAction} closure (iOS 14) \\
Closure & 1:1 & \texttt{onSelect: (Item) -> Void}; stored $\to$ \texttt{[weak self]}; best
for one event \\
Notification\-Center & 1:N & broadcast by name, untyped \texttt{userInfo};
\textbf{synchronous, on the posting thread} \\
KVO & 1:N & \texttt{observe(\textbackslash.x, options:)} $\to$
\texttt{NSKeyValueObservation}; needs \texttt{NSObject} + \texttt{@objc dynamic} \\
Responder chain & 1:? & \texttt{sendAction(\_:to: nil, …)}: first responder up via
\texttt{next} (see gof-behavioural) \\
Combine / \texttt{@Observable} & 1:N & typed streams / per-property tracking (iOS 17);
the modern default in-app \\
\bottomrule
\end{tabular}}

\begin{lstlisting}[language=SwiftSheet]
protocol PickerDelegate: AnyObject {        // so it can be weak
  func picker(_ p: Picker, didPick item: String)
  func pickerShouldClose(_ p: Picker) -> Bool   // answer back
}
final class Picker {
  weak var delegate: PickerDelegate?        // Picker never owns it
  func pick(_ item: String) {
    delegate?.picker(self, didPick: item)
    if delegate?.pickerShouldClose(self) ?? true { /* close */ }
  }
}

\section{Massive VC — the recipe}
Characterisation/snapshot tests first, then steps 1–6 as drawn, one safe move at a time
(child VCs: \texttt{addChild} + \texttt{didMove(toParent:)}). It is an \textbf{SRP} problem,
not an MVC one — moving the mass into the model or a \texttt{Manager} only relocates it.

\section{Traps}
\begin{itemize}
  \trap{``Singletons are always bad'' — no (\texttt{FileManager.default}). The damage is
        \textbf{hidden lookup} (\texttt{.shared} inside logic) + \textbf{global mutable
        state}: keep one instance, \textbf{inject} it.}
  \trap{A service locator still hides dependencies — a missing registration fails at run
        time, not compile time (Mark Seemann).}
  \trap{NotificationCenter for a 1:1 flow = invisible coupling: no contract, no ``who
        listens?''.}
  \trap{``Duplication is far cheaper than the wrong abstraction'' (Sandi Metz).}
  \trap{\texttt{UIAction}/\texttt{sink}/timer closures are \emph{stored}: \texttt{[weak self]};
        \texttt{unowned} only when the lifetime is guaranteed.}
\end{itemize}

\section{Remember}
\textbf{Answer back $\to$ delegate · one $\to$ closure · many $\to$ Combine/Notification ·
unknown $\to$ responder chain. Make responsibilities and dependencies visible.}
