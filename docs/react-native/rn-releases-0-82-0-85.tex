\sheettitle{React Native 0.82 → 0.87 — what changed, release by release}{react-native · folio}

\oneliner{A minor about every \textbf{two months}; the current and the two previous minors are
supported. \textbf{0.82} (Oct 2025) runs \textbf{only the New Architecture}; later releases remove
the legacy code, make \textbf{Hermes V1} and \textbf{prebuilt iOS binaries} the default (0.84),
share one \textbf{animation backend} (0.85), and generate a \textbf{strict TypeScript API} from
source (0.87). 0.83 and 0.86 shipped \textbf{no} user-facing breaking changes.}

\hd{Upgrade path}
\begin{itemize}
  \item \textbf{Still on the Legacy Architecture?} Official route: go to \textbf{0.81} (or Expo SDK 54),
        turn the New Architecture on, fix libraries there, \emph{then} 0.82. Libraries not yet
        migrated run through the \textbf{interop layers}, kept ``for the foreseeable future''.
  \item \textbf{Upgrade Helper} (react-native-community upgrade-helper) = the template diff between
        two versions: \ct{AppDelegate}, Podfile, Gradle, \ct{package.json}. Apply it by hand, one
        release at a time; read that release's breaking-changes list.
  \item \textbf{Expo}: bump the SDK (it pins RN), then \ct{npx expo install \dd{}fix} and
        \ct{npx expo-doctor}. SDK 54 = RN 0.81; SDK 55 = RN 0.83.
  \item Bump native deps with RN (Reanimated, Screens, SVG\ldots): they track the C++ APIs that
        each release removes.
\end{itemize}

\hd{In detail}
\begin{itemize}
  \item \textbf{DOM-like refs} (0.82): a host-component ref is a node with \ct{parentNode},
        \ct{children}, \ct{getBoundingClientRect()}, \ct{ownerDocument.getElementById()};
        \ct{measure}/\ct{setNativeProps} still work.
  \item \textbf{Web performance APIs} (stable 0.83): \ct{performance.mark}/\ct{measure},
        \ct{PerformanceObserver}, Event Timing, Long Tasks — measure real users, not just the lab.
  \item \textbf{Shared Animation Backend} (0.85): animation updates move into RN core, so
        Animated \emph{and} Reanimated drive layout props (\ct{width}\ldots) natively.
  \item \textbf{SwiftPM} (0.87): only Xcode needed (no Ruby/CocoaPods); after a fresh clone and
        in CI run \ct{npx react-native spm} once — the \ct{pod install} analogue.
\end{itemize}

\hd{Example — the config lines these releases touch}
\begin{lstlisting}[language=CfgSheet]
# 0.84+: build RN core from source again (debug a C++ crash)
RCT_USE_PREBUILT_RNCORE=0 bundle exec pod install
# 0.82+: Android debug build with C++ optimised (~60 FPS)
npx react-native run-android --mode debugOptimized
// 0.85+: jest.config.js
preset: '@react-native/jest-preset',
// 0.87: tsconfig escape hatch (bridge through 0.88)
"customConditions": ["react-native",
                     "react-native-legacy-deep-imports"]
# 0.87: SwiftPM instead of CocoaPods (experimental, once)
cd ios && npx react-native spm --deintegrate
\end{lstlisting}

\hd{Traps}
\begin{itemize}
  \trap{``0.82 deleted the legacy code'' — it \emph{ignores the flag}; class removal started
        after, and legacy libraries still load through the interop layer.}
  \trap{Jumping 0.79 $\to$ 0.84 in one go: legacy arch, JSC, prebuilt binaries, Hermes V1 and
        Node 22 all at once — impossible to bisect.}
  \trap{New crash reports after 0.82 may be old bugs: unhandled rejections stopped being silent.}
  \trap{Hermes V1 on 0.82/0.83 needs RN built from source — not with prebuilt core.}
  \trap{0.87 breaks \ct{from 'react-native/Libraries/\ldots'} at type-check time.}
  \trap{0.87: \ct{useColorScheme()} returns \ct{null}, no longer \ct{'unspecified'} — a
        \ct{\hbox{=}\hbox{=}\hbox{=} 'unspecified'} check silently stops matching.}
  \trap{0.85 tests fail to start until the Jest preset is renamed — not an app bug.}
\end{itemize}
