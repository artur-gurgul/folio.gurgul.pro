exception, \textbf{native signal} in a \texttt{.so}, \textbf{ANR} (main thread blocked \textbf{5\,s}
on input), \textbf{silent kill}. Each leaves a \emph{different} record read by a \emph{different} tool.}

\section{ANR — what triggers it (exact)}
\begin{itemize}\raggedright
  \item \textbf{Input dispatch}: no response to a key/touch within \textbf{5\,s}.
  \item \textbf{BroadcastReceiver} not finished in time — \textbf{5\,s} with a foreground activity.
  \item \texttt{startForegroundService()} without \texttt{startForeground()} within \textbf{5\,s}.
  \item \textbf{Service} \texttt{onCreate}/\texttt{onStartCommand}/\texttt{onBind} and
        \textbf{JobService} \texttt{onStartJob}/\texttt{onStopJob}: ``a few seconds'' (job
        ANRs are reported to the app only when targeting Android 14+).
  \item Causes: \textbf{I/O} or heavy work \textbf{on main}, \textbf{deadlocks}, slow
        \texttt{onReceive()}, \textbf{binder} calls.
\end{itemize}

\section{The RN angle}
\begin{itemize}\raggedright
  \item ANRs are about the \textbf{main (UI) thread}. A busy \textbf{JS} thread freezes your
        React UI but the main thread still consumes input — usually \emph{no} ANR, so it
        hides from vitals: measure JS stalls yourself (\texttt{longtask} observer).
  \item Typical RN ANRs: SDK init in \texttt{MainApplication.onCreate}, a native module doing
        I/O on the UI thread, main blocked on a lock another thread holds.
  \item Native crashes in RN often sit in \texttt{libhermes.so} / \texttt{libreactnative.so}
        (merged lib since 0.76) — the \emph{cause} is often a native module misuse higher
        up. A fatal JS error in release surfaces as a JVM crash
        (\texttt{JavascriptException}\unverified) carrying the JS stack.
\end{itemize}

\section{Diagnose}
\begin{itemize}\raggedright
  \item \textbf{StrictMode} (debug): flags disk/network on main before users see an ANR.
  \item \textbf{Traces}: \texttt{/data/anr/anr\_*} (was \texttt{traces.txt}); no root? \texttt{adb bugreport}.
  \item \textbf{ApplicationExitInfo} (API 30): \texttt{REASON\_ANR},
        \texttt{REASON\_CRASH}, \texttt{REASON\_CRASH\_NATIVE}, \texttt{REASON\_LOW\_MEMORY}…;
        \texttt{getTraceInputStream()} = the ANR trace, or the tombstone as protobuf.
  \item \textbf{Tombstones}: logcat \texttt{DEBUG} = signal, fault address, registers,
        backtrace; the file adds every thread, maps, fds. Written by \texttt{crash\_dump}
        since 8.0 (\texttt{debuggerd} before).
        SIGSEGV = bad memory access; SIGABRT = \texttt{abort()} (assert, uncaught C++ exception).
  \item \textbf{R8}: \texttt{retrace} + that build's \texttt{mapping.txt} (AAB + AGP 4.1+: Play
        takes it itself). Native: \texttt{ndk \{ debugSymbolLevel 'SYMBOL\_TABLE' \}} or \texttt{'FULL'}.
\end{itemize}

\section{Example — commands + in-app capture}
\begin{lstlisting}[language=KtSheet]
# one app only, crash buffer, JS + crash tags
adb logcat --pid=$(adb shell pidof -s com.example.app)
adb logcat -b crash -d
adb logcat ReactNativeJS:V AndroidRuntime:E DEBUG:V *:S
adb bugreport ./bug.zip          # ANR traces, tombstones
adb logcat -d | $NDK/ndk-stack -sym \
  app/build/intermediates/cxx/RelWithDebInfo/<hash>/obj/arm64-v8a
retrace mapping.txt stack.txt    # R8, per build
\end{lstlisting}
\begin{lstlisting}[language=KtSheet]
// next launch: why did the last process die?
val am = getSystemService(ActivityManager::class.java)
am.getHistoricalProcessExitReasons(packageName, 0, 5)
  .filter { it.reason == ApplicationExitInfo.REASON_ANR }
  .forEach { i -> i.traceInputStream?.use { upload(it) } }
// debug builds: catch main-thread I/O early
if (BuildConfig.DEBUG) StrictMode.setThreadPolicy(
  StrictMode.ThreadPolicy.Builder().detectDiskReads()
    .detectDiskWrites().detectNetwork().penaltyLog().build())
\end{lstlisting}

\section{Logcat essentials}
\begin{itemize}\raggedright
  \item Filter spec \texttt{TAG:LEVEL} (V D I W E F S), \texttt{*:S} silences the rest;
        \texttt{\dd{}pid} scopes to one process; \texttt{-b crash} = crash buffer;
        \texttt{-d} dump and exit; \texttt{-c} clear. A new PID after a crash = the process
        restarted — re-run \texttt{pidof}.
  \item Paste a tombstone to \texttt{ndk-stack} \emph{with} its first
        \texttt{*** *** ***} line, or it finds nothing.
\end{itemize}

\section{Traps}
\begin{itemize}\raggedright
  \trap{``Move it to a coroutine'' when main is \emph{waiting} on that coroutine
        (\texttt{runBlocking}) — still an ANR, and a deadlock risk.}
  \trap{Symbolicating with the wrong build's \texttt{.so}/mapping — the build ID must match;
        output looks plausible and is wrong.}
  \trap{Not every ANR has a stack in your code: the main thread may be idle in
        \texttt{nativePollOnce} when the trace is taken (the block already ended).}
\end{itemize}

\section{Remember}
\textbf{Five failures, five records:} ReactNativeJS · AndroidRuntime · DEBUG/tombstone ·
\texttt{/data/anr} · ApplicationExitInfo.
