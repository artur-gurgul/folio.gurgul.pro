\sheettitle{Background work in React Native}{react-native · folio}

\oneliner{RN has \textbf{no background scheduler of its own}: JS runs only while the native process
is alive and not suspended. Every background feature is a \textbf{native scheduler} —
\ct{BGTaskScheduler}, \ct{WorkManager}, a push, a background mode — that wakes the app and
\textbf{boots or resumes the JS runtime} for a short, OS-chosen window. The OS picks \emph{when};
your code only picks \emph{what}.}

\hd{The options}
\begin{itemize}
  \item \textbf{expo-background-task} (SDK 53; \ct{expo-background-fetch} is deprecated): Android
        \textbf{WorkManager}, iOS \textbf{BGTaskScheduler} (\ct{UIBackgroundModes: processing},
        id \ct{com.expo.modules.backgroundtask.processing}). \ct{minimumInterval} in
        \textbf{minutes}, default 12 h, floor 15. Needs battery + network; stops if the user kills
        the app; iOS: physical device only.
  \item \textbf{react-native-background-fetch} (Transistorsoft): iOS \ct{BGAppRefreshTask}
        (\ct{com.transistorsoft.fetch}), $\geq$ 15 min, frequency learnt from usage; Android
        \ct{stopOnTerminate: false} + \ct{enableHeadless} + \ct{startOnBoot}; \ct{scheduleTask}
        for one-off/periodic custom tasks.
  \item \textbf{Headless JS} (Android only): \ct{AppRegistry.registerHeadlessTask('Sync',
        () \fat{} task)}; a \ct{HeadlessJsTaskService} returns \ct{HeadlessJsTaskConfig(name, data,
        5000 /* ms timeout */, false)} — the last flag: by default the app \textbf{crashes} if the
        task runs while in foreground. Retries: \ct{LinearCountingRetryPolicy(3, 1000)} + throw
        \ct{HeadlessJsTaskError}. From a \ct{BroadcastReceiver}: \ct{acquireWakeLockNow()}.
  \item \textbf{Your own native job}: a Kotlin \ct{Worker} / a \ct{BGTaskScheduler} handler that
        does the work \textbf{natively} (upload, DB write) without booting JS — cheapest, most
        reliable; emit an event if JS happens to be alive. iOS: register every id \textbf{before
        the end of} \ct{didFinishLaunching}, list it in \ct{BGTaskSchedulerPermittedIdentifiers};
        a second registration of the same id kills the app.
  \item \textbf{Push-triggered}: FCM data message $\to$
        \ct{messaging().setBackgroundMessageHandler(fn)} registered in \ct{index.js} (outside
        components; on iOS it may mount the root); iOS silent push (\ct{content-available: 1}) is
        low priority, throttled, and discarded for a force-quit app.
  \item \textbf{Continuous modes}: location (\ct{expo-location}
        \ct{startLocationUpdatesAsync} + TaskManager; Android foreground service +
        notification), audio (\ct{UIBackgroundModes: audio}), BLE — held only while really in use.
        Big transfers: background \ct{URLSession} / WorkManager, native side. iOS 26
        \ct{BGContinuedProcessingTask}: user-started work that continues with a system progress UI.
\end{itemize}

\hd{Testing}
\begin{itemize}
  \item iOS device, paused in LLDB after \ct{submit}: \ct{e -l objc \dd{} (void)[[BGTaskScheduler
        sharedScheduler] \_simulateLaunchForTaskWithIdentifier:@"id"]} (and
        \ct{\_simulateExpiration\ldots}) — private, never ship it.
  \item Expo: \ct{triggerTaskWorkerForTestingAsync()} (dev). Android: \ct{adb shell dumpsys
        jobscheduler} (constraints met?); Doze: \ct{adb shell dumpsys deviceidle force-idle}.
\end{itemize}

\hd{Example — expo-background-task}
\begin{lstlisting}[language=TSSheet]
import * as TaskManager from 'expo-task-manager';
import * as BackgroundTask from 'expo-background-task';
const SYNC = 'outbox-sync';
// top-level scope: a headless launch mounts no component
TaskManager.defineTask(SYNC, async () => {
  try { await flushOutbox();            // read storage, POST, write
        return BackgroundTask.BackgroundTaskResult.Success; }
  catch { return BackgroundTask.BackgroundTaskResult.Failed; }
});
export async function enableSync() {
  const s = await BackgroundTask.getStatusAsync();
  if (s === BackgroundTask.BackgroundTaskStatus.Available)
    await BackgroundTask.registerTaskAsync(SYNC, { minimumInterval: 15 });
}
\end{lstlisting}

\hd{Writing a JS background task}
\begin{itemize}
  \item \textbf{Self-contained}: re-create what it needs (API client, tokens from Keychain, DB);
        do not assume the store, navigation or a logged-in React tree exists.
  \item \textbf{Short and idempotent}: an outbox flush, a delta sync, a prefetch. It can be
        cut off at any moment and run twice.
  \item Cold boot costs: the JS runtime + bundle load eats part of the window — keep the
        task's imports small; heavy work belongs in native.
  \item Keychain reads while locked need \ct{AFTER\_FIRST\_UNLOCK} accessibility.
\end{itemize}

\hd{Platform limits}
{\footnotesize
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{11mm}>{\raggedright\arraybackslash}p{62mm}@{}}
\toprule
iOS & no guaranteed schedule; system learns usage; refresh tasks are brief, processing tasks
      longer (often when charging/idle)\unverified; nothing after a user force-quit; no BGTask
      in the simulator; silent push $\leq$ 2--3/hour, 30\,s \\
Android & WorkManager periodic $\geq$ 15 min (flex $\geq$ 5 min); Doze + App Standby buckets
      defer work; constraints must all hold; OEM task killers\unverified; since 8.0 a background
      app can't \ct{startService()} (\ct{IllegalStateException}) \\

\hd{Traps}
\begin{itemize}
  \trap{``Every 15 minutes'' — a \emph{minimum}; iOS may run it hours later, or never.}
  \trap{\ct{setInterval} in JS as a background timer: frozen on suspend.}
  \trap{Task defined inside a component — never registered in a headless launch.}
  \trap{Headless JS on iOS — it doesn't exist.}
\end{itemize}

\hd{Remember}
\textbf{The OS schedules, native wakes, JS gets a short window — design for ``maybe, later''.}
