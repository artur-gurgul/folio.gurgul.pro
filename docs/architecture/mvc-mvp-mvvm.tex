\sheettitle{MVC · MVP · MVVM · MVVM-C}{architecture · folio}

\oneliner{All four keep the \textbf{same Model}; they differ in \textbf{where presentation
logic lives} and \textbf{who holds a reference to whom}. Each step moves logic
\emph{out} of the UIKit-bound view into a plain, unit-testable object:
\textbf{MVC} (controller does it all) $\to$ \textbf{MVP} (presenter pushes to a view
\emph{protocol}) $\to$ \textbf{MVVM} (view \emph{binds} to state; VM never sees the view)
$\to$ \textbf{MVVM-C} (a Coordinator also takes \emph{navigation} out).}

\section{Who knows whom}
{\footnotesize
\setlength{\tabcolsep}{2.5pt}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{12mm}*{3}{>{\raggedright\arraybackslash}p{19.5mm}}@{}}
\toprule
 & \textbf{MVC} & \textbf{MVP} & \textbf{MVVM} \\
\midrule
logic in & Controller (= the VC) & Presenter & ViewModel \\
view is & fused w/ controller & passive, behind a protocol & binds to VM state \\
to view & VC sets outlets & Presenter \emph{pushes}: \texttt{view?.show()} & View \emph{observes} (bindings) \\
knows view? & yes, owns it & yes — via protocol (weak) & \textbf{no} \\
test via & UI / host app & mock View, verify calls & assert on state \\
fits & small screens & UIKit, strict tests & SwiftUI, Combine \\
\bottomrule
\end{tabular}}

\begin{itemize}
  \item \textbf{Classic (Smalltalk) MVC:} the View observes the Model directly.
        \textbf{Apple MVC:} Controller mediates both ways, so V and M stay reusable. But
        \texttt{UIViewController} \emph{is} view + controller, so networking, parsing,
        routing pile in $\to$ \textbf{Massive VC}: violates SRP, testable only with UIKit.
  \item \textbf{MVP:} View forwards every event, renders only what it is told.
        Presenter holds \texttt{weak var view: LoginView?}, formats data, calls
        explicit methods. No bindings. Presenter imports no UIKit $\Rightarrow$
        fully unit-testable against a mock View.
  \item \textbf{MVVM:} VM exposes formatted observable state + intent methods,
        holds \emph{no} view reference and imports no UIKit. Binding tech:
        \texttt{@Observable}/\texttt{@Published}+Combine, KVO, closures/\texttt{Box<T>}.
        SwiftUI binds for free; \textbf{UIKit has none} — add one.
  \item \textbf{MVVM-C:} MVVM solves \emph{presentation}, not \emph{navigation}.
        Coordinator: \texttt{childCoordinators}, a presenter
        (\texttt{UINavigationController}), \texttt{start()}. Builds VC+VM,
        injects deps, performs push/present. VM only \emph{signals} intent
        (closure / delegate / Combine subject).
\end{itemize}

\section{Example — same screen, MVP vs MVVM}
\begin{lstlisting}[language=SwiftSheet]
// MVP: presenter KNOWS the view (protocol) and PUSHES
protocol LoginView: AnyObject { func show(error: String) }
final class LoginPresenter {
  weak var view: LoginView?        // VC owns presenter
  func loginTapped(_ u: String) {
    if u.isEmpty { view?.show(error: "Empty") } }
}
// MVVM: VM knows NOTHING of the view; the view OBSERVES
@Observable final class LoginVM {
  var error: String?               // bound by the view
  var onLoggedIn: (() -> Void)?    // intent -> Coordinator
  func loginTapped(_ u: String) {
    if u.isEmpty { error = "Empty" } else { onLoggedIn?() } }
}
\end{lstlisting}
{\footnotesize Test MVP: \texttt{spy.shownErrors == ["Empty"]}. Test MVVM:
\texttt{XCTAssertEqual(vm.error, "Empty")} — no view at all.}

\section{Traps}
\begin{itemize}
  \trap{``MVVM is just MVP.'' No: Presenter \emph{knows} the view and
        \emph{pushes}; VM has \emph{no} view ref and the view \emph{observes}.}
  \trap{Testability decides it: MVP $\approx$ MVVM $>$ MVC, because
        Presenter/VM import no UIKit. That is the whole point of the evolution.}
  \trap{``MVVM in UIKit just works'' — no binding mechanism exists; pick one
        (Combine \texttt{sink}/\texttt{assign}, closures, KVO, RxSwift).}
  \trap{VM must not import UIKit nor push screens (that is the Coordinator's
        job); its nav closure captures \texttt{[weak self]}.}
  \trap{MVVM-C leak: child coordinator never removed. System \textbf{back button}
        and \textbf{swipe-to-dismiss} bypass \texttt{didFinish} — detect via
        \texttt{UINavigationControllerDelegate didShow} /
        \texttt{presentationControllerDidDismiss}. Remove with \texttt{===}.}
  \trap{Opposite bug: a child coordinator kept only in a local dies after \texttt{start()} —
        its screens show, its \texttt{weak} callbacks are \texttt{nil}.}
\end{itemize}
