\sheettitle{Sync engines — clocks, conflicts, CRDTs}{architecture · folio}

\oneliner{A sync engine keeps \textbf{replicas} (phones, tablets, the server) that accept
writes \emph{offline} and must end in the \textbf{same state}. Record \textbf{operations}, not
snapshots, in a durable \textbf{log}; apply them \textbf{idempotently}; \textbf{detect}
concurrency with \textbf{versions or vector clocks} (never wall clocks); \textbf{resolve} it with a
named policy — server-authoritative, LWW, field merge, \textbf{OT} (a server orders and transforms)
or \textbf{CRDTs} (merge is mathematically order-free); keep deletes as \textbf{tombstones}.}

\hd{The engine}
\begin{itemize}
  \item \textbf{Local store = truth}; each write also appends an \textbf{op}
        \ct{\{opId: UUID, entity, id, field, value, baseVersion\}} to a durable \textbf{outbox}
        in the \emph{same} transaction. Ops (intent: ``add tag b'') merge better than
        snapshots (``tags = \{a,b\}'').
  \item \textbf{Push}: send ops in order; the server applies each once — \ct{opId} is the
        \textbf{idempotency key} (at-least-once delivery + idempotent apply = effectively once)
        and stamps a monotonic \textbf{server revision}.
  \item \textbf{Pull}: \ct{GET /changes?since=<cursor>} $\to$ \ct{\{changes, cursor, hasMore\}};
        the cursor is a server \textbf{revision}, never a timestamp. Apply + store the new
        cursor in \textbf{one transaction}. Cursor too old (GC'd) $\to$ \textbf{410 Gone} $\to$
        full resync.
  \item \textbf{Rebase}: remote changes arrive while local ops are pending $\to$ apply remote,
        replay pending ops on top (like \ct{git rebase}) so the UI shows local intent.
  \item \textbf{Tombstones}: a delete is a row \ct{deleted=true, version=n}, synced like any
        change. GC only when every replica has seen it (\emph{causal stability}) or after a TTL
        longer than the max offline window — else an old device \textbf{resurrects} the row.
\end{itemize}

\hd{Clocks — detection, not decoration}
\begin{itemize}
  \item \textbf{Wall clock}: users and NTP move it; skew of minutes is normal. Display only.
  \item \textbf{Lamport}: counter; on send \ct{c+=1}, on receive \ct{c=max(c,msg)+1}.
        Causal $\Rightarrow$ smaller, but a smaller number does \emph{not} prove causality —
        cannot detect concurrency. Total order with a replica-id tie-break.
  \item \textbf{Vector clock / version vector}: one counter per replica. \ct{V1 $\leq$ V2} in every
        slot $\Rightarrow$ V1 happened-before; neither $\Rightarrow$ \textbf{concurrent}. Cost:
        grows with replicas (per \emph{device}, not per user) — prune retired devices.
  \item \textbf{HLC} (hybrid logical clock): \ct{(max physical seen, logical counter)} — stays
        close to real time, monotonic even when the device clock jumps back, fits in 64 bits;
        a good LWW timestamp.
\end{itemize}

\hd{Example — the two smallest CRDT merges}
\begin{lstlisting}[language=SwiftSheet]
struct GCounter: Hashable {              // grow-only counter
  var slots: [String: Int] = [:]        // replicaId -> count
  var value: Int { slots.values.reduce(0, +) }
  mutating func inc(_ r: String) { slots[r, default: 0] += 1 }
  func merged(_ o: GCounter) -> GCounter {   // join = max per slot
    GCounter(slots: slots.merging(o.slots, uniquingKeysWith: max)) }
}
struct ORSet<E: Hashable> {              // observed-remove set
  var adds: [E: Set<UUID>] = [:]; var removed: Set<UUID> = []
  mutating func add(_ e: E) { adds[e, default: []].insert(UUID()) }
  mutating func remove(_ e: E) { removed.formUnion(adds[e] ?? []) }
  var elements: Set<E> {                 // alive = a tag not removed
    Set(adds.filter { !$0.value.subtracting(removed).isEmpty }.keys) }
}   // merge: union adds, union removed -> concurrent add WINS
\end{lstlisting}

\hd{Traps}
\begin{itemize}
  \trap{``Newest timestamp wins'' with device clocks — skew picks the winner.}
  \trap{Lamport order $\neq$ causality: it can't tell ``after'' from ``concurrent''.}
  \trap{Hard delete locally — the delete never syncs; the row comes back.}
  \trap{Counter as a plain \ct{Int} ``+1'' replayed on retry — double count; use op ids or a G-Counter.}
  \trap{CRDT $\neq$ correct: it converges to \emph{a} state — maybe not the one users meant (invariants like ``stock $\geq$ 0'' need a server).}
  \trap{Cursor = ``last sync time'': a row committed late with an older timestamp is skipped forever.}
\end{itemize}

\columnbreak

\hd{CRDTs — why they converge}
\begin{itemize}
  \item \textbf{State-based} (CvRDT): replicas ship state; \ct{merge} is a \textbf{join} —
        \textbf{commutative, associative, idempotent} — so any order, any duplicates, same result.
        \textbf{Op-based} (CmRDT): ship ops that commute; needs causal, exactly-once delivery.
  \item \textbf{G-Counter}: slot per replica, value = sum, merge = max per slot (a single int
        would double-count on re-merge). \textbf{PN-Counter} = two G-Counters (P $-$ N): likes.
  \item \textbf{LWW-Register}: \ct{(value, timestamp, replicaId)}, larger wins — deterministic,
        still \emph{loses} an edit by design. Use an HLC, not \ct{Date()}.
  \item \textbf{OR-Set}: every add gets a unique tag; remove deletes only the tags it
        \emph{observed} $\to$ a concurrent add survives (\textbf{add-wins}). Tombstoned tags =
        metadata that grows until GC.
  \item \textbf{Text / JSON}: sequence CRDTs (RGA, YATA) give each character an id and order —
        Yjs, Automerge. Cost: metadata per character, history kept.
\end{itemize}

\hd{Pick the policy per field, not per app}
{\footnotesize
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{27mm}>{\raggedright\arraybackslash}p{47mm}@{}}
\toprule
one user, many devices & field-level LWW on an HLC — rare conflicts, cheap \\
money · stock · bookings & \textbf{server-authoritative}: reject + rebase (invariants) \\
likes, counts & increment ops with op ids, or a PN-Counter \\
tags, members & OR-Set semantics (add wins) \\
shared text & sequence CRDT, or OT behind a server \\
files, blobs & keep both: ``conflicted copy'' + let the user pick \\
\bottomrule
\end{tabular}}

\hd{Apple's example — CloudKit}
\begin{itemize}
  \item \ct{NSPersistentCloudKitContainer}: mirrors a Core Data store to CloudKit record zones.
        Model rules: \textbf{no unique constraints}, every relationship \textbf{optional + has an
        inverse} (records arrive out of order), no \textbf{Deny} delete rule. After promoting to
        production the schema is \textbf{add-only} — never rename or delete a field.
  \item Conflict detection: each \ct{CKRecord} carries a change tag; saving a stale copy
        $\to$ \ct{CKError.serverRecordChanged} (the server's record in the error).
  \item \ct{CKSyncEngine} (iOS 17 / macOS 14): your own store; the engine \textbf{schedules}
        send/fetch, batches your pending changes (\ct{nextRecordZoneChangeBatch}), and hands
        you a state blob to \textbf{persist}; \ct{serverRecordChanged} is \textbf{yours} to resolve.
\end{itemize}

\hd{Remember}
\textbf{Ops in a log · idempotent by op id · revision cursor · versions detect · policy
resolves · CRDT = merge is a join · tombstones until everyone has seen them.}
