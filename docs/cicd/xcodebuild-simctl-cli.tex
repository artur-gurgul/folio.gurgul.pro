\sheettitle{xcodebuild, simctl \& friends — Xcode from the command line}{cicd · folio}

\oneliner{\ct{xcodebuild} runs one \textbf{action} of a \textbf{scheme} against a \textbf{destination}
and leaves files you can open — an \ct{.xcarchive}, an \ct{.ipa}, an \ct{.xcresult}. \ct{simctl}
drives simulators, \ct{devicectl} phones; \ct{xcode-select} / \ct{DEVELOPER\_DIR} pick \textbf{which
Xcode} answers.}

\hd{Build once, test anywhere}
\ct{build-for-testing} writes an \ct{.xctestrun}: an editable plist of bundle paths, environment and
arguments (Xcode 26+: even \emph{disabled} plan configurations). Any Mac runs it with
\ct{test-without-building} — no source, no compiler. Tests are paths,
\ct{-only-testing Target/Class/method}; \ct{@file} reads one a line; \emph{only} beats \emph{skip}.

\hd{Two repetition loops that point opposite ways}

  \node[lbl, anchor=west, align=left] at (3.35,0.42) {stops at the first \textbf{pass} (≤3): a flake ends \textcolor{sheetGreen!70!black}{\textbf{green}}};
  \node[cmd, anchor=west] at (0,0) {-run-tests-until-failure};
  \foreach \i in {0,...,4} { \node[ok] at (2.55+\i*0.28,0) {}; }
  \node[lbl] at (3.95,0) {…};
  \node[ko] at (4.2,0) {};
  \node[lbl, anchor=west, align=left] at (4.38,0) {stops at the first \textbf{fail} (≤100): caught};

\ct{-test-iterations N}: N runs, or either loop's cap.
\ct{-test-repetition-relaunch-enabled YES}: a fresh process per run.

\ct{-parallelize-tests-among-destinations} splits it.

\hd{The \ct{.xcresult}: query it, never parse it}
\link{\ct{xcresulttool}}{https://keith.github.io/xcode-man-pages/xcresulttool.1.html} speaks JSON;
\ct{help <command>} prints the schema. Xcode 16 swapped its commands: \ct{get object} needs
\ct{\dd legacy}, and parsers built on it broke.

\hd{Traps}
\begin{itemize}
  \trap{\ct{xcodebuild … | xcbeautify} without \link{\ct{set -o pipefail}}{https://www.gnu.org/software/bash/manual/html_node/Pipelines.html}:
        the pipeline returns the formatter's status — a red build reports green.}
  \trap{No \ct{OS=} is \ct{latest}: a new runner image moves the iOS version. Pin \ct{OS=} or \ct{id=}.}
\end{itemize}

The 100 is per product family per membership year; \link{disabling a device does not give the slot
back}{https://developer.apple.com/help/account/devices/devices-overview/}, only renewal does.
\ct{manageAppVersionAndBuildNumber}: Xcode rewrites every build number in the archive — off when CI
owns it. \ct{testFlightInternalTestingOnly}: never submittable. Manual signing:
\ct{provisioningProfiles} \{bundle id $\rightarrow$ profile\}.

\hd{Signing with nobody at the keyboard}
\ct{-allowProvisioningUpdates} lets \ct{xcodebuild} make certificates and fetch profiles itself; an
App Store Connect API key (key path, key ID, issuer ID) stands in for a logged-in account and also
uploads. \ct{altool} finds \ct{AuthKey\_<id>.p8} in \ct{./private\_keys},
\ct{\textasciitilde/.appstoreconnect/private\_keys} and two more.

\hd{Swift packages, plugins, macros on CI}
\begin{itemize}
  \item \ct{Package.resolved} is the lockfile: commit it;
        \link{\ct{-disableAutomaticPackageResolution}}{https://developer.apple.com/documentation/xcode/building-swift-packages-or-apps-that-use-them-in-continuous-integration-workflows}
        makes CI build exactly those versions.
  \item Checkouts land in \ct{DerivedData/SourcePackages}; \ct{-clonedSourcePackagesDirPath P} moves
        them somewhere a cache survives.
  \item \ct{-scmProvider system}: the Mac's own git, its config and SSH keys.
  \item Nobody is there to click ``Trust \& Enable'': \ct{-skipPackagePluginValidation},
        \ct{-skipMacroValidation} — in the tool's words, ``can be a security risk''.
\end{itemize}

\hd{A simulator is a userspace, not a virtual machine}
\link{The iOS userspace}{https://developer.apple.com/videos/play/wwdc2019/418/} — its own
\ct{launchd}, daemons and frameworks — runs on the \emph{Mac's} kernel, sharing its filesystem with a
home of its own. CPU and memory limits are not simulated: on a Mac with a terabyte of RAM the
``iPhone'' can allocate a terabyte. Simulator timings say nothing about a phone.

What a phone will not let a script do, a simulator will: \ct{privacy … grant} (no alert to tap),

\hd{Xcode Cloud}
Runs only \ct{ci\_post\_clone.sh}, \ct{ci\_pre\_xcodebuild.sh} and \ct{ci\_post\_xcodebuild.sh}
from \link{\ct{ci\_scripts/}}{https://developer.apple.com/documentation/xcode/writing-custom-build-scripts}
beside the project — the last \emph{even if xcodebuild failed}. No shebang $\rightarrow$
\ct{zsh file}; no \ct{sudo}; created files are deleted; secrets print as asterisks. 25 compute
hours a month are included.
