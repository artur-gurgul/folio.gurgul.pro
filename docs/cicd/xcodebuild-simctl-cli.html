xcodebuild, simctl & friends — Xcode from the command line

cicd · folio

In one line: xcodebuild runs one action of a scheme against a destination; archive + -exportArchive with an ExportOptions.plist make the shippable .ipa; test results land in an .xcresult read with xcresulttool. xcrun simctl scripts simulators, devicectl real devices, and xcode-select / DEVELOPER_DIR decide which Xcode answers. Xcode Cloud runs the same xcodebuild.

Download PDF Print view LaTeX source

Actions

build (default) · build-for-testing (+ .xctestrun) · test · test-without-building · archive · analyze · docbuild · clean; they chain (clean build). build-for-testing, test, archive, analyze need -scheme. Discover: -list -json, -showdestinations, -showTestPlans, -showBuildSettings. -showBuildTimingSummary times each command; -quiet = warnings and errors only.

Choosing, repeating and timing tests

-testPlan P · -only-test-configuration Cplan name without extension
-only-testing T/C/m · -skip-testing …@file: one id a line; only wins
-enumerate-tests · …-format jsonlist, don’t run; needs -destination
-test-iterations NN runs — or the cap for:
-retry-tests-on-failureuntil a pass, ≤3: a flake goes green
-run-tests-until-failureuntil a fail, ≤100: finds flakes
-test-repetition-relaunch-enabled YESfresh process per repetition
-test-timeouts-enabled YES+ per-test time-allowance flags
-collect-test-diagnostics on-failuresysdiagnoses, log archives
-enableCodeCoverage YES · -testLanguageoverride scheme / test plan

TEST_RUNNER_Foo=Bar → Foo=Bar in the runner. Xcode 26+: .xctestrun keeps disabled plan configurations (-only-test-configuration).

Parallel: clones within a destination, suites across destinations

-parallel-testing-enabled YES; -parallel-testing-worker-count N = exactly N. Several -destinations each run the whole suite, concurrently; -parallelize-tests-among-destinations splits classes instead. A device lookup waits -destination-timeout (30 s).

Result bundles — xcrun xcresulttool

get test-results summary · teststhe summary · the test tree
get test-results test-details · activitiesone test: -0pt-test-id ID
get test-results insights · metricspatterns · performance
get build-results · get log -0pt-type buildwarnings, errors · raw logs
export attachments -0pt-only-failuresscreenshots, recordings
merge a b -0pt-output-path m · comparecombine shards · diff vs -0pt-baseline-path
xcrun xccov view -0pt-report -0pt-json Rcoverage per target / file

JSON out; help get test-results summary prints the schema. Xcode 16: get object fails unless -0pt-legacy (deprecated) — old parsers broke.

What changed, Xcode 15 → 27

Traps

  • xcodebuild … | xcbeautify without set -o pipefail: the pipeline returns the formatter’s status — a red build reports green.
  • No OS= means latest: a new runner image silently moves the iOS version — pin OS= or id=.
  • Exit codes (sysexits): 70 = build or test failed; 64 usage, 66 no input, 74 I/O.

ExportOptions.plist — what -exportArchive reads

methodapp-store-connect · release-testing (ad hoc) · enterprise · debugging (default) · developer-id · mac-application · validation; app-store, ad-hoc, development are deprecated
destinationexport (local file) or upload (to App Store Connect)
manageAppVersion
AndBuildNumber		Xcode rewrites the build number of everything in the archive — turn off when CI owns the number
testFlightInternal
TestingOnly		team-only TestFlight; the build can never be submitted
signingStyle teamIDmanual needs provisioningProfiles {bundle id → profile}; uploadSymbols for symbolicated crashes

Signing on a runner: -allowProvisioningUpdates fetches profiles (and creates certificates for automatic signing) through an account in Xcode’s Accounts pane — or an App Store Connect API key: -authenticationKeyPath, -authenticationKeyID, -authenticationKeyIssuerID (also for uploads, Xcode 15+). altool looks for AuthKey_<id>.p8 in ./private_keys, ~/.appstoreconnect/private_keys and two more.

Swift packages, plugins, macros on CI

  • Commit Package.resolved (in App.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/); -disableAutomaticPackageResolution makes CI use exactly it.
  • Checkouts land in DerivedData/SourcePackages unless -clonedSourcePackagesDirPath P: pin it to cache them.
  • Private repos: SSH URLs + known_hosts; -scmProvider system uses the Mac’s git config (URL rewrites, proxies, SSH); registries: -packageAuthorizationProvider netrc.
  • Headless, nobody clicks “Trust & Enable”: -skipPackagePluginValidation, -skipMacroValidation — “can be a security risk”.

Which Xcode, which components

sudo xcode-select -s /Applications/Xcode_27.app: every user, persistent; DEVELOPER_DIR=…/Xcode_27.app: this process only. /usr/bin/xcodebuild, git, swift are shims through it; xcrun -0pt-find T resolves a tool. xcodes install 27.0; pin the version in .xcode-version. Fresh Mac: -runFirstLaunch (components + licence) · -downloadPlatform iOS -exportPath D [-buildVersion 26.4] once, -importPlatform D/….dmg on each Mac · -downloadComponent metalToolchain.

Xcode Cloud

From ci_scripts/ beside the project it runs only ci_post_clone.sh, ci_pre_xcodebuild.sh, ci_post_xcodebuild.sh (runs even if xcodebuild failed). No shebang → zsh file; no sudo; created files are deleted; non-zero exit fails the build. Scripts read CI_* variables (CI_PULL_REQUEST_NUMBER …); secret ones print as ****. 25 compute h/month come with the Developer Program; plans add 100, 250, 1,000 h.
